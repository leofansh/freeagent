# 个人事务助手（原型）

解决「角色多、事情杂」的个人日常事务助手原型。

**核心脉络**：角色多对多视图 · `state`/`kind`/`scheduled_for` 正交化 · 今天视图有顺延收口 ·
排序只给透明可反驳的弱信号 · 恢复上下文有可验证契约 · 提醒有渠道与错过处理。

完整设计（**实现契约**，枚举值/字段名/权重/阈值均以此为准）：
[`docs/个人事务助手设计方案.md`](docs/个人事务助手设计方案.md)

**怎么用**（命令全表、配置、故障排查、已知边界）：
[`docs/使用说明书.md`](docs/使用说明书.md)

## 快速开始

**日常只需要一个入口**：飞书里跟助手说话。开机自启已经配好（见下），登录后
桥接自动拉起，**不用开任何终端窗口**。

### 最省事的三条

| 想做什么 | 怎么做 |
|---|---|
| 记一笔、看今天 | 直接在**飞书**里说 |
| 管理事务 | 开 <http://127.0.0.1:8770/> |
| 临时用终端 | `set PYTHONIOENCODING=utf-8` + `set PYTHONPATH=src` + `python -m freeagent.cli.app` |

### 开机自动运行

桥接**登录后自动拉起**，不用手敲命令。做法是把 `tools\_svc_bridge.cmd`
复制一份到 Windows 的**启动文件夹**：

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\
```

再复制一份进去即可（**零权限**，不用管理员）：

```bat
copy /y tools\_svc_bridge.cmd "%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\FreeAgent-bridge.cmd"
```

**为什么不用「计划任务」**：`schtasks /create` 即使配`/sc onlogon` 也需要
**管理员权限**，报错「拒绝访问」。启动文件夹是**按用户**生效的，零权限，
对个人助手够用。

⚠️ **触发时机是「登录」，不是「开机」**——开机但没登录不会起。你的飞书通道
只在你登录后才有用，所以这不构成问题。

启动后想确认它到底在不在，**别看状态文件**（进程死后它会留在盘上、仍写着
`connected: true`）。用这条命令，它按**命令行**找进程，不靠 pid：

```bat
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='python.exe'\" | Select-Object ProcessId,CommandLine | Format-List"
```

日志在 `data\bridge.log`。手动启动用 `tools\run_feishu.bat`（它会先跑
doctor 自检凭据，错了当场说清原因）。

**两个入口**（共用同一套服务层，规则不会漂移）。

### 终端

```bash
# 无需安装依赖即可运行（Python 3.11+）
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.cli.app
```

### Web 界面

```bash
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.web
```

打开 <http://127.0.0.1:8770/>。**首屏就是一个对话框**，直接问「今天该做什么」
或说一件事记下来。旁边还有 **今天 / 全部未结束 / 已结束 / 角色 / 设置** 五个页签。

- 对话只**读你的数据**、只**新建**事务，**不改已有事务** —— 白话入口越权时
  会明确说做不到并给出该用的命令，而不是猜一个动作去改
- 零框架零依赖，**无任何外部资源**——断网照常能用
- **只监听回环地址**，局域网不可达；无鉴权正是靠这一点成立
- 写操作是**白名单**：新建事务、状态迁移（开始/做完/放一放/算了）、排期与移出排期。
  角色归属、改完成标准、改形状、草稿采纳、角色管理仍在终端
- **多家 LLM 可在界面配**（服务商 / 模型 / Key），只支持 **OpenAI 兼容**的那几家
  （DeepSeek、Kimi、通义、OpenAI、Ollama 等）；**Claude / Gemini 还不行** ——
  原因见 [`docs/个人事务助手设计方案.md`](docs/个人事务助手设计方案.md) 12.3。
  Key 写进 `~/.freeagent/llm.env`（**不写** `config.json`），环境变量仍优先于文件。

数据库默认 `~/.freeagent/agent.db`（`FREEAGENT_HOME` 可改），
配置文件同目录；`--db` 指定别的位置时，配置也跟着走那个目录。

```bash
python -m freeagent.web --db ./data/agent.db --port 9000
```

### 委派执行器（可选）

把一件事交给本机的 [opencode](https://opencode.ai) 去改代码。
  **独立进程**，只从库里取「已确认」的委派，**不接受任何外部消息作为指令**（命令 / 任务 / 授权都只能经由它自己签发的凭据进入；它会接受对「它自己提出的问题」的文本答复）。闸门（`/start` 门、项目白名单、逐次授权）都在**服务层的函数**里，所以合并进程也绕不过；进程拆分给的是**纵深防御**，真正的好处是**交互中桥接重启不丢**。详见 [设计文档 11.8.1](docs/个人事务助手设计方案.md)。

```bash
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src

# 先看一眼会派什么，但什么都不执行
python -m freeagent.delegate --dry-run

# 确认无误后真跑（可加 --model opencode/big-pickle 指定模型）
python -m freeagent.delegate

# 默认就是这样：agent 每要动手一次就发一张飞书卡，等你批
python -m freeagent.delegate

# ⚠️ 确实要无人值守才加它（此时第三道闸门不存在）
python -m freeagent.delegate --no-tool-gate
```

用之前先在 `config.json` 里填项目白名单（**留空 = 关闭委派**）：

```json
{ "delegate": { "projects": ["D:/PycharmProjects/freeagent"],
                "model": "opencode/big-pickle" } }
```

**第三道闸门是「执行期逐次授权」** —— **默认就开着**：

```
agent 动手 → opencode 挂起 → 飞书卡片（含 **diff**）→ 你点 → 继续
```

- ✅ **默认开启**（`--no-tool-gate` 才关）。**默认值决定的是失效方向**：
  默认关等于「忘了加旗标就静默进入无人值守」，而
  [复盘 0001](docs/postmortem/0001-auto-flag-is-not-a-gate.md) 实测 opencode
  默认 `allow` —— 不传 `--auto` 也全部放行、写出目录外都执行。
  那种情况下「跑起来了」比「跑不起来」危险得多。
- **`--tool-gate` 仍可用**，只是把默认再说一遍（README 与 `tools\*.cmd` 的
  既有命令行都写着它，删掉会把那些命令变成报错而不是变安全）。
- **没配飞书通道时会拒绝派发**（失败关闭），并列出三条出路：
  配通道 / 显式 `--no-tool-gate` / 先 `--dry-run` 预演。
  **绝不静默退化成无人值守** —— 那正是闸门形同虚设的样子。
- `--no-tool-gate` 那条路是 `subprocess` 一次跑到底、无人值守。
  它保留是因为已在没有飞书通道的环境验证过。
- **还有第四道：工具调用步数硬上限**（默认 40 次，`DEFAULT_MAX_TOOL_CALLS`）。
  超限即**主动中止会话**，并报「这件事该拆开」。
  **为什么逐次授权还不够**：每次询问都可能拿到「允许」，所以一个跑偏的 agent
  会反复来问 —— 人是被**同意淹没**，不是被拦住。审批是「问」，不是「限」。
  超限时**不发那张卡**（点了也没后果，比不发更困惑），并 `abort` 会话，
  否则 opencode 会挂着一个没人会答的请求干等 —— 那就是卡死。
- **第五道：单条委派总时长上限**（默认 30 分钟）。与第四道**互补** ——
  第四道限「做了多少件事」，第五道限「花了多久」。一个一直有动静的 agent
  次数不涨、时间却能拖很久；而 opencode 那个 600 秒是**空闲超时**，
  「一直有动静」正是它管不到的那一类。
- **Plan → Build 的确认卡**（`/mode-build` 发出，点「确认执行」才建事务）。
  `/mode-build ok` 确认、`/mode-build cancel` 先留着。计划在卡片挂着期间被
  **冻结** —— 卡上印的就是会执行的，不一致就要求重新确认。
- **授权卡上还有第三个按钮：「停止这条委派」**。点了执行器立刻中止整个
  会话 —— **「拒绝」只否掉这一个动作，agent 还能换方向继续**。这两件事
  混起来最危险：用户以为已经停掉了，而 agent 还在改代码。
  只有发起人能停止（复用「只有发起人能批」那条规则）。
- 卡片上写明动作、影响路径、**它到底想改成什么**，以及「只批准这一个动作，
  下一个还会再问」。**没有 diff 的话你点的就是「信任」而不是「确认」。**
- **只有发起人能批** —— ✅ **已达成**（V1.17）。发起人由 `channel_ctx.sender_open_id` 落进 `tasks.delegate_requested_by`（schema 12，旧库自动迁移），
  待批行、**卡片收件人**、执行期逐次授权三处统一用它。
  判定是双向 id 后缀匹配（`open_id` 与 `user_id` 是两个串）。
  终端发起的没有飞书身份，落回 approver —— 那条路径行为不变。
  详见 [设计文档 11.8.1](docs/个人事务助手设计方案.md)；回归测试 `tests/test_delegate_requester.py`。
- 不点就算拒绝（超时自动降级为拒绝）—— 沉默不等于同意。
- 委派跑在**独立的 opencode 服务**里，配置隔离在一次性目录，
  **不碰你的 `~/.config/opencode/opencode.jsonc`**；也不加载你的插件
  （无人值守时攻击面更小）。
- 已映射的权限：`edit`/`bash`/`webfetch`/`websearch` 逐次问；
  `external_directory`（写出项目目录）**永远拒绝**；读与检索不拦
  （全拦会问到最后变成无脑点）。

> **为什么不是「不传 `--auto`」**（曾写在这里，**已纠正**，已移入
> [`docs/postmortem/0001`](docs/postmortem/0001-auto-flag-is-not-a-gate.md)）
>
> 原文说「不传 `--auto`（dangerous!）」是第三道闸门。**这条不成立。**
> 实测：非交互子进程下 opencode **不传 `--auto` 也全部自动放行** ——
> 目录内写文件执行、**写出目录外也执行**，且**不产生任何授权事件**。
>
> 根因不是「没有权限系统」，而是**默认 `allow`**（官方 V1 文档原文：
> *"Most permissions default to `allow`"*）。当时本机配置里
> `external_directory: allow` 又覆盖了它本来的默认 `ask`。
>
> 正确的第三道闸门是上面那个**执行期逐次授权**（`--tool-gate`）。
> 细节见 [设计文档 11.8.1](docs/个人事务助手设计方案.md)。
> **完整的踩坑过程、根因分析、留下的规矩**在复盘 0001 里，这里不重复。
>
> ⚠️ **opencode 主版本提醒**：本项目按 **V1**（实测 `1.18.31`）的字段名接线。
> 官网现已主推 **V2（2.0.6）**，permission 模型字段名**全变**
> （`permission` 对象 → `permissions` 数组，`bash` → `shell`，`task` → `subagent`）。
> 旧字段会被**静默忽略**、闸门随之失效，所以执行器启动时会**查主版本，
> 不是 V1 就拒绝派发**（退出码 2），不会警告后照跑。
> 查当前版本：`opencode --version` 看第一位。

**从飞书发起的委派会闭环**：执行器跑完主动把结果推回那个飞书会话
（含事务 id 和摘要，并写明「待你验收」）。推送在本地落库之后做、
失败只记日志 —— 通知渠道挂了不等于任务没做完。桥接和执行器仍是
**两个独立进程**，执行器要你另开终端跑。

### 飞书通道（可选）

在飞书里跟助手说话，命令语义**与终端完全一致**（复用同一套派发逻辑，
不是另写一套，所以不会分叉）。用**长连接**，不需要公网 IP。

```bash
pip install ".[feishu]"      # 核心包仍然零依赖

REM 推荐：交互式脚本，Secret 不落文件、不进 shell 历史
tools\run_feishu.bat
```

它提示你粘贴 App Secret，先联网自检凭据，确认没问题再起长连接。
凭据错了会**当场说清原因**并停下 —— 32 位密钥里 `I`/`l`/`1`/`!`
肉眼分不清，转写错一位的报错和真失效一模一样，所以让机器直接读原文。

手动设也行（`FEISHU_ALLOWED_USERS` 留空 = 谁都不许）：

```bash
set FEISHU_APP_ID=cli_xxx
set FEISHU_APP_SECRET=xxx
set FEISHU_ALLOWED_USERS=ou_xxx

python -m freeagent.feishu.doctor     # 自检（默认不联网，不打印 secret）
python -m freeagent.feishu.bridge
```

`lark-oapi` 只是**可选**依赖，核心包 `dependencies` 依然为空 ——
「克隆即可跑」这条不变。详见 [`docs/使用说明书.md`](docs/使用说明书.md)。

## 设计上的几个关键决定

**1. 三个字段正交，而不是一个 status 枚举**

`state`（生命周期）、`kind`（动作/等候/提醒）、`scheduled_for`（排进哪天）互不覆盖。
一个事务完全可以「既是进行中、又排在今天」。

**2. 今天视图必须有收口机制**

逾期未结束的事务在访问时自动顺延到今天，并产出一条**合并摘要**。
没有这条规则，inbox 会无限膨胀直到用户不再打开它。

**3. 排序只给透明弱信号，不替用户做取舍**

每条信号带一句面向用户的理由，输出必须标注「启发式提示，不是评分」。
`OVERDUE_WAIT +50` / `DEADLINE_RISK +40` / `DEPENDED_ON +30` / `RESUME_STALE +20` …
完整表见文档 7.2。

**4. `TaskRecord` 是唯一真源**

事务上下文全靠只追加日志重建；`progress_note` 只是派生缓存，随时可从日志重算。
草稿 `Artifact` 带版本且**永不原地覆写**，旧版可回看。

**5. 恢复契约是可验证的结构，不是愿望**

打开事务必须返回 `RestoreView`（生效完成标准 / 当前草稿 / 进度 / 最近 20 条记录 /
等候对象 / 下一步建议），缺一项就算恢复失败。

**6. 界面不能藏掉设计意图**

Web UI 好看，但有测试守着不许它把关键信息藏起来：每条排序信号的**理由**
必须显示、「启发式提示，不是评分」必须出现、视图切换只允许**换角度读同一份数据**，
不给「筛选掉某些事」的选择权——那是替用户做取舍。

**7. 智能层可替换、可换家，且有防编造护栏**

`LLMProvider` 协议 + 两种实现：配了 Key 用真实模型，没配/失败退回规则层。
「换家」落在 `services/llm/providers.py` 的注册表里，**协议层一行没动** ——
客户端本来就是标准 OpenAI 形状（`messages` / `Bearer` / `choices[0]`），
所以加一家是加一行表项，不是重写。

```bash
# Key：环境变量优先，~/.freeagent/llm.env 兜底（界面上填的写进后者）
set DEEPSEEK_API_KEY=sk-...
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.cli.app
```

非秘密配置（provider / model / base_url / timeout / 精力档位）可写 `~/.freeagent/config.json`：

```json
{
  "llm": { "provider": "deepseek", "model": "deepseek-chat", "timeout": 20 },
  "energy_windows": { "evening": [19, 23] }
}
```

`config.json` 里**永远不会有 Key**：`Config` 压根没有 `api_key` 字段，
它是个现读环境变量 / `llm.env` 的 property —— 这条不是靠约定防住的，是靠类型防住的。

模型会编造，所以输出必须过校验：**角色名白名单**（编出来的直接丢弃）、
**kind 白名单**、**草稿强制补齐 `[TODO]` 骨架**。模型不可用时如实打印
「已退回规则推断」，**不静默劣化**；降级原因里带的是**真实服务商名**，
用 Kimi 出错不会显示成 deepseek。`/llm` 看当前状态（不显示 Key）。

## 已知边界

- **V1 不做多渠道采集** —— 断点 1「入口散」因此**未被验证**。输入全部手工录入。
- **系统不运行时不提醒** —— 提醒是轮询式的：终端每轮对话查一次，Web 每次加载查一次。
  **两个进程都关着就收不到**，浏览器开着也没用。
- **Web 写操作是白名单** —— 状态迁移与排期可以在界面做；角色归属、改完成标准、
  改形状、草稿采纳、角色管理仍得回终端。
- **智能层是无状态单轮** —— 没有流式输出，也不保留对话历史；
  上下文由恢复契约显式提供。
- **`/draft` 的产出质量取决于输入信息量** —— 只给一句「先理一版」时，
  模型会正确地只填 `[TODO]` 而不是编造内容。想让它有实质产出，就得给更多约束。
- 角色级记忆只有 `Role.note` 自由文本，没有可检索的脉络知识（V2）。
- 排序不是打分模型；用户可以反驳任一信号，助手不会坚持。
- **委派不继承你的 opencode 配置**：委派跑在**配置隔离**的实例里（`HOME` 与全部 `XDG_*` 都指向一次性目录），所以 `~/.config/opencode/` 里的 provider 配置**对它不可见** —— 要指定模型就用 `--model` （例如 `opencode/big-pickle`），否则由 opencode 自选（实测会落到免费模型）。
- **委派依赖你机器上装了 opencode，并且账户能用** —— 付费模型余额不足会直接
  `402` 失败。实测用 `opencode/big-pickle` 不需要余额（2026-09-27）。
  另外委派**简报必须单行**：提示里只要有换行，opencode 就会判定为「复杂任务」
  并升级到主 agent 的强模型、**无视 `--model`**，于是必然失败。
- **飞书通道只把文字当指令** —— 图片、文件、富文本会**回一句「我只处理文字」**
  （带上实际收到的类型）然后就此打住，**不会建事务**。这条提示**只发给白名单内、
  且群里确实 @ 了 bot 的人**：白名单外连提示都不回（回一句就等于向陌生人确认
  「这里有个 bot」），群里没 @ 也不回（否则随手发张图就抢着说话，等于破坏「不抢答」）。
  群里必须 @ **bot 自己**才响应（@ 别人不抢答，@ 所有人也不算数），判定靠 bot 自身 `open_id`
  （启动时自动探测，缓存到 `feishu_bot.json`）。探不到身份时群聊**失败关闭**
  （群里不响应、私聊正常），启动会告警。
- **事件去重表落盘**（`feishu_seen_events.json`，24 小时 / 2048 条），
  所以长连接重连重投时不会重复建事务，重启也记得。
- **同一台机器只允许一个桥接进程**（`FEISHU_LOCK_PORT`，默认 8771）——
  跑两个的话飞书只把事件投给其中一个，另一个静默失效。
- **执行期逐次授权的飞书卡片**（`permission.asked` → 卡片 → 点回 → 送回 opencode）
  已接线并有 53 项回归测试覆盖，但**真机点一次还没验过** —— 需要真发一张卡、
  在飞书里点它，确认 opencode 那边真的收到答案并继续。静态测试证明的是
  **协议形状**对，不是「飞书会把点击原样带回来」（后者只有真机能证明）。
- **委派出去的 opencode 看不到你的环境变量** —— 子进程环境是从零构造的**白名单**（本机实测 77 → 22 个变量）：家目录 / 配置 / 缓存 / 临时目录全部指向一次性 jail 目录，只有**模型凭据**与 OS 必需变量放行。
- 装了飞书通道等于开了一个远程入口 —— 缓解措施是白名单失败关闭
  （`FEISHU_ALLOWED_USERS` 为空则拒绝启动）、App Secret 只从环境变量读、
  委派走白名单 + 逐次授权。但它仍然是
  「谁能指挥你本机」的信任边界，配置时别图省事。
  **完整的信任边界、实测出的硬约束、以及「不要把本项目当成不可信负载的
  唯一安全控制」这条，见 [`docs/SAFETY.md`](docs/SAFETY.md)。**
  （原文此处写「不传 `--auto`」，**已纠正** —— 那不构成保护，
  见上文委派章节与[复盘 0001](docs/postmortem/0001-auto-flag-is-not-a-gate.md)。）
- **数据库 schema 升到 5**（`pending_approvals` 加 `requested_by`）。
  旧库第一次启动会**自动迁移**（`ALTER TABLE ADD COLUMN`，幂等）。
  列可空，所以加列前的待批项仍然点得动。
