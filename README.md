# 值守（Steward）· 个人事务助手原型

解决「角色多、事情杂」的个人日常事务助手原型。

**核心脉络**：角色多对多视图 · `state`/`kind`/`scheduled_for` 正交化 · 今天视图有顺延收口 ·
排序只给透明可反驳的弱信号 · 恢复上下文有可验证契约 · 提醒有渠道与错过处理。

完整设计（**实现契约**，枚举值/字段名/权重/阈值均以此为准）：
[`docs/个人事务助手设计方案.md`](docs/个人事务助手设计方案.md)

**怎么用**（命令全表、配置、故障排查、已知边界）：
[`docs/使用说明书.md`](docs/使用说明书.md)

## 快速开始

**日常只需要一个入口**：飞书里跟助手说话。开机自启已经配好（见下），登录后
桥接自动拉起，**不用开任何终端窗口**。

### 最省事的四条

| 想做什么 | 怎么做 |
|---|---|
| 记一笔、看今天 | 直接在**飞书**里说 |
| 双击就能用（不装 Python） | 拿到打包目录后双击 `install.cmd`，桌面出现 `Steward` 快捷方式；以后双击它即可（**关窗口 = 停服务**，想让它继续跑就用下面的网页版） |
| 管理事务 | 双击 `tools\run_web.bat`（自动定位 Python 3.11+、起服务并开浏览器到 <http://127.0.0.1:8770/>） |
| 临时用终端 | `set PYTHONIOENCODING=utf-8` + `set PYTHONPATH=src` + `python -m freeagent.cli.app` |

### 自己打这个安装包

```bash
python tools\pack\build_portable.py
```

产出 `dist\Steward\`：官方 embeddable Python 3.11.9（`runtime\`）+ 本仓 `src` 的副本
（`app\`）+ `desktop_main.pyw` + `install.cmd` / `uninstall.cmd`。把整个目录压成 zip
发给别人，对方解压后双击 `install.cmd` 即可 —— **对方机器不需要装 Python**。
首次构建会下载约 11 MB 的 embeddable zip（缓存到 `tools\pack\.cache\`，离线机可用
`--python-zip <已下载的 zip>` 跳过下载）。

### 开机自动运行

桥接**登录后自动拉起**，不用手敲命令。做法是把 `tools\_svc_bridge.cmd`
复制一份到 Windows 的**启动文件夹**：

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\
```

再复制一份进去即可（**零权限**，不用管理员）：

```bat
copy /y tools\_svc_bridge.cmd "%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\Steward-bridge.cmd"
```

> 已经按旧名装过 `FreeAgent-bridge.cmd` 的，先把那一份删掉再复制 —— 两份
> 同名服务同时起会抢同一个锁端口，症状是其中一个反复报「端口被占用」。

**为什么不用「计划任务」**：`schtasks /create` 即使配`/sc onlogon` 也需要
**管理员权限**，报错「拒绝访问」。启动文件夹是**按用户**生效的，零权限，
对个人助手够用。

⚠️ **触发时机是「登录」，不是「开机」**——开机但没登录不会起。你的飞书通道
只在你登录后才有用，所以这不构成问题。

启动后想确认它到底在不在，**别看状态文件**（进程死后它会留在盘上、仍写着
`connected: true`）。用这条命令，它按**命令行**找进程，不靠 pid：

```bat
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='python.exe'\" | Select-Object ProcessId,CommandLine | Format-List"
```

日志在 `data\bridge.log`。手动启动用 `tools\run_feishu.bat`（它会先跑
doctor 自检凭据，错了当场说清原因）。

**两个入口**（共用同一套服务层，规则不会漂移）。

### 终端

```bash
# 无需安装依赖即可运行（Python 3.11+）
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.cli.app
```

可选：`pip install -e .` 后会注册三个命令入口 `freeagent` / `freeagent-feishu` /
`freeagent-feishu-doctor`，不再需要手动设 `PYTHONPATH`（Python 的 `Scripts` 目录要在
PATH 里）。核心依赖依然为空，这一步只是暴露入口，不装任何运行时库。

### Web 界面

最省事：双击 `tools\run_web.bat`。它自己设好 `PYTHONIOENCODING` / `PYTHONPATH`，
依次找 PATH 上的 `python`、`py` 启动器和标准安装目录下的解释器，版本低于 3.11 会
停下来把原因说清；服务起好后自动打开浏览器。

手动方式（等价）：

```bash
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.web
```

打开 <http://127.0.0.1:8770/>。**首屏就是一个对话框**，直接问「今天该做什么」
或说一件事记下来。一级入口还有 **工作台 / 今天 / 事务 / 更多**，其余视图
（角色 / 关系 / 承诺 / 待处理 / 催办 / 编程 / 后台服务 / 飞书通道 / 设置等）
收在「更多」下拉里。

- 对话只**读你的数据**、只**新建**事务，**不改已有事务** —— 白话入口越权时
  会明确说做不到并给出该用的命令，而不是猜一个动作去改
- 没配模型 Key 时，首屏顶部会提示当前是规则层（能记事、排期、提醒，角色判断
  和草稿是模板），并给「去配置模型」按钮直达设置页；头部状态栏同步显示智能层
- 零框架零依赖，**无任何外部资源**——断网照常能用（唯一例外是**默认关闭**的
  在线检索可选腿，要你自己配端点才启用，见使用说明书「记忆」第 6 条）
- **只监听回环地址**，局域网不可达；**会话令牌**由服务端生成并注入页面
  （挡的是「网页里的脚本乱发请求」与 CSRF，不是网络上的攻击者）
- 写操作是**白名单**：新建事务、状态迁移（开始/做完/放一放/算了）、排期与移出排期，
  **外加委派的实时交互**（见下）。角色归属、改完成标准、改形状、草稿采纳、角色管理仍在终端
- **多家 LLM 可在界面配**（服务商 / 模型 / Key），只支持 **OpenAI 兼容**的那几家
  （DeepSeek、Kimi、通义、OpenAI、Ollama 等）；**Claude / Gemini 还不行** ——
  原因见 [`docs/个人事务助手设计方案.md`](docs/个人事务助手设计方案.md) 12.3。
  Key 写进 `~/.freeagent/llm.env`（**不写** `config.json`），环境变量仍优先于文件。

#### 编程页签：委派的实时交互（V1.35）

**WEB 与飞书是两种独立的操作界面**，体验对齐：网页上能看进度、能批授权、
能答问题，不用切到飞书。两者共用同一份库，在哪边批另一边立刻就看到那张卡消失。

- 面板每 2 秒读一次 `GET /api/delegate/live`（**只读**端点，无副作用）
- 授权卡带**动作 / 影响哪些路径 / diff** 与三个按钮：**允许**（只批这一个动作）、
  **拒绝**（否掉这一步，agent 换个方向继续）、**停止这条委派**（中止整个会话，
  已完成的改动仍有效）
- 不点就算拒绝 —— 沉默不等于同意
- 飞书发起的委派**网页上看得见但批不了**（那些卡只由发起人批），面板会写明去哪儿批
- 想关掉轮询：`FREEAGENT_LIVE_POLL_SECONDS=0`

设计与取舍见设计文档 12.8 节。

数据库默认 `~/.freeagent/agent.db`（`FREEAGENT_HOME` 可改），
配置文件同目录；`--db` 指定别的位置时，配置也跟着走那个目录。

```bash
python -m freeagent.web --db ./data/agent.db --port 9000
```

### 委派执行器（可选）

把一件事交给本机的 [opencode](https://opencode.ai) 去改代码。
  **独立进程**，只从库里取「已确认」的委派，**不接受任何外部消息作为指令**（命令 / 任务 / 授权都只能经由它自己签发的凭据进入；它会接受对「它自己提出的问题」的文本答复）。闸门（`/start` 门、项目白名单、逐次授权）都在**服务层的函数**里，所以合并进程也绕不过；进程拆分给的是**纵深防御**，真正的好处是**交互中桥接重启不丢**。详见 [设计文档 11.8.1](docs/个人事务助手设计方案.md)。

```bash
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src

# 先看一眼会派什么，但什么都不执行
python -m freeagent.delegate --dry-run

# 确认无误后真跑（可加 --model opencode/big-pickle 指定模型）
python -m freeagent.delegate

# 默认就是这样：agent 每要动手一次就发一张飞书卡，等你批
python -m freeagent.delegate

# ⚠️ 确实要无人值守才加它（此时第三道闸门不存在）
python -m freeagent.delegate --no-tool-gate
```

用之前先在 `config.json` 里填项目白名单（**留空 = 关闭委派**）：

```json
{ "delegate": { "projects": ["D:/PycharmProjects/freeagent"],
                "model": "opencode/big-pickle",
                "plugins": "inherit" } }
```

`delegate.plugins` 决定委派实例**要不要加载你的 opencode 插件**：
`inherit`（默认，全部加载，含插件注入的 MCP 与技能）或 `off`
（加 `OPENCODE_PURE=1`，插件注入的 **MCP 服务器与工具全部消失**、agent 人格
回到默认）。默认为什么是 `inherit`：改默认会**静默削掉你正在用的工具**（本机就有
codegraph / context7 / grep_app / lsp / websearch 五个 MCP 服务器）。
实测 `off` 与 `inherit` 只差这一个变量时：`GET /mcp` 从 5 个 connected 变成 `{}`、
agent 从 `Sisyphus - ultraworker` 变回 `build`、input tokens 20805 → 7092、
启动 ~4s → 1.3s。**关插件 ≠ 关闸门** —— 两种模式下执行期逐次授权都照常开着。
详见[使用说明书](docs/使用说明书.md#delegateplugins要不要带上你的插件)。

**第三道闸门是「执行期逐次授权」** —— **默认就开着**：

```
agent 动手 → opencode 挂起 → 飞书卡片（含 **diff**）→ 你点 → 继续
```

- ✅ **默认开启**（`--no-tool-gate` 才关）。**默认值决定的是失效方向**：
  默认关等于「忘了加旗标就静默进入无人值守」，而
  [复盘 0001](docs/postmortem/0001-auto-flag-is-not-a-gate.md) 实测 opencode
  默认 `allow` —— 不传 `--auto` 也全部放行、写出目录外都执行。
  那种情况下「跑起来了」比「跑不起来」危险得多。
- **`--tool-gate` 仍可用**，只是把默认再说一遍（README 与 `tools\*.cmd` 的
  既有命令行都写着它，删掉会把那些命令变成报错而不是变安全）。
- **没配飞书通道时会拒绝派发**（失败关闭），并列出三条出路：
  配通道 / 显式 `--no-tool-gate` / 先 `--dry-run` 预演。
  **绝不静默退化成无人值守** —— 那正是闸门形同虚设的样子。
- `--no-tool-gate` 那条路是 `subprocess` 一次跑到底、无人值守。
  它保留是因为已在没有飞书通道的环境验证过。
- **还有第四道：工具调用步数硬上限**（默认 40 次，`DEFAULT_MAX_TOOL_CALLS`）。
  超限即**主动中止会话**，并报「这件事该拆开」。
  **为什么逐次授权还不够**：每次询问都可能拿到「允许」，所以一个跑偏的 agent
  会反复来问 —— 人是被**同意淹没**，不是被拦住。审批是「问」，不是「限」。
  超限时**不发那张卡**（点了也没后果，比不发更困惑），并 `abort` 会话，
  否则 opencode 会挂着一个没人会答的请求干等 —— 那就是卡死。
- **第五道：单条委派总时长上限**（默认 30 分钟）。与第四道**互补** ——
  第四道限「做了多少件事」，第五道限「花了多久」。一个一直有动静的 agent
  次数不涨、时间却能拖很久；而 opencode 那个 600 秒是**空闲超时**，
  「一直有动静」正是它管不到的那一类。
- **Plan → Build 的确认卡**（`/mode-build` 发出，点「确认执行」才建事务）。
  `/mode-build ok` 确认、`/mode-build cancel` 先留着。计划在卡片挂着期间被
  **冻结** —— 卡上印的就是会执行的，不一致就要求重新确认。
- **授权卡上还有第三个按钮：「停止这条委派」**。点了执行器立刻中止整个
  会话 —— **「拒绝」只否掉这一个动作，agent 还能换方向继续**。这两件事
  混起来最危险：用户以为已经停掉了，而 agent 还在改代码。
  只有发起人能停止（复用「只有发起人能批」那条规则）。
- 卡片上写明动作、影响路径、**它到底想改成什么**，以及「只批准这一个动作，
  下一个还会再问」。**没有 diff 的话你点的就是「信任」而不是「确认」。**
- **只有发起人能批** —— ✅ **已达成**（V1.17）。发起人由 `channel_ctx.sender_open_id` 落进 `tasks.delegate_requested_by`（schema 12，旧库自动迁移），
  待批行、**卡片收件人**、执行期逐次授权三处统一用它。
  判定是双向 id 后缀匹配（`open_id` 与 `user_id` 是两个串）。
  终端发起的没有飞书身份，落回 approver —— 那条路径行为不变。
  详见 [设计文档 11.8.1](docs/个人事务助手设计方案.md)；回归测试 `tests/test_delegate_requester.py`。
- 不点就算拒绝（超时自动降级为拒绝）—— 沉默不等于同意。
- 委派跑在**独立的 opencode 服务**里，配置隔离在一次性目录，
  **不碰你的 `~/.config/opencode/opencode.jsonc`**；也不加载你的插件
  （无人值守时攻击面更小）。
- 已映射的权限：**兜底 `ask`（失败关闭）** —— 没登记的一律要人点头，
  含插件注入的 MCP 工具与将来 opencode 新增的工具；写文件
  （`edit`/`write`/`multiedit`/`apply_patch`）、`bash`、`skill`、
  `webfetch`/`websearch` 逐次问；`external_directory`（写出项目目录）
  **永远拒绝**；读与检索（`read`/`list`/`glob`/`grep`/`codesearch`/`lsp` 等）
  不拦（全拦会问到最后变成无脑点）。
  > **2026-10-14 实测改的**：兜底原是 `"*": "allow"`，而**未登记 = 落到兜底
  > = 放行**。于是本机插件注入的 5 个 MCP 工具在委派里**静默执行、零授权
  > 事件**；更要紧的是 V1 写文件是**四个**工具，只登记 `edit` 时
  > `write`/`apply_patch`/`multiedit` 全从兜底拿到 allow ——
  > 且 `tool/registry.ts` 对含 `gpt-` 的模型只给 `apply_patch`、
  > **把 `edit`/`write` 过滤掉**，那时 `edit: ask` 是死配置、闸门被整体绕过。
  > 两阶段实测对照见[设计文档 11.8.1](docs/个人事务助手设计方案.md)。

> **为什么不是「不传 `--auto`」**（曾写在这里，**已纠正**，已移入
> [`docs/postmortem/0001`](docs/postmortem/0001-auto-flag-is-not-a-gate.md)）
>
> 原文说「不传 `--auto`（dangerous!）」是第三道闸门。**这条不成立。**
> 实测：非交互子进程下 opencode **不传 `--auto` 也全部自动放行** ——
> 目录内写文件执行、**写出目录外也执行**，且**不产生任何授权事件**。
>
> 根因不是「没有权限系统」，而是**默认 `allow`**（官方 V1 文档原文：
> *"Most permissions default to `allow`"*）。当时本机配置里
> `external_directory: allow` 又覆盖了它本来的默认 `ask`。
>
> 正确的第三道闸门是上面那个**执行期逐次授权**（`--tool-gate`）。
> 细节见 [设计文档 11.8.1](docs/个人事务助手设计方案.md)。
> **完整的踩坑过程、根因分析、留下的规矩**在复盘 0001 里，这里不重复。
>
> ⚠️ **opencode 主版本提醒**：本项目按 **V1**（实测 `1.18.31`）的字段名接线。
> 官网现已主推 **V2（2.0.6）**，permission 模型字段名**全变**
> （`permission` 对象 → `permissions` 数组，`bash` → `shell`，`task` → `subagent`）。
> 旧字段会被**静默忽略**、闸门随之失效，所以执行器启动时会**查主版本，
> 不是 V1 就拒绝派发**（退出码 2），不会警告后照跑。
> 查当前版本：`opencode --version` 看第一位。

**从飞书发起的委派会闭环**：执行器跑完主动把结果推回那个飞书会话
（含事务 id 和摘要，并写明「待你验收」）。推送在本地落库之后做、
失败只记日志 —— 通知渠道挂了不等于任务没做完。桥接和执行器仍是
**两个独立进程**，执行器要你另开终端跑。

**现在能派的只有 opencode 一个。** `/agents` 列的是注册表里登记的**全部**
执行器（没装的、装了但没验过的也会列出来并说清原因），其中 `hermes`
是「已登记、未接线」—— 它的 API Server 面（`hermes gateway`，HTTP 默认
8642）照文档看与 opencode **同构**（建 run → 读 SSE → `/stop` 中止 →
`/approval` 回应授权），**接它不必换传输层、也不必引依赖**；但那些是读文档
读来的，**一次真机都没验过**，所以刻意**不派发、一桶能力都不给**。

为什么要先登记一个不能派的执行器：不登记的话 `/agents` 只列 opencode，
「多执行器」看起来就做完了。

> ⚠️ **有一条捷径绝不能走**：把 hermes 当 OpenAI 兼容后端直接问
> `/v1/chat/completions` 是最省事的接法，但那条面上**工具已在服务端执行完**
> （回放的 `function_call` 一律 `status: completed`）—— 它已经动过 terminal
> 和文件系统，本仓看不到也拦不住。那是绕过 11.8 全部闸门，而症状只是「能用」。

详见 [设计文档 11.10.8](docs/个人事务助手设计方案.md)。

### 飞书通道（可选）

在飞书里跟助手说话，命令语义**与终端完全一致**（复用同一套派发逻辑，
不是另写一套，所以不会分叉）。用**长连接**，不需要公网 IP。

```bash
pip install ".[feishu]"      # 核心包仍然零依赖

REM 推荐：交互式脚本，Secret 不落文件、不进 shell 历史
tools\run_feishu.bat
```

它提示你粘贴 App Secret，先联网自检凭据，确认没问题再起长连接。
凭据错了会**当场说清原因**并停下 —— 32 位密钥里 `I`/`l`/`1`/`!`
肉眼分不清，转写错一位的报错和真失效一模一样，所以让机器直接读原文。

手动设也行（`FEISHU_ALLOWED_USERS` 留空 = 谁都不许）：

```bash
set FEISHU_APP_ID=cli_xxx
set FEISHU_APP_SECRET=xxx
set FEISHU_ALLOWED_USERS=ou_xxx

python -m freeagent.feishu.doctor     # 自检（默认不联网，不打印 secret）
python -m freeagent.feishu.bridge
```

`lark-oapi` 只是**可选**依赖，核心包 `dependencies` 依然为空 ——
「克隆即可跑」这条不变。详见 [`docs/使用说明书.md`](docs/使用说明书.md)。

## 设计上的几个关键决定

**1. 三个字段正交，而不是一个 status 枚举**

`state`（生命周期）、`kind`（动作/等候/提醒）、`scheduled_for`（排进哪天）互不覆盖。
一个事务完全可以「既是进行中、又排在今天」。

**2. 今天视图必须有收口机制**

逾期未结束的事务在访问时自动顺延到今天，并产出一条**合并摘要**。
没有这条规则，inbox 会无限膨胀直到用户不再打开它。

**3. 排序只给透明弱信号，不替用户做取舍**

每条信号带一句面向用户的理由，输出必须标注「启发式提示，不是评分」。
`OVERDUE_WAIT +50` / `DEADLINE_RISK +40` / `DEPENDED_ON +30` / `RESUME_STALE +20` …
完整表见文档 7.2。

**4. `TaskRecord` 是唯一真源**

事务上下文全靠只追加日志重建；`progress_note` 只是派生缓存，随时可从日志重算。
草稿 `Artifact` 带版本且**永不原地覆写**，旧版可回看。

**5. 恢复契约是可验证的结构，不是愿望**

打开事务必须返回 `RestoreView`（生效完成标准 / 当前草稿 / 进度 / 最近 20 条记录 /
等候对象 / 下一步建议），缺一项就算恢复失败。

**6. 界面不能藏掉设计意图**

Web UI 好看，但有测试守着不许它把关键信息藏起来：每条排序信号的**理由**
必须显示、「启发式提示，不是评分」必须出现、视图切换只允许**换角度读同一份数据**，
不给「筛选掉某些事」的选择权——那是替用户做取舍。

**7. 智能层可替换、可换家，且有防编造护栏**

`LLMProvider` 协议 + 两种实现：配了 Key 用真实模型，没配/失败退回规则层。
「换家」落在 `services/llm/providers.py` 的注册表里，**协议层一行没动** ——
客户端本来就是标准 OpenAI 形状（`messages` / `Bearer` / `choices[0]`），
所以加一家是加一行表项，不是重写。

```bash
# Key：环境变量优先，~/.freeagent/llm.env 兜底（界面上填的写进后者）
set DEEPSEEK_API_KEY=sk-...
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.cli.app
```

非秘密配置（provider / model / base_url / timeout / 精力档位）可写 `~/.freeagent/config.json`：

```json
{
  "llm": { "provider": "deepseek", "model": "deepseek-chat", "timeout": 20 },
  "energy_windows": { "evening": [19, 23] }
}
```

`config.json` 里**永远不会有 Key**：`Config` 压根没有 `api_key` 字段，
它是个现读环境变量 / `llm.env` 的 property —— 这条不是靠约定防住的，是靠类型防住的。

模型会编造，所以输出必须过校验：**角色名白名单**（编出来的直接丢弃）、
**kind 白名单**、**草稿强制补齐 `[TODO]` 骨架**。模型不可用时如实打印
「已退回规则推断」，**不静默劣化**；降级原因里带的是**真实服务商名**，
用 Kimi 出错不会显示成 deepseek。`/llm` 看当前状态（不显示 Key）。

## 我们决定不做什么

**定位一句话**：这个项目**不做执行、只做委派治理** —— 决定「该不该动手、谁来授权」，
动手本身交给 opencode。下面每一条「不做」都是这句话的推论，不是口味。

### 决定不做，以及换来的永久代价

| 不做 | 永久代价 |
|---|---|
| **多用户、分享、团队** | 只有你自己能用；没有共享知识库、没有专家市场 |
| **自己的 Agent 运行时** | 工具循环长什么样由 opencode 定，改不了；也正因如此，治理者才不必与被治理者同体 |
| **自带 RAG / 向量检索 / 浏览器** | 检索只能借 opencode 的 MCP，浏览器同样只能借（想自己造得先重新论证整条定位） |
| **永久授权**（opencode 的 `always`） | 每一次动手都要点一次；`reply_payload` 只映射到 `once` 是刻意的（11.9.7） |
| **linter / 类型检查作为交付门** | 没有 ruff / mypy 守风格漂移，只有 `python -m pytest` 全量绿 |
| **拆成多份文档** | 只有一份契约（`docs/个人事务助手设计方案.md`），且示例必须与真实输出逐字一致 |
| **跨平台** | 声明 **Windows-first**；源码里的 `os.name` 分支只为进程组与隐藏控制台窗口存在，**不代表已支持别的平台** |

> 为什么必须连代价一起写：「不做」不标代价就只是口号。
> **一条从没付过代价的定位，和宣传没有区别。**

### 延后（不是不做，是还没做）

- **多渠道采集**（爬邮件 / 日历 / RSS）—— V1 范围外；断点 1「入口散」因此**未被验证**
- **角色级可检索记忆** —— 现在只有 `Role.note` 自由文本（V2）
- **Hermes 执行器** —— 已登记、未接线、一桶能力都不给（11.10.8）
- **「本任务内对某工具免确认」旁路** —— Octop 有线程级 `allow_tools`，值得做；
  但它是**安全姿态变更**，要做先单独拍板，且 `ask_user_question` 必须不可跳过
- **并发派发 L1**（项目级租约 + 有界线程）—— V1.94 的租约只解决了「在跑」
  可观察，派发**仍是单线程串行**
- **引擎侧的三件事**（V1.96 排的六条只落了第二条）：
  ① **会话续接**（P0）—— 跨进程续接的 API 前提已验证，但「跨目录会不会串味」
  因额度耗尽、模型一条没跑起来而**未验证**，所以刻意没落；
  ② **引擎的账**（P1）—— token 走 `session.tokens` 已验，「改了哪些文件」待验；
  ③ **项目脉络**（P3）—— `GET /api/session` 已有公开契约可走，不必读引擎 SQLite
- **「停止这条委派」真机验证** —— 审批链 17 格里真机只点过 2 格，逐格见
  [`docs/真机验收矩阵.md`](docs/真机验收矩阵.md)（本项 = `A7`–`A9`，三个通道全空）。
  允许/拒绝验过**不能顺带证明**它：停止的按钮载荷是新的
- **主动起草跟进（不发送）** —— 基于「在等谁」生成待发送草稿，人一键确认才发
- **反馈驱动权重校准** —— 在规范权重表之上叠一层个人校准
- **执行器注册表真正落地** —— 多执行器真可插拔且都过同一探针，不留半成品

### 曾经决定做，后来放弃（记账）

**V1.31 放弃了「隔离 jail + 复制用户配置」**，改成「系统 opencode + 项目级权限覆盖层」。

- 放弃的原因**全是实测**：插件每次重装 **107.7s**、**离了网就装不上**、
  继承出口的 `null` 会把整份配置作废（返 502，看起来像插件坏了）。
- 代价说在明处：委派**看得见你的真实配置** —— 插件、MCP、技能、agent 全进来，
  agent 人格可能被插件换掉，每轮多约 2 万 input tokens。
- 兜底：`permission` 闸门失败关闭（未登记一律 `ask`）+
  `delegate.plugins: "off"` 可一键不加载插件。
- 教训：**顺着证据转，别顺着潮流转。** 同一条轴上我们转过两次，每次都是被数字推着走的。

## 已知边界

> 上一节是**决定不做**（连代价一起）；这一节是**当前实现的操作性事实**（会随版本变）。
> 两者分开写，是因为混在一起时分不清哪条该等、哪条永远不该等。

- **系统不运行时不提醒** —— 提醒是轮询式的：终端每轮对话查一次，Web 每次加载查一次。
  **两个进程都关着就收不到**，浏览器开着也没用。
- **Web 写操作是白名单** —— 状态迁移与排期可以在界面做；角色归属、改完成标准、
  改形状、草稿采纳、角色管理仍得回终端。
- **智能层是无状态单轮** —— 没有流式输出，也不保留对话历史；
  上下文由恢复契约显式提供。
- **`/draft` 的产出质量取决于输入信息量** —— 只给一句「先理一版」时，
  模型会正确地只填 `[TODO]` 而不是编造内容。想让它有实质产出，就得给更多约束。
- 排序不是打分模型；用户可以反驳任一信号，助手不会坚持。
- **委派看得见你的 opencode 配置**（V1.31 起，**不再隔离**）：跑的是系统 opencode，
  读你真实的 `~/.config/opencode/opencode.jsonc` —— 插件、MCP、技能、agent 全都会进来
  （本机实测 **45 个插件 / 5 个 MCP 服务器**），agent 人格也可能被插件换成它的
  （实测会话的 `agent` 变成 `Sisyphus - ultraworker`，一句话回「OK」烧 2 万 input tokens）。
  要指定模型仍用 `--model`（例如 `opencode/big-pickle`），否则由 opencode 自选。
  ⚠️ 这一段**曾经写反过**（旧 README 写「配置隔离在一次性目录……也不加载你的插件」）——
  那是 jail 时代的话，V1.31 已放弃隔离，见上文「曾经决定做，后来放弃」。
  想让委派不加载插件：`config.json` 里 `"delegate": {"plugins": "off"}`（实测 `GET /mcp` 变 `{}`、
  agent 回到 `build`、input tokens 20805 → 7092、启动 ~4s → 1.3s）。
- **委派依赖你机器上装了 opencode，并且账户能用** —— 付费模型余额不足会直接
  `402` 失败。实测用 `opencode/big-pickle` 不需要余额（2026-09-27）。
  另外委派**简报必须单行**：提示里只要有换行，opencode 就会判定为「复杂任务」
  并升级到主 agent 的强模型、**无视 `--model`**，于是必然失败。
- **飞书通道把文字当指令，非文字消息「收下而非丢弃」** —— 图片/文件（带可下载附件）
  会**下载到状态目录 `attachments/`、落入「待处理收集器」，并回一句「已收下」**；
  富文本仍只回一句「我只处理文字」（带上实际收到的类型）。**都不建事务**：
  收集器里的东西等你显式 `/pending N` 才澄清成事务（`/pending` 列出，先进先出；
  下载失败也照样入队 —— `media_key` 是重新下载的凭据）。`/today` 在有待处理时
  会多一行「待处理 N 条」提醒，0 条不占位。
  这条告知**只发给白名单内、且群里确实 @ 了 bot 的人**：白名单外连告知都不回
  （回一句就等于向陌生人确认「这里有个 bot」），群里没 @ 也不回（否则随手发张图
  就抢着说话，等于破坏「不抢答」）。
  群里必须 @ **bot 自己**才响应（@ 别人不抢答，@ 所有人也不算数），判定靠 bot 自身 `open_id`
  （启动时自动探测，缓存到 `feishu_bot.json`）。探不到身份时群聊**失败关闭**
  （群里不响应、私聊正常），启动会告警。
- **事件去重表落盘**（`feishu_seen_events.json`，24 小时 / 2048 条），
  所以长连接重连重投时不会重复建事务，重启也记得。
- **同一台机器只允许一个桥接进程**（`FEISHU_LOCK_PORT`，默认 8771）——
  跑两个的话飞书只把事件投给其中一个，另一个静默失效。
- **执行期逐次授权的飞书卡片**（`permission.asked` → 卡片 → 点回 → 送回 opencode）
  已接线并有 53 项回归测试覆盖。**真机验过哪几格见
  [`docs/真机验收矩阵.md`](docs/真机验收矩阵.md)**（允许/拒绝 2026-10-03 已验；
  第三个按钮「停止这条委派」仍未验 —— 它的载荷是新的，前两项不能顺带证明它）。
- **委派的实时交互有两套界面**（V1.35）：飞书是 CardKit 流式卡片（执行器直推），
  网页是 2 秒只读轮询（`GET /api/delegate/live`）。**同一份落库状态**，
  两边看到的进度、待批项、结论一致。
  ⚠️ **网页端是离线验过的，飞书端才是真机验过的** —— 网页那条链路的每一环
  （落库投影、快照、授权写入口、提问逐轮）都有回归测试，但**没有起真 opencode
  跑过一轮完整委派**。首次真跑请盯紧面板与执行器日志。
- **网页只决「没带发起人身份」的待批项**（V1.35）：飞书发起的委派带着 `ou_…`，
  网页没有那个身份可出示，于是只读不给按钮。理由是「只有发起人能批」是硬规则，
  而底层 `resolve` 对空 `decided_by` **根本不判**（不自己判就会被击穿）。
- **环境变量:委派与 `/ask` 走的是两条路**（V1.31 起，别再当一条读）：
  - **委派**（`isolate=False`）：子进程是 `dict(os.environ)` **全量继承**。
    代价说在明处:模型凭据之外的东西（比如你 shell 里的其他 Key）子进程也看得见。
  - **`/ask`**（`isolate=True`，因为 `cli/app.py` 那个工厂**没传** `isolate`、
    吃下了默认值）：走 jail，环境是**白名单**（本机实测 77 → 22 个），
    家目录 / 配置 / 缓存 / 临时全指一次性目录 —— 慢与离线不可用是同一个原因的
    另一面，不是两个 bug。
  ⚠️ 设计文档 11.8.1 写着「三个构造点统一 `isolate=False`」——**对 `/ask` 不成立**。
  这条漂移还没修（设计文档是实现契约，改它要走版本号），先在这里记实。
- **数据库 schema 升到 29**（V1.96；V1.37 起 `task_records` 新增 `seq` 序号列，
  V1.35 的 `delegate_progress` 表 + `pending_approvals.task_id` 也在其中；
  V1.90 加 `pending_approvals.thread_root`、V1.92 加 `decided_via`、
  V1.93 加 `tasks.origin`、V1.94 加 `dispatch_leases`、
  V1.95 加 `artifacts.model` / `artifacts.tool_calls`、
  V1.96 加 `task_records.error_kind`）。
  旧库第一次启动会**自动迁移**（`ALTER TABLE ADD COLUMN` + `CREATE TABLE`，幂等；
  存量记录按写入序回填 `seq`）。两列都**可空/可缺**：加列前的待批行没有归属，
  判为「不归属」而不是猜。
  **库的形状只有一个写入口**（V1.93）：新库也走同一条迁移链重放，
  所以「全新安装」与「老库升级」跑的是同一段代码 —— 不会再出现
  「老库缺表 / 新装缺列」这种方向相反的事故。
- 装了飞书通道等于开了一个远程入口 —— 缓解措施是白名单失败关闭
  （`FEISHU_ALLOWED_USERS` 为空则拒绝启动）、App Secret 只从环境变量读、
  委派走白名单 + 逐次授权。但它仍然是
  「谁能指挥你本机」的信任边界，配置时别图省事。
  **完整的信任边界、实测出的硬约束、以及「不要把本项目当成不可信负载的
  唯一安全控制」这条，见 [`docs/SAFETY.md`](docs/SAFETY.md)。**
- **委派恢复与每日备份**（V1.39）：执行器启动时会扫「挂起待批 + 投影陈旧」的委派，
  追加一条执行期失败终态记录（错因：执行器中断后无人续上）并推飞书通知；
  网页面板对陈旧且未结束的行给「重新派发 / 放弃」按钮（走与终端
  `/redispatch`、`/drop` 同一套服务层写入口；放弃加一次确认）。
  每日滚动备份（`bak-daily` × 7）在 CLI / 执行器 / Web 启动时各触发一次，
  设置页显示最近备份时间。**停止按钮真机仍待验**（矩阵 `A7`）。
- **「在跑」是租约观察出来的，不是从日志形状猜的**（V1.94）：`dispatch_leases`
  表记着派发租约与到期时间，所以「正在跑 / 失联」是**能观察到的事实**，
  不再靠「末条 dispatched、无终态」这种形状推断 —— 那个形状在「真在跑」和
  「跑到一半崩了」下完全一样，而崩溃之后正是唯一需要它的时刻。
  ⚠️ 租约只解决「在跑」可观察，**并发派发 L1（项目级租约 + 有界线程）未做** ——
  多个执行器进程同时扫同一目录仍会争。
- **审批闸门只有两档**（至今）：只支持 Allow Once / Deny，**没有 Session /
  Always**；**不校验点击者**（只记 `decided_by`，靠 uuid4 不可猜兜底）；
  写入/删除走委派链路，**尚未接上这套闸门**。
- **引擎侧只接上了失败分类**（V1.96）：引擎每天在本机写的东西
  （`~/.local/share/opencode/opencode.db`：222 条会话 / 906 次 edit / 1072 次 bash）
  **几乎没被接上**。本版只落了「失败怎么分类、给什么下一步」；
  **会话续接**（跨进程续接已验证，跨目录边界待额度恢复后再验）与
  **引擎的账**（token 已验，「改了哪些文件」待验）未做。
