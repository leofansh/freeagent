## 信任边界在哪

本项目有一条**远程输入 → 本地代码执行**的链路：

```
飞书（谁能发消息）
  → bridge（白名单门控）
    → channel（命令派发，规则与终端共用一份）
      → delegate（项目白名单 + 必须先 /start）
        → opencode（独立进程，独立配置目录）
          → 改你的文件
```

**这条链路的终点是你本机的文件。** 装了飞书通道等于开了一个远程入口 ——
凡是能对这台机器发消息的人，都在信任边界内侧。

## 实测得出的三条硬约束

这一节记的都是**量过的**，不是推断的。

### 1. opencode 的权限默认放行

官方 V1 文档原文：*"Most permissions default to `allow`*"。

所以**「不传 `--auto`」不构成任何保护** —— 实测不传它同样目录内写文件执行、
**写出目录外也执行**，且不产生任何授权事件。当年的「已验证」验的是
「不加危险开关也能跑通」，而那正是权限缺失的表现。

真正的闸门是**执行期逐次授权**（`--tool-gate`）：每要动手一次发一张飞书卡，
卡上写明动作、影响路径和 **diff**。完整机制与踩坑见
[复盘 0001](postmortem/0001-auto-flag-is-not-a-gate.md)。

### 2. 隔离靠的是环境，不是配置

- 委派跑在**独立的 opencode 进程**里，配置隔离在**一次性目录**，
  **不碰** `~/.config/opencode/opencode.jsonc`，**不加载你的插件**
  （无人值守时攻击面更小）
- 隔离机制必须用 `XDG_CONFIG_HOME`（**完全替换**）而不是 `OPENCODE_CONFIG`
  （**合并**语义 —— 未指定的键沿用用户的，那是 fail-open）

### 3. Windows 上必须整组收口

`terminate()` 只杀掉 `opencode.CMD` 批处理包装器，原生 `opencode.exe`
**不会跟着死**。实测 14 次探针各漏一个，累计约 **12.5 GB**。

所以用**进程组**整组收口，并**验端口**。

## 不要依赖本项目当唯一防线

这一条是本文件最重要的一句。

**审批与闸门能降低风险，但不构成隔离，也不保证不造成损失。** 即使全部正确执行，
它也保护不了你**已经允许它访问**的那些资源。

所以：

- 按**最小权限**运行，**别**给它不需要的目录与凭据
- 备份它能碰到的文件
- 装了飞书通道的机器，**别**放不可重放的凭据
- 真要跑不可信的工作量，**用一次性的虚拟机 / 容器**

**不要把本项目当成不可信负载的唯一安全控制。**

## 密钥

设计上「Key 不会进配置文件」是**靠类型防住的**，不是靠约定：

- `Config` **压根没有 `api_key` 字段** —— 它是个现读环境变量 / `llm.env` 的 property
- `config.json` 里**永远不会有 Key**
- `llm.env` 在 `~/.freeagent/`，环境变量仍优先于文件
- `secrets.py` 的 `SecretStr` 让密钥**在类型层面无法被 `print` / 日志带出**
- `tests/` 里那些 `sk-*` 是**故意埋的探针**，用来证明密钥不会漏进错误信息与日志。
  它们不是泄露

## 失败时必须停下而不是降级放行

这条贯穿全项目，写在这里因为它最容易被违反：

| 遇到 | 必须 | 不能 |
| --- | --- | --- |
| opencode 主版本不是 V1 | 拒绝派发（退出码 2） | 警告后照跑（旧字段被**静默忽略**） |
| 模型输出里编造的角色名 | 丢弃 | 建成角色 |
| 模型不可用 | 如实打印「已退回规则推断」 | 静默劣化 |
| 提醒推送失败 | 令牌不落库，下轮重发 | 标记成已送达 |
| 白名单为空 | 谁都不许 | 谁都放行 |
| 探不到 bot 身份 | 群聊**失败关闭** | 群里瞎回应 |

复盘 0001 与 0003 都是这条规则的直接产物。

## 报告安全问题

不要开公开 issue。私有渠道发给维护者，并附上：版本、操作系统、复现步骤、
**脱敏后的**日志。

> **调试日志可能含敏感内容**（对话、截图、音频）—— 分享前先自查。
> 不要提交 API Key、私人对话或未脱敏的截图。
