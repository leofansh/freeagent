## 1. 三十秒版

一个**跑在你自己机器上**的个人事务助手。

- 日常在**飞书**里跟它说话，或开 <http://127.0.0.1:8770/>
- 它管的是「今天该做什么」「这件事卡在谁那儿」「上次那个事后来怎么了」
- 它**不替你决定**优先级——只给带理由的确定性弱信号，你可以反驳
- 写代码的活它**不自己写**，而是交给 OpenCode：要么派一条**委派事务**
  （你验收、留账），要么在 **工作台**里直接说一句（它自己判要不要动手，
  V1.114）

## 2. 现在能干什么（已实现且有测试守着）

| 能力 | 入口 | 一句话 |

| 工作台的「最近的活」 | 工作台页签底部列表 | 每一轮**落库**（`workbench_turns`），关掉网页 / 重启之后还能把最近几轮列出来、**点开接着看**。列表**不含正文**（列出来是为了找得到，不是把首页变成聊天记录）；连点两次落在同一秒也不会乱序（按 `rowid`）。**轮次的正文没在浏览器里点过**（V1.115） |

| 工作台带上「家里的事」 | 发送框下的勾选框 | 每轮把「今天的活 + 未结清承诺 + 相关记忆」折成**一行**跟在你的话后面发出去，界面上写「背景：附带 3 条…」；**只读**（不顺延事务、不在 `task_records` 留记录）、**读不出来≠没有**（降级要点名）。可当场关掉（V1.115） |

## 3. 三层结构

```text
freeagent/
├── domain/      纯值对象，零 I/O、零业务判断
├── storage/     只存取，不判断（顺延/权重/迁移合法性都不在这层）
├── services/    全部业务规则与不变式 ← 闸门也在这里
├── llm/         LLMProvider 协议 + 规则兜底 + OpenAI 兼容客户端
├── cli/         REPL（终端）
├── web/         本地 Web（零框架零外部资源）
└── feishu/      远程通道：全仓唯一依赖 lark-oapi 的一层
      ↑
   app.py     依赖组装：CLI / Web / 测试共用同一条装配路径
```

三条纪律，改代码前先看：

1. `services` 承载全部业务规则。Web 层**不许**自己再算一遍顺延或排序。
2. `services/llm/provider.py` **不 import domain**——这是换真实 LLM 的接缝。
3. 核心包 **`dependencies = []`**，唯一第三方依赖是 pytest。断网必须照常能用。

## 4. 三个入口，对等

| 入口 | 怎么起| 特点 |
|---|---|---|
| **飞书** | 开机自启（启动文件夹放一个 `.cmd`） | 最省事，日常只需要它 |
| **Web** | `python -m freeagent.web` → `127.0.0.1:8770` | 零框架；**只监听回环**，其他地址直接抛错 |
| **终端** | `python -m freeagent.cli.app` | 角色合并、改名、静置等只能在终端 |

**通道之间不广播。** 一条事务在哪儿创建就在哪儿处理。

**第四个入口（V1.114）：Workbench 在工作台页签里，不是独立进程。** 页签里选
目录 + 模型 + 授权档，说一句话就开跑 —— 引擎（OpenCode）由宿主常驻，**第一次
点「交给它」才起**，关 FreeAgent 时一并收掉。它与「委派」并存：委派留验收与
账，工作台图快。

## 5. 怎么跑

```bat
REM 日常：飞书（开机自启，不用管）
REM 手动起桥接（会先跑 doctor 自检凭据）
tools\run_feishu.bat

REM Web 界面
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.web

REM 终端
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.cli.app
```

配 LLM（可选，不配也能跑通全部功能，只是分类靠规则）：

1. 环境变量优先：`set DEEPSEEK_API_KEY=sk-...`
2. 或落`~/.freeagent/llm.env`
3. `/llm` 看当前生效的是哪一个（**显示 Key 来源，不显示 Key**）

强制只走规则层（离线排查）：`set FREEAGENT_RULES_ONLY=1`
禁止自动降级（宁可报错）：`set FREEAGENT_ALLOW_FALLBACK=0`

跑测试（交付前必须全量绿，约 6 分钟）：

```bat
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m pytest --basetemp=.pytest-tmp\all
```

`--basetemp` 指到仓内目录：pytest 默认要清理 `%TEMP%\pytest-of-*`，会直接被
沙箱拦（理由见 AGENTS.md）。

**跑完看那行 `!!!!` 横幅，不是只看 `N passed`**（V1.106）：它按原因列出
「本次有几条没有验证」。本仓的跳过全是环境缺失（缺 node / opencode），而
`test_web_js_syntax.py` 是**唯一**守 web 包 JS 语法的地方 —— 缺 node 的机器上
那一块从没被验证过，而 `N passed` 读起来像全绿。要把它算进「已验证」，
装上那个依赖再跑一次；不想装就记着「这一块这次没验」。

改测试时的两条硬规矩（`tests/test_assert_discipline.py` 守着，会红）：

1. 跳过必须写 `reason` **字面量**，说清缺什么、补什么能跑（不许藏进变量）。
2. 不要用 `time.sleep` 等结果 —— 等可观察状态（条件轮询 / `FrozenClock` 推进）。
   确实只能真等，就在 `SLEEP_BUDGET` 里登记「在等什么、为什么没有状态可等」。

## 6. 已知边界（会咬人的地方）

| # | 边界 | 后果 |
|---|---|---|
| 1 | **提醒是轮询式** | 两个进程都关就收不到。Web 界面**不解决**这个 |

## 7. 几个反直觉的设计（别顺手"修好"）

| 现象 | 为什么故意的 |
|---|---|
| 排序不给出「就做这个」 | 用户无法反驳一个看不见的分数，但可以反驳一条带理由的信号 |
| 每条事务都挂「启发式提示，不是评分」 | 这句话是产品承诺，删了就是把判断权悄悄收回 |
| 委派时先问权限、再问模型 | 否则 LLM 会挑一个无权访问的项目满口答应，结果没做 |
| 简报**单行**，不加 markdown 排版 | 实测（opencode 1.18.31）：提示里**只要有一个换行符**，opencode 就升级到主 agent 的强模型并**无视 `--model`** → 余额不足直接 402，委派全盘失败。**「格式好看」和「能跑」在这里冲突，能跑优先** |
| 委派简报带**世界的事实**，不带人的倾向 | 带的是「这个项目以前踩过什么坑」「人定了什么方案」「人记了什么约定」；**不学人的偏好、不调权重** —— 那是 11.9.11 刻意划的界 |
| 引擎失败只说**可执行的下一步**，不说「重试」 | 「允许重派」≠「重派有用」：配额错误重派一百次还是 429。**11.8 判能不能重试，12.10.11 判下一步做什么** |
| 认不出的引擎错误归 `unknown` 并**原样保留原话** | 宁可给不出建议，也不给错建议 —— **错建议会把人引到错方向，漏判只是没建议** |
| Web 只能建事务不能合并角色 | 合并不可逆且要能回看，这种操作留在能敲命令的地方 |
| 桥接状态显示「在跑但不是本界面启的」 | 合并成「在跑/没跑」等于把「管不着」谎报成「干净」 |
| 能杀进程的操作只挂 POST | 浏览器预取、爬虫、`<img src>` 都会自动发 GET |
| 白名单默认为空 | 白名单为空是**致命配置**，所以拒绝启动而不是默认放行 |
| 明文密钥落盘但不假装加密 | DPAPI 只防「其他 Windows 用户」，同用户进程照样能解；防那个的是会话令牌 |
| 委派禁止读 FreeAgent 自己的配置 | 否则执行器会把自己的 LLM 凭据反向读出来 |
| 冲突时以 `设计方案.md` 为准 | 它是逐字契约，`test_doc_contract.py` 守着 |

## 10. 市场对标（Today AI / Dots / Muse / 国内双雄 / OpenCode 生态）

> 一句话：FreeAgent 不是「AI 同事」，是**跑在你自己机器上的外接记忆 + 待办澄清**。
> 竞品强在「替你连、替你干」，FreeAgent 强在「替你记、提醒你、不替你发 / 不替你决定」。

| 维度 | **FreeAgent（本仓）** | Today AI（此间无限，齐俊元） | OpenAI Dots（2026-09 DevDay） | **Meta Muse（2026-09-08）** |
|---|---|---|---|---|
| 定位 | 个人本地 CLI / Web，外接记忆 | 商业云「活记忆」个人 Agent | 商业云「常驻 AI 同事」，关窗接着干 | 商业云「替你干活」Agent，上线即登顶美区榜首 |
| 连续性记忆 | ✅ 记忆(3.7) + /model + 待处理收集器 | ✅ living memory（profile/work/goals…） | ✅ 跨会话保持目标与上下文 | ✅ Active Memory（跨对话记住你、主动召回） |
| 承诺主动提醒 | ✅ OVERDUE_WAIT / PROMISE_OVERDUE / NudgeService | ✅ founding 场景即「找出你许下没跟进的承诺」 | 通用任务推进，非专做承诺 | 目标拆解 + 推进，非专做承诺 |
| 人在回路 | ✅ **fail-closed，结构上无发送能力** | 发送前确认 | 权限三档（允许 / 需批准 / 禁止）；人不在时强制只读 | Sentinel 监督全部对外操作 + 敏感动作人确认 |
| 数据源 | 只录你主动交给它的 | 跨应用连接器（日历/邮件/笔记…） | **云端电脑 + 4000+ 应用**，可连本机 | Muse Secure VM + 自建连接器（Shopify/Walmart…） |
| 自主执行 | ❌ 不做子任务、写码派给 OpenCode | ✅ 任务执行 / 后台并行 / GUI Agent | ✅ 7×24 后台、自有浏览器跑多项目 | ✅✅ 最激进：替你发邮件 / 购物 / 谈账单，退出 App 仍在跑 |
| 部署 | 本地优先、零依赖、断网可用 | 云端常驻 | 云端常驻 | 云端常驻（专属安全虚拟机） |
| 护城河 | **本地 / 零依赖 / 不替你对外行动** | 主动双锚点 + 连接器广度 | 规模与模型（GPT-6 Astra） | 安全架构（Secure VM + Sentinel）+ 生态广度 |

**为什么 FreeAgent 不借那两点**：跨应用连接与自主执行，与本地优先 / 零依赖 / 隐私半径 / 不做子任务 / fail-closed **正面冲突**。把「替你连外部、替你对外发」做进来，就不再是同一个产品了。对齐点在「连续性 + 人在回路」，分歧点在「是否替你对外行动、是否读外部数据源」—— 后者是刻意守住的差异化，不是短板。

**Muse 是最尖锐的对照样本**：它把「替你做」推到极致（替你发、替你买、替你谈，还从你的交易里抽成），恰好把 FreeAgent「增强范式」的护城河衬到最亮——我们要的不是少做那部分，是**永远不做那部分**。详见设计文档「〇、产品哲学与演进方向」。

**边界纪律（怎么守住）**：见设计文档 **§11.22 显式触发边界清单** —— 每个能力归入 `EXPLICIT_ONLY`（显式触发才建状态）/ `READ_ONLY`（只读不可变）/ `NO_SEND`（可主动提醒自己、结构上无对外发送能力），未列入的能力一律禁止静默改动状态。

**「验过没有」是另一笔账**：代码写完有测试兜着，**人真的点过没有**只有人知道。审批链（允许 / 拒绝 / 停止 / 答提问 / 超时 / 谁有资格点）逐格记在 `docs/真机验收矩阵.md`，空框就是**没点过**。这份速读**不重复它的数字** —— 是几个空框，去那份文件的摘要行看（同一个事实写两处，就是本文件第 8 节刚刚解释过的那种烂法）。

### 10.1 增强范式版图（2026，非规范性速读）

> 上表（FreeAgent / Today AI / Dots / Muse）是"含替代范式极端"的对比样本。下面把"增强范式"这一侧的玩家按品类铺开，看 FreeAgent 站在哪。

| 品类 | 代表产品 | 与 FreeAgent 的关系 |
|---|---|---|
| 记忆义肢（Lifelogging） | Limitless（原 Rewind，已被 Meta 收购整合）、Screenpipe（开源·本地优先·可接 MCP）、MS Recall（系统级·闭源） | 同"记忆层"；FreeAgent 取 Screenpipe 的本地优先姿态，但不做全量屏幕录制 |
| 第二大脑（AI Notes） | Mem.ai、得到大脑（Get 笔记）、flomo 浮墨（Agent 读你全部笔记·MCP） | 同"结构化记忆"；FreeAgent 把记忆进一步结构化成交互面相（节奏 / 关系账 / 承诺与目标） |

### 10.2 价值假设（非规范性，详见设计文档 〇.7）

- **范式有市场，且大**：Meta 收购 Limitless、Apple / MS / Google 下注、Mem / flomo / 得到 / Screenpipe / Notion AI 均有真实付费，"第二大脑"已验证。
- **FreeAgent 切口小但真实**：本地优先正变入场券、fail-closed 不卖，唯"结构化个人事务面相"可 own；属红海里的信任型小众位。
- **价值来自行为改变，不来自立场**：能否让你真的少漏掉生活里重要的事（少放鸽子、少漏承诺、看清精力节律），才是付费与留存理由。
- **元纪律**：差异化是立场不是壁垒；讲给外人时当"我们刻意不那样"，不要讲成"我们因此无敌"。

### 10.3 国内双雄：WorkBuddy（腾讯）与豆包（字节）

> 海外三家（Today AI / Dots / Muse）是"范式标本"；真正和中国用户每天打交道的，是这两家本土巨头。它们把同一对矛盾（增强 vs 替代、职场 vs 生活）在本土生态里跑出了两种答案。

| 维度 | **WorkBuddy（腾讯）** | **豆包（字节）** |
|---|---|---|
| 定位 | 全场景职场 AI 智能体**桌面工作台**（B 端生产力 Agent） | 国民级 AI 助手（C 端起家，现转型"AI 生产力核心平台"） |
| 范式站位 | **增强·职场**：像同事一样规划执行、交付可验收成果，有高危指令拦截 | **替代·生活**并上探办公：主动"创造需求"、聊天框内做电商交易闭环 |
| 生态绑定 | 腾讯文档 / 企业微信 / 腾讯乐享 / Ardot / 开放平台 | 抖音电商 / 飞书 / TRAE / Coze（"豆包工作"） |
| 规模 | 桌面端 AI 办公月访问 8534 万（合并 CodeBuddy 超 1.1 亿）领跑 | 月活 4.19 亿（2026-09），中国第一 |
| 商业化 | 企业套件 + 开放平台（硬件 / 专家 / 技能 / 连接器） | 算力成本高、规模不经济；双 11 主动带货、推电商券走交易闭环 |
| 对中国用户的契合 | **价值观契合**：可信、合规、不替你做主，贴合职场人对"靠谱不越界"的深层诉求；但服务 B 端，非大众习惯 | **习惯与审美契合**：长在抖音 / 移动生态，零学习成本、活泼审美，就是网民习惯的延伸；但"主动营销"在消耗 AI 客观中立的信任 |

**关键判断（非规范性）**：
- 论**大众日常习惯 + 大众审美**，豆包更贴——它本就是中国网民习惯的延伸；论**深层价值观（可信 / 可控 / 不越权）**，WorkBuddy 更贴，但它服务职场 / 企业而非大众 C 端。
- 两者恰好印证 〇 章的两范式框架：WorkBuddy 落在「增强范式（让你做）」一侧，豆包往「替代范式」滑并带商业操控。差异化不是谁对谁错，是切口不同。
- **FreeAgent 的空档**：它既非 WorkBuddy 的职场协作，也非豆包的大众入口，而是两者之间的**「个人主权」空档**—— 本地优先 + 不越权 + 结构化个人事务。这个空档的价值假设见 10.2 / 〇.7：价值来自行为改变，不来自立场。

### 10.4 OpenCode 生态智能体谱系（非规范性，详版见设计文档 §19.7.10）

> 上面三家海外 + 两家国内，都是"个人 / 通用 Agent"赛道。把镜头拉到"开发底座"赛道：OpenCode 在 2026 年已是开源编码 Agent 事实标准底座（220K+ stars、~16M 月活），围绕它长出一批"基于 OpenCode 开发的智能体"。本仓 freeagent / openmos / xiaoyuan 也在这条线上。

| 定位 | 代表 | 自我定位 |
|---|---|---|
| 多玩家 / 团队 harness | **qm**（yc-software） | 给创业团队的多员工隔离 workspace + 频道协作 agent harness |
| 替代范式全能助手（OpenCode 当引擎） | **OpenWork** | 开源替代 Claude Cowork，由 OpenCode 驱动、自主操作桌面 / 文件 |
| 模块化 / 专业 agents 团队 | **Agentic / zenox / oh-my-opencode / opencode-agents** | 把单一 agent 变一群专家：模块化开发 / 5 领域 specialist / 多模型编排 |
| 工作流驱动 agent | **micode / opencode-conductor / goal / subtask2** | 把开发固化成流程：Brainstorm→Plan→Implement 等 |
| 治理层 + OpenCode 执行器 | **FreeAgent（本仓）** | 把时间 / 记忆 / 关系还给人，OpenCode 只是执行器 |

> 规模：OpenCode 官方 ecosystem 列 30 插件 + 11 项目 + 2 agents，加独立构建共 40+；真算"完整智能体产品"约 10 个。插件（脱敏 / 记忆 / 定时 / 抓取 30 个）与前端入口（nvim / OpenChamber / CodeNomad / Obsidian / kimaki / ocx）不算智能体本身。

**关键判断（非规范性）**：
- 约 10 个智能体里，六个（OpenWork / Agentic / zenox / oh-my-opencode / micode / conductor）定位全是"怎么把 OpenCode 变得更能干"——专家分工、多模型编排、流程固化、自主操作，全在「怎么做成」那一层；qm 上探团队 harness，仍偏编排 / 执行基础设施。
- **只有 FreeAgent 一个把 OpenCode 当执行器、自己在治理层 + 增强范式**——OpenCode 生态里「能替你干活的 agent」一抓一大把，「帮你管时间 / 记忆 / 关系、不替你干」的只有 freeagent 一个。差异化在 OpenCode 自己的生态里也是独一份。
- 从"个人 Agent 赛道"（10.1–10.3）到"开发底座赛道"（本节）：FreeAgent 的空档一致成立——别人在 OpenCode 上卷"谁更能写代码"，它在 OpenCode 上卷"谁更懂你的生活 / 学习"。详版与 qm 深挖见设计文档 §19.7.10。
