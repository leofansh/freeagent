# 真机验收矩阵（审批链）

> 一句话：**这张表记的是「人真的点过没有」，不是「代码写完了没有」。**
>
> 这两件事在仓里一直是两笔账。第一笔有测试兜着（`tests/` 三千多条）；第二笔
> 此前**散在三个文件的十来处散文里** —— 11.8.1 落地状态表、11.9.4「现状与边界」、
> 一次走查结论、20.1.6 待办、README 三处、`AGENTS.md` 引擎侧待办 #4。同一句话
> 抄十来遍，改一次就要改十来处，于是必有一处烂掉。`现状速读.md` 里那句
> 「同一个事实写两处，**会被顺手改的那处改了、不会被顺手改的那处烂掉**」
> 说的就是这件事，只是当时没人把它用到这句话上。
>
> 从本文件起：**审批链的「验过没有」只在这里写一次**，别处只留指针。

**范围**：执行期逐次授权（11.8.1）与它自己的行为边界。**不含**收尾（验收采纳，
12.8）、陈旧委派的恢复（重派 / 放弃，12.11.1）、以及引擎字段形状的实测（那些
记在对应章节里，验的是协议不是按钮）。

## 怎么读

| 记号 | 意思 | 谁来填 |
|---|---|---|
| ✅ | 真机上点过，且**证据带日期、能复查** | 「已验格子的证据」那一节 |
| ⬜ | **没点过**。不是「应该没问题」，是「没验」 | 「空格子怎么验」那一节 |
| ✖ | 这条**根本没实现**（不是没验） | 附录 |
| ➖ | 这道闸门不覆盖这个通道（设计如此） | 不需要 |

三条纪律：

1. **⬜ 不许改写成「已支持」「应该没问题」**。「有测试」与「人点过」是两笔账，
   混着写的结果是本仓反复踩的那个坑：测试全绿，而真机上点了没反应。
2. **✅ 必须带日期与可复查的落点**（查哪张表、看哪一行、日志里哪一句）。
   没有复查方式的 ✅ 等于 ⬜ —— 它只是让别人不好意思怀疑。
3. **编号只增不重排，作废用删除线**（借 OpenHands `@spec` 那条规矩）。
   `tests/test_acceptance_matrix.py` 冻着编号全集：删一格必须去测试里显式划掉，
   于是它一定会出现在 diff 里，而不是悄悄少一行。

⚠️ **「飞书私聊」那两格的证据早于话题化。** `A1`/`A4` 的样本取自 2026-10-03，
那时授权卡**直接回在私聊主消息流里**；V1.90 起 `_card_delivery` 的

严格说是 `A2`/`A5`（未验），`A1`/`A4` 只证明「私聊卡点得动」这件事本身。

**终端不是第四个通道**：`delegate` 没配飞书通道时**失败关闭**并列出三条出路
（11.8.1），它不承载审批。所以这一列不是「没验」，是「没有」。

## 空格子怎么验

「怎么验」写到**点到什么程度算过**；「为什么不能顺带证明」一栏是这一节的重点
—— 它挡的是那句最常见的合理化：「旁边那格都验过了，这格应该一样」。

| 格子 | 怎么验（点到什么程度算过） | 为什么不能顺带证明 |
|---|---|---|
| `A2` `A5` | 起一条委派（卡会自动进话题）→ 在**话题里**点允许 / 拒绝 → 查 `decision` 与 `decided_via='card'`，且执行器按结论继续 / 改向 | V1.90 的探针七项只证「卡进得了话题」「话题内更新照常」，**没点过按钮**；而回写收据依赖 `open_message_id`，话题里那张与主消息流那张不是同一个 id |
| `A3` `A6` | 起**真 opencode** 跑一轮 → 面板点允许 / 拒绝 → 查 `decided_via='web'`、`decided_by` 为空、执行器按结论继续 / 改向 | 面板每一环都有回归测试，但 README 自己写着「网页端是**离线**验过的」—— 没起真执行器跑过完整一轮。接口通 ≠ 人看得到、点得动 |
| `A7` `A8` | 起一条委派，等一张授权卡 → 点第三个按钮 → 四件事都要看到：① 卡写「已停止」② `decided_via='stop'` 且 `stop_requests` 有行 ③ **执行器进程真的退出**（不是换个方向继续）④ 已改的文件仍在、剩下的没做 | 允许 / 拒绝验过只证明「按钮 `value` 能原样带回」这条通用前提；停止的载荷是新的（`kind`），而且它一次做两件事（记停止 + 回掉挂起）。**这就是拖了十几版的那格** |

## 附录 · 项目级目录审批（旧证据，**已不在链路上**）

这道闸门（`services/localops.py` 的 `DirectoryAccess`）在当前代码里**没有任何
生产调用点**：`grep DirectoryAccess src/` 只有它自己，`delegate.py` 只用它顺手
定义的 `CardSender` 协议。它当年确实通过，证据保留作凭证，但**不能拿来给委派
那条链作证** —— 两条闸门同库不同路，一条验过不等于另一条验过。

| 动作 | 状态 |
|---|---|
| 允许一次 | ✅ `D1` |
| 拒绝 | ✅ `D2` |
| 过期后才点 | ✅ `D3` |
| 非白名单人点 | ✖ `D4` |

证据在上一节（`D1` `D2` `D3` 那一行，2026-09-29）。

- `D4` **✖ 未实现**：`DirectoryAccess.request()` 只把 `decided_by` 读出来写日志，
  不做比对（11.9.4「尚未实现 · 不校验点击者」）。**这是缺口，不是待验项** ——
  别把它当 ⬜ 排进验收计划，排进去也只会得到一个「验出来是没挡」的结果。

## 怎么加一格

1. 先在表里加编号（**下一个号，不复用**），状态写 ⬜。
2. 同时写「空格子怎么验」那一行 —— 没有复查方式的格子不算登记，只算许愿。
3. 真点过之后：状态改 ✅，把日期与复查落点写进「已验格子的证据」，删掉
   「怎么验」那一行（它已经兑现了）。
4. 去 `tests/test_acceptance_matrix.py` 的编号全集里加一行。忘了它的后果是测试
   报红，而不是这一格悄悄消失。
5. 摘要那两行数字跟着改 —— 忘了也会报红（测试重算）。
