## 一、30 秒上手

### 装成桌面应用（不想碰 Python 就用这个）

拿到 `Steward` 目录（或它的 zip）：解压 → 双击 `install.cmd`。它把程序复制到
`%LOCALAPPDATA%\Steward`、在桌面放一个 `Steward` 快捷方式。以后双击快捷方式就行，
**这台机器不需要装 Python**。

三件要提前知道的事：

- **关窗口就是停服务。** 没有托盘图标，窗口就是唯一的开 / 关开关；它正在跑的那一轮
  会被中断。想让它继续跑、自己只把网页关掉，就用下面的网页版。
- **第一次可能被 SmartScreen 拦一次。** 包没有代码签名（证书是付费的），Windows 会
  提醒「来自网络」—— 选「仍要运行」即可。
- **数据和网页版是同一份。** 都在 `%USERPROFILE%\.steward`；`uninstall.cmd` 只删程序
  与快捷方式，**不动这份数据**（要删自己删）。

出问题先看 `%USERPROFILE%\.steward\desktop.log`：服务起没起、每个请求、窗口关没关，
都在那一个文件里。

### 打开就能打字（推荐先试这个）

双击 `tools\run_web.bat`：它自己设好编码与 `PYTHONPATH`，依次找 PATH 上的
`python`、`py` 启动器和标准安装目录下的解释器，低于 3.11 会停下来说清原因；
服务起好后自动打开浏览器。

手动方式（等价）：

```bash
cd D:\PycharmProjects\freeagent
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.web
```

> 名字叫**值守 / Steward**，但**包名没改**，所以 `python -m freeagent.web` 一直
> 有效。`pip install -e .` 之后还可以直接敲 `steward`（同一个入口，短一截）；
> 旧的 `freeagent` 命令作为别名保留 —— 按旧名字装过的快捷方式不必改。

浏览器打开 <http://127.0.0.1:8770/>，**首屏就是一个对话框**。直接问：

```
今天该做什么
周报进展怎么样
我在等什么
我上周完成了什么
```

或者直接说一件事记下来：

```
下周二要交的销售周报初稿
```

**它能问什么、不能问什么，见第五章。**

### 启动终端版

```bash
cd D:\PycharmProjects\freeagent
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.cli.app
```

### 先试这三条

```
> 下周二要交的销售周报初稿，先理一版
> /draft <前面给的 id 前几位>

```

第三条是核心：它把这条事务的**意图、完成标准、当前草稿、进度、最近记录、下一步建议**
一次全给你看 —— 中断几天回来，靠的就是这一屏。

## 二、它解决什么问题

一句话：**按「角色脉络」组织事务，而不是一个扁平的待办列表。**

具体解决三件事：

| 问题 | 做法 |
|---|---|
| 事情混在一起，看不出是工作还是家里的 | 每条事务挂一个或多个**角色**，角色视图分开看 |
| 中途被打断，回来得从头捡上下文 | 每条事务有**恢复契约**，`/task` 一屏还原 |
| 该先做哪件没依据 | 给**透明的弱信号**（附理由），但不替你决定 |

**它不做的事**：不替你判断哪件事更重要。

## 三、必须先懂的 5 个概念

不懂这几个，你会觉得它「问东问西」。懂了之后就很自然。

### 1. 角色 = 事务的来源语境

不是你的身份，是「这件事从哪来」。比如 `工作项目A`、`家庭`、`个人创作`、`跑腿杂项`。

- 一条事务**至少**属于一个角色，可以属于多个
- 角色可以随时**改名、合并、静置**
- **角色名和备注里的词会用于自动推断** —— 所以 `/role-add` 的备注要写关键词

```
> /role-add 工作项目A 销售 周报 客户
> /role-add 家庭 孩子 学校 材料
```

写完备注后，说「销售周报初稿」就能自动归到 `工作项目A`，不用每次指定。

### 2. 三种形状（kind）

| 形状 | 用于 | 例句 |
|---|---|---|
| `动作` action | 要产出某个东西 | 写周报 |
| `等候` wait | 等别人/系统/时间 | 等客户回复合同 |
| `提醒` reminder | 到点通知一下 | 下午三点提醒我修窗户 |

**这个区分很重要**：等一件事不需要你「做」，所以它不该混在待办里消耗注意力。

### 3. 三个状态（state）

`待办` → `进行中` → `已完成`，另有 `等候中`（卡住了）和 `已放弃`。

**不是死板的流水线** —— 任何方向都能走，只禁止明显矛盾的（已完成不能直接跳到等候中）。

### 4. 排期是独立的

「做不做」和「什么时候做」是**两件事**。

一条事务可以同时是「进行中」**且**排在今天。`/today` 只显示排进今天和顺延过来的。

### 5. 排期 + 顺延

- 排到某天 → 那天出现在「今天视图」
- 到了那天还没做完 → **自动顺延到今天**，并给你一条合并摘要
- 不排期（`scheduled_for` 为空）→ 不进今天视图，但「全部未结束」里能看到

> 顺延机制是为了防止「今天」越积越长直到你不再打开它。

## 四、终端：命令全表

`/help` 是权威版本（永远与实现同步）。以下按用途分组。

### 看

| 命令 | 作用 |
|---|---|
| `/today` | 今天视图。先顺延，再排序，每条附信号理由 |
| `/weigh` | **代价对照**：两件以上的事**争同一天**时，把各自的代价摆出来供你拍板 —— 每项代价带**出处**（库里那列），**只摆事实不替你决定**、不排序不筛选；没有真取舍时如实说「没有需要拍板的取舍」，不会降格成「建议做 X」 |
| `/weigh <序号>` | **记下这一板**：把当时那组取舍与当时的代价对比**冻结**下来。7 天后自动拿出来，跟这几件事**现在的状态**并排摆给你看。**同一板重复拍只记一条**（连按两次不会在日志里留两条一模一样的记录）；换了选择、隔天再拍则各自留着 |
| `/decisions` | **决策日志**：今天到期的那些（当时那板 vs 现在）+ 拍过哪些板的索引。只摆事实 —— 不说「你选对了」也不说「你选错了」 |
| `/week` | **周回顾**：本周结束、卡在哪（顺延次数）、下周承诺、没排期、在等、成长目标（只摆事实）。V1.133 起再加三段：**本周拍板**（冲突 + 当时理由，逐字冻结）、**本周承诺**（仍未兑现）、**本周交给引擎的轮数**；Web 上在「更多 → 我的事 → 周回顾」，与命令同源 |
| `/feedback` | **四段留痕**：审批分账（含「没人看」）、执行层履历、没派出去的卡在哪、圈改差异 |
| `/model` | **连续性个人模型**：从记录现推的**结构化画像**（节奏：完成时段分布 + **「集中在哪」**（如「其中 13 次（56%）集中在 21-23 点」）/ 常顺延 / 卡住的等候 / 角色活跃度；关系账：跟谁还有未结清的账；承诺与目标：对外承诺 + 记忆里的约定/目标），只摆事实不评价 |
| `/pending` | **待处理收集器**：飞书收下的图片/文件；无参列出，`/pending N [标题]` 澄清成事务，`/pending drop N` 忽略 |
| `/capture` | **批量倾倒**：粘贴一大坨文本，空行结束，**按行切成多条**进待处理队列；`/pending` 澄清。只入队不建事务 |
| `/mail` | **邮件入口**：粘贴邮件正文，空行结束，**整段一条**进待处理队列（首行当标题，不按行切分）；`/pending` 澄清。只入队不建事务 |
| `/promise` | **对外承诺**：我答应别人的；无参列出，`/promise 记 <事务id> <承诺> [关系=名字] [期限=时间]` 记一笔，`/promise keep\|break\|withdraw <序号>` 落终态，`/promise postpone <序号> <日期>` 延期。**只显式记录，不自动推断；过了日期也不替你判违约** |
| `/contact` | **关系对象**：事务背后的人；无参列出（附「几条承诺未兑现」**与「几笔在等他」**），`/contact <名字> [备注]` 记一个 |
| `/nudge` | **催办草稿**：无参列出该催的事务（等候跟进日已过 / 承诺逾期），`/nudge <序号>` 出草稿。**只铺事实、正文留白 —— 系统没有发送能力，绝不代发**；出了草稿也**不代替你结账**（承诺仍挂账、不落记录），催过了自己用 `/followup` 或 `/promise keep` 销 |
| `/care` | **人生角色关注面**：给角色定义「该周期性关心的东西」（如 `/care 爸爸 孩子的作业和状态 每周六`），到点并进每日总览提醒；无参列出，`/care done <序号>` 记「看过了」推到下周期。**关注面不是待办，不因看完而消失** |
| `/all [open\|closed\|all]` | 全部事务。默认只列未结束 |
| `/roles [all]` | 角色脉络。默认只列活跃，`all` 含静置 |
| `/role <名字\|id>` | 某角色下的事务 |
| `/task <id>` | **恢复契约**（核心，见第三章） |
| `/plan <id>` | 单条事务的排期参考 + 命中信号 |
| `/llm` | 当前智能层与配置（**不显示 Key**） |

### 交互模式

对话式委派的第一刀：**先沟通、零副作用，再动手**。设计见 12.7.2。

| 命令 | 作用 |
|---|---|
| `/mode-plan` | 进入规划：之后说的话**只记进计划**，不建事务、不改文件，可多轮 |
| `/mode-build` | 退出规划并发确认卡（`ok` 确认 / `cancel` 先留着） |
| `/mode-build discard` | **不弄了**：计划丢掉、回正常模式，一条都不建 |

⚠️ **不叫 `/plan`** —— 那个名字已经是「按命中信号给排期参考」了。

⚠️ **进得去就得出得来**：进了 `/mode-plan` 又改主意，说 `/mode-build discard`。
它是唯一一条**不建任何东西**的出路 —— 而 `cancel` 的语义是「计划留着、继续
规划」，不是退出。Plan 状态是**落盘**的，所以关掉重开也逃不掉，必须显式丢弃。

确认卡上也有这三个选择（确认执行 / 再想想 / 不弄了），点哪个都一样。

### 记忆

让助手**记住你是谁**：稳定的偏好、你我之间说好的协作方式、以及「之前那么说，现在改了」。

| 命令 | 作用 |
|---|---|
| `/remember <内容>` | 记一条全局偏好（`/memory add 偏好 <内容>` 的快捷方式） |
| `/memory list [global\|角色]` | 列出记过什么（**全貌**）；没记过会说「还没记过」 |
| `/memory add <偏好\|约定\|修正\|目标> <内容>` | 记一条全局记忆（类别：偏好 / 约定 / 修正 / 目标；目标=前瞻自我期许，如「今年把英语练到能开会」） |
| `/memory add-role <角色> <类别> <内容>` | 记到某个角色名下 |
| `/memory search <关键词>` | 检索。**总会先说清是怎么找到的**，搜不到也明说「搜过，没找到」 |
| `/memory stats [天数]` | **哪些记忆好久没用了**（默认近 90 天）：逐条「被检索 N 次 · 被注入 M 次 · 最近哪天」，单列「近 N 天没用过的」。**只摆事实，不替你决定删不删** |
| `/memory review [天数]` | **该整理了**（默认近 90 天）：列出三组候选 ——「好久没动静」（窗口内没被检索/注入/确认过）、「内容相近」（整体字面像）与「只差一处」（首尾一样、中间岔开，改口最可能长这样）。三组**都只说像不说冲突**。**只摆不动，绝不自动删** |
| `/memory review confirm <id> [<id>...]` | 确认这条还留着：退出一个窗口的候选（确认不是永久静音，窗口过后仍没用过还会再摆出来）；删仍用 `/memory del` |
| `/memory edit <id> <新内容>` | 改内容（类别与范围不可改；改归属等于删掉重记） |
| `/memory del <id>` | 删掉这条 |

三条要知道的事：

1. **记忆不等于事实。** 它记的是「当时这么认为」，可能已过期。
   与当前真实状态（事务、配置）冲突时**以当前为准** —— 注入时也这么标注。
2. **可查、可改、可删。** 这是设计里的硬要求：删不掉的记忆等于不信任。
3. **记了不一定会被带上。** 会自动带记忆的地方目前有两个：**委派简报**——
   只带「约定」一类、最多三条、每条截到 120 字；**`/ask` 问执行器**（V1.97）——
   **按问题的相关度**带上你记下的全局记忆（V1.99：问 requests 时就带
   「禁用 requests」那条，而不是一律带最新的几条），并明说带了什么、
   怎么选的（「与这个问题相关的 N 条」/「最近的 N 条——相关度没命中」/
   「相关度检索不可用，按时间倒序取」），超预算时报「还有 M 条未带上，
   用 `/memory list` 看全部」。两处都带「可能过期」的定性。`/task` 看事务脉络
   **还不带**（设计文档 3.7.6 登记了这个注入点，未接线）。要让哪条记忆被用上，
   也可以直接 `/memory search <关键词>` 把它找出来。
4. **「用过」才算数（V1.98）。** 每次检索与注入都会留痕，`/memory stats`
   按条目告诉你它被检索 / 被注入过几次、最近一次是什么时候。
   一条「三个月前用过」会写「上次 哪天」—— **不会因为超出统计窗口
   就被说成「从未用过」**。如果留痕本身读不出来，它会明说「计数不可信」，
   而不是显示成 0 次。
5. **攒久了要整理，但只能你整理（V1.100 / V1.102）。** 记下来的东西只会
   变多，而常驻层要小才有效。`/memory review` 把候选摆到你眼前，三组：

   - **好久没动静** —— 一个窗口内没被检索 / 注入 / 确认过；
   - **内容相近** —— 整体字面像（一半以上的相邻字对相同），可能记重了；
   - **只差一处** —— 首尾几乎一样、中间岔开，例如「回复先给结论」与
     「回复先给细节」。这是**改口最可能长的样子**：旧版本还在，新版本
     又记了一条。

   三组都**只说像、不说冲突**：字面像可能是改口、也可能是两件并列的真事
   （「不喜欢早上开会」和「不喜欢晚上开会」都成立），分不出来，所以只把
   差在哪摆给你。**绝不自动删、绝不自动改写** —— 确认留着
   （`/memory review confirm <id>`）还是删掉（`/memory del`），你定。

6. **本地真找不到时，可以让它问一句外面（V1.105，默认关闭）。** 默认**不联网**
   —— 断网照常能用是本项目的硬性质，所以这条腿要你显式打开：

   ```bat
   REM Windows（一次性）
   set FREEAGENT_ONLINE_SEARCH_URL=https://你的检索服务/search?q={query}&format=json
   ```

   - **只在本地关键词一条都没命中时才发**；本地有命中就不出去（「排得不好」
     不等于「不够」）。检索本身坏了也不会出去 —— 那会把「本地坏了」显示成
     「本地没有」。
   - **会写明发到哪**：结果块第一行是「已发往 `<主机>`（查询原文离开了本机）」。
     查询离开本机是这次唯一真正的代价，你有权在结果旁边看到它。
   - **单列一块「外部材料，未核实」**，绝不和你的记忆混在一起 —— 前者是
     「网上有个人这么说」，后者是「你记过的」。
   - **不会自动喂给模型**：只摆到你眼前，`/ask` 不会因为开了这条腿就多读一段
     网上文字（那会让「确定/推理/猜想」那行档位说谎）。
   - 端点要返回 JSON，SearXNG 的 `format=json` 开箱即用（容器认
     `results`/`items` 之类，每条认 `title`/`url`/`snippet` 一族字段）。
     配错（比如模板里忘了 `{query}`）随时用 `/memory stats` 看一眼 ——
     那行会写「配置有问题」并说明原因。
   - **没开时 `/memory search` 一个字也不提它** —— 不是坏了，是没开。

### 委派（交给 opencode 改代码）

| 命令 | 作用 |
|---|---|
| `/delegate <项目绝对路径> \| <角色> \| <需求>` | 建一条委派事务 |
| `/redispatch <id> [原因]` | 让一条委派**可以重新派发** |
| `/brief <id>` | 看这条委派**实发的简报**（逐字）与它的协作象限 |

#### 从飞书发起：五步（不用敲命令）

在飞书里发「你好」拿到入口菜单卡，点**「让它改代码」**，然后依次点四段：

```
① 项目  →  ② 工作模式  →  ③ 模型  →  ④ 推理档位
```

四段点完，机器人发一张**第 5 步**提示卡，让你用**一句话**说清要做的事。
你发完，它回一张**确认卡**，上面写着项目 / 模型 / 工作模式 / 推理档位 /
脉络 / 你的原话，带三个按钮：

| 按钮 | 作用 |
|---|---|
| 建这条委派 | 建出委派事务（一条待办，执行器不碰它），回你 `/start <id>` |
| 改一下 | 丢掉这句，重新说一遍 |
| 先不做了 | 清掉这次选择，什么都不建 |

> **为什么第 5 步要单独一张卡**：四段选完之后，你说下一句话时机器人
> **已经知道**那是简报，不必再猜你是不是在提问。早先没有这一步，
> 「了解最新开发进度」这种句子会被当成「查某条事务的进展」，
> 于是回了「没找到你说的是哪一条」。

**三件要知道的事**：

- **简报必须单行**。含换行会被判成「复杂任务」，升级到主 agent 的
  强模型并**无视你选的模型**，于是必然失败（见下方故障排查）。
- **中途改主意**：任何 `/` 开头的命令都会清掉这次选择（手滑打了个 `/today`
   也算）。想重来就再点一次菜单里的「让它改代码」。
- **确认卡只对发起人有效**：群里别人点不动 —— 状态按**点击者**取，
  别人点了只会得到一句「已过期」。

#### 派之前先看一眼简报：`/brief <id>`

简报是执行器**唯一**收到的输入。以前你看不到它，只能猜「我是不是没说清」；
现在 `/brief <id>` 把那份原文打出来（逐字，与你按下 `/start` 后实发的
**是同一份**，只是按分号折行方便阅读）。

它会先在顶上告诉你这件事处在**哪个象限** —— 判据只有一条：**谁手里有
「这件事怎么做」的一手材料**。

| 象限 | 你给过做法？ | 机器跑过？ | 这句话的意思 |
|---|---|---|---|
| 讲授 | 有 | 没有 | 你的方案/约定已全文进简报，不必再补 |
| 共识 | 有 | 有 | 两类材料都在里面，不用再说 |
| 暗知 | 没有 | 有 | 里面只有机器记的执行账 —— 那是账，不是你的规矩 |
| 双盲 | 没有 | 没有 | 里面只有需求和验收标准，谁都没先例 |

所以它回答的是「**我还该补什么**」：

- 想出个方案 → `/draft <id> 要求`，然后 `/accept <id>`（只有**已采纳**的
  方案才进简报）；
- 想让它守规矩 → `/memory add 约定 <内容>`（例如「这个项目不用 npm」）；
- 直接派也行 —— 双盲象限本来就意味着「遇到取舍它只能自己定」。

> **象限不决定派不派**。它只是把「这次手里有什么」摊在明处；
> 该不该派、要不要先想清楚，还是你定。也**不要**指望它替你判对错 ——
> 它连「方案好不好」都不看，只看「有没有」。

脉络不单独问你：确认卡上按现有规则**预览**一条（通常是第一条），
点「建这条委派」后由 `/delegate` 那条唯一入口决定实际归属。
一条角色都没有时，它会直说「还没有任何脉络，先 `/role-add` 建一个」，
而不是硬发一条注定失败的命令。

**产出回来之后怎么验收**：

执行器跑完会把结果落成一份**草稿产物**，任务上写「执行器已产出结果，
待你验收」。三个界面都能验收（2026-10-17 补的，之前只有终端能点）：

| 界面 | 怎么验收 |
|---|---|
| 网页 | 打开那条事务 → 当前稿下面有**「验收这一版」** |
| 飞书 | 产出卡上点**「验收」** |
| 终端 | `/accept <id>` |

**不合意怎么办**：不要「标记为不合格」——**要改**。在网页或终端里开新版本
（`/draft <id>`），旧版会自动降为「已被取代」并保留可回看。一个被要求
改了三次的结果和一个一次通过的结果，在库里是**看得出来的**（见下面
`/feedback`），而这在 2026-10-17 之前是看不出来的。

真要判死产出，用 `/drop <id>` 把任务放下 —— 那是任务层的事。

**派出去之后失败了怎么办**：

- **执行期失败**（模型 402、opencode 崩了、网络抖了）—— 执行器下次扫到会**自动**重派
- **派发前就被拒**（项目不在白名单、没配飞书闸门）—— **不会自动重试**。
  原因是确定性的：配置没改之前重试多少次都是同一个结果，而实测过
  `--watch` 常驻 180 秒扫 60 轮、写 60 个产物版本，而真正的委派一条没干成

所以第二种情况要手动恢复，**先把配置改好**，再：

```text
> /redispatch <id>  白名单加好了
```

执行器是独立进程，所以这条**不会立刻跑**，要等你下次扫到。

**失败时它会告诉你「为什么」和「下一步」**（2026-10-28 补的）：

引擎失败时给的是**结构化**的（`type` / `status`），此前本仓只挖其中
一句人话，于是你看到的是「Free usage limit reached…」—— 一句**没有行动
指向**的话（订阅？换模型？等？改需求？）。现在失败摘要会给出**类别**与
**下一步**：

| 它说 | 意思 | 下一步 |
|---|---|---|
| 额度耗尽 | 免费额度用完了 | 等额度恢复，或换一个还没用完的模型 |
| 凭据问题 | API Key 无效 / 无权限 | 检查 Key 或登录状态 |
| 模型不可用 | 模型不存在或已下线 | 换一个当前可用的模型 |
| 上下文超限 | 这次需求太长 | 把需求拆小，或换上下文更大的模型 |
| 工具失败 | 工具执行出错 | 看工具输出，确认是环境问题还是需求做不到 |
| 上游故障 | 上游/网络抖动 | **只有这一类**重派有意义 |
| 看原始报错 | 认不出来的类型 | 看原始报错；反复出现就报给引擎维护方 |

三条要紧的：

- **除「上游故障」外一律不说「重试」**。配额错误重派一百次还是 429 ——
  **「允许重派」不等于「重派有用」**。
- **认不出来就说认不出来**，并把原话原样留着 —— 宁可给不出建议，也不给
  错建议（错建议会把人引到错方向，漏判只是没建议）。
- **它给的是「下一步」，不是「你该重派」**。决定权仍然在你。

#### 简报里带了什么（2026-10-28 补的）

委派不再让执行器像个新生儿 —— 简报里带的是**世界的事实**：

| 带的东西 | 从哪来 | 为什么 |
|---|---|---|
| **你已采纳的方案** | `/accept` 采纳过的那一版正文 | 规划线与委派线此前是断开的：你在 `/mode-plan` 里花时间定的方案，派发时被丢掉，执行器只拿到一句需求 |
| **同项目踩过的坑** | 同项目其它委派的历史失败（默认三条） | 上层存在的意义就是从下层结果里学到东西 |
| **上次跑到哪** | 上次用的模型、碰过的工具、错因 | 重派时不用从零问一遍 |
| **你记下的「约定」** | `/memory add 约定` 记的那类记忆 | 人定的规则，与机器踩的坑不同类，所以排在前面 |

**只带事实，不学你的倾向** —— 不从你的行为里推偏好、不调权重。
这一层积累的是「世界的事实」（客户不接受涨价、项目禁用某库），不是
「你的倾向」。

> 采纳一份执行器产出后，系统会**提示**你可以用 `/memory add 约定` 沉淀
> 下来 —— 但**只提示，不代记**。静默替你写一条约定，与静默挂关系账是
> 同一种越权。

三条会拒绝的情况各给一句不同的话，看它说哪句就知道该做什么：

| 它说 | 意思 | 该怎么办 |
|---|---|---|
| 正在跑，不能重派 | opencode 还在跑这条 | 等它跑完，或 `/pause <id>` 先移出来 |
| 已经做完了，重派没有意义 | 这条已成功 | 真要再做一遍，那是件新事，建条新事务 |
| 还没派出去过，不需要重派 | 它本来就在队列里 | 下次扫描就会派，不用管 |
| 不是委派事务 | 这条没有项目路径 | `/redispatch` 只对委派有用 |

委派是**唯一**一条终点在「本地执行代码」的能力，所以它比其它命令多两道闸门。

**动手之前先看一眼执行器**：`/agents` 是**只读探针**，回答五件事——
装没装、探到哪个主版本、能不能派、能力是哪三桶、**凭据从哪来**。它**不派发任何东西**
（设计文档 11.10.5：绝不自动触发委派）。

```text
> /agents
opencode：可以派发（主版本 1，接线已验证）
  可执行文件：有
  探到的主版本：1
  能力（read/write/approve）：read、write、approve
  凭据来源：登录态（`auth.json`） —— `~/.local/share/opencode/auth.json` 里有 3 个提供方（deepseek、opencode、openrouter），环境里也没有以 `_API_KEY` 结尾的变量。
```

**那一行凭据说的是「看到什么」，不是「能不能用」**（V1.109）。它只列
**提供方名**与**环境变量名**，从不打印密钥值。看清它说的是哪一件：

| 它说 | 意思 |
|---|---|
| 登录态 / 只有环境变量 / 两处都有 | 在**哪**看到了凭据。两处都有时本仓**不判断**哪个生效 —— 那是执行器的内部规则 |
| 两处都没看到 | 一次**观察**，不是断言（换版本后它可能把凭据放到别处）。要补就 `opencode auth login` |
| 认不出 | `auth.json` 在、但本仓读不懂。**别按「没登录」处理** —— 先去核对那个文件 |

> 派出去报 401 / 402 时先看这一行：**凭据没有**与**凭据有但没权限**是两件
> 完全不同的事，而它们报出来的字往往一样。

三种「不能派」各给**不同**的一句话，因为该做的事不同：

| 它说 | 意思 | 该怎么办 |
|---|---|---|
| 没装 | PATH 里找不到 `opencode` | 装好，跑 `opencode --version` 确认能起来 |
| **探不到版本** | 装了但 `--version` 输出解析不出主版本 | 本仓按「不知道在跟什么说话」处理，**不猜** |
| 不认识 / 认识但未验证 | 版本对不上，或接线没对着真机验过 | 前者升降级执行器，后者先实测适配器字段形状 |

> 「探不到版本」显示的是**探不到**，不是 `0` —— 后者会被当成「版本 0」
> 进入别的分支，然后说出一句关于版本 0 的莫名其妙的话。

### 批得怎么样、派得怎么样、改了什么：`/feedback`

`/feedback` 把四段留痕一起摆出来 —— **我批得怎么样、派得怎么样、哪些
委派卡住了、圈改时实际动了哪几行**。

```text
> /feedback
审批留痕（近 90 天共 23 条）
  允许 6　明确拒绝 3　叫停 1
  点了但已过期 2　没人看 11　还挂着 0
  ↑「没人看」不是拒绝 —— 卡放到过期，你根本没看见它。

  最近几条：
    10-27 22:05　拒绝　opencode 想 shell: rm -rf build　等了 0 秒
    10-27 21:48　没看　派到 openmos　等了 10 分钟
    10-26 18:02　允许　读目录 D:/x　等了 4 分钟

未结束事务 6 条 —— 其中派过的 5 条
  成功 2　执行期失败 3　派发前被拒 0　没派过 1
  成功率 40%（分母只算真跑过的：派发前被拒不算失败）

反复出现的错因（原样引用，不归类）：
  3 次　HTTP 402 余额不足

引擎错误的类别（按类别计次）：
  3 次　额度耗尽

产出验收：
  已验收　1 条
  圈改重做过（>=2 版）　1 条

没派出去的 2 条（各自卡在哪一步）：
  补测试 —— 正在跑（租约还剩 19 分钟）
  重构 —— 失联：派出后进程中断，租约已过期 —— 确认没有进程在改这个目录后 /redispatch，或 /drop
　够格待派 1 条 —— 执行器下一次扫到就会派；它没在跑就不会自己开始。

改版差异（圈改时实际动了什么）：
  写周报（9edc14f4）v1→v2：+2 行 / -1 行
    - 接口联调
    + 接口联调（含异常分支）
    + 压测

这些是事实，不是建议 —— 要不要重派、怎么改，由你决定。
```

几件事值得留意：

- **「没人看」被单独列出来了**（2026-10-27 起）。在那之前，一个「拒绝」
  里混着三种完全相反的事：你不同意、你叫停了整件事、以及**卡躺到过期
  你根本没看见**。三者落成同一列，于是「拒绝率」把「我没看见」也算进了
  「我不同意」—— 而前者该改的是**打扰方式**，后者该改的是**提议内容**。
- **「等了多久」是关键信息**。秒回 = 你正盯着；隔四小时 = 你回来才看见；
  躺满十分钟 = 根本没注意。同一个「允许」，这三种情况说明的事完全不同。
- **「改版差异」是唯一能看见「你改了什么」的地方**。审批卡上只有同意 /
  拒绝 / 叫停，没有「改一下」；真正的改动发生在圈改 —— 它永远存新版本、
  旧版不删，所以两版摆在一起就能算差。它只报增删行数和几行样本，
  **不解释你为什么这么改**。
- **「执行期失败」与「派发前被拒」分开算**。后者是确定性的（配置没改，
  重试多少次都一样），混进失败率会让人误以为自己「全失败了」。
- **成功率的分母只算真跑过的**。一次都没派过时它显示「没真跑过」，
  而不是 `0%` —— 后者是个指控。
- **「没派出去的」会说出卡在哪一步**（2026-10-27 起）。在那之前，委派的
  资格判定不满足就**静默跳过** —— 「我建了委派它怎么不动」的答案只在代码里。
  现在四种卡点各有各的话：`状态是 inbox`（还没 `/start`）、`正在跑`
  （附租约还剩多久）、`失联`（派出后进程没了，租约过期）、`派发前被拒`
  （带原文，确定性失败）。够格的不算卡住，只报一条计数 —— 但要留意那句
  话：**执行器没在跑，它就不会自己开始**。
- **错因有两段，是有意的**（2026-10-28 起）。上面那段是**原话**，按文本聚类，
  给你核对「引擎到底说了什么」；下面那段是**类别**，回答「哪一类在反复
  发生」。只有原话会看不出模式（同一个配额错误每次带不同的 URL 与时间戳，
  按整句聚类会聚成 N 条、每条计数都是 1，于是「这类错我犯过 5 次」这句话
  根本说不出来）；只有类别就没法自己核对。**两段并存，别删其中一段。**
- **「失联」不是失败，是没人续**。执行器是子进程，父进程死了它可能还在
  改文件，所以认领**只落一条失败账**、不自动重跑。确认没有进程在动那个
  目录之后，再 `/redispatch` 或 `/drop`。
- **它不给建议，也不会自动重派**。判断「该不该再派」是弱信号且不可复核
  （同 11.10.5），所以本仓只把事实摆出来，决定权在你。

> 这一节是 2026-10-17 补的。在那之前，失败记录**躺在库里没人读** ——
> 同一个错因栽三次，界面上不会有任何提示。
>
> 「审批留痕」与「改版差异」是 2026-10-27 补的。起因是一句听起来很对的
> 话：「每次处理都人工审核，审核过程就是不断积累，也就是具备自我学习
> 能力。」—— 积累的前提是**先记得准**，而当时连「他拒绝了」和「他没看见」
> 都分不开。这一节补的就是那个前提；至于要不要从审核记录里学出规则，
> 11.9.11 给了三条不做的理由。

### 你的画像：`/model`

`/model` 从你的记录里现推一份**结构化画像**，分三面：**节奏**（完成时段
分布、顺延、卡住的等候、角色活跃度）、**关系账**（还跟谁有未结清的账）、
**承诺与目标**（对外承诺 + 记下的约定/目标）。只摆事实，不评价。

**「集中在哪」（V1.101 起）**：时段分布下面多一句凝练，例如
「其中 13 次（56%）集中在 21-23 点」—— 原始的小时分布照旧全列在上面，
这句只是把「集中在哪」从「自己数」变成「直接说」，**每次都连计数与
占比一起出**，可反驳。

两件要知道的事：

1. **判不出时会说清为什么**。样本太少或太散（一段至少 3 次、且占全部
   完成的三分之一才算「集中」）时，它会写「没有达到『集中』的判定线」，
   而不是一声不响地跳过 —— 也别把它当成「没有规律」，上面那份原始
   分布就是全部事实。
2. **它是描述，不是建议**。「37 次里 13 次在 21-23 点」是事实陈述；
   它不会说「你总在深夜干活，建议调整」—— 要不要顺着调，是你的事。

### 只想问一句：用 `/ask`

`/ask` 把一句话交给执行器，把答复拿回来。它和 `/delegate` 的区别是
**「问一句」vs「把一件事做掉」**：

| | `/ask` | `/delegate` |
|---|---|---|
| 建事务 | **不建** | 建 |
| 落库 / 进今天视图 | **都不** | 都 |
| 产出草稿 / artifact | **不产出** | 产出 |
| 要不要 `/start` | **不要** | 要 |
| 项目白名单 | **不走** | 走（只接受绝对路径） |
| 逐次授权卡 | **不会来** | 会来 |

```text
> /ask 这个项目是干什么的？
（问的是这个目录：D:\PycharmProjects\freeagent）

它是个人事务助手的原型，核心脉络是角色多对多视图。

—— 凭据（说的是「查没查」，不是「对不对」）——
  确定 · 查过本机，可自己复核：README.md、docs/现状速读.md
```

**那句「凭据」是什么**（V1.104）：答复下面那一行告诉你，这段话是**读过
文件**说的，还是凭它已有的知识说的。三档：

| 档 | 它当时干了什么 |
|---|---|
| **确定** | 至少读过 / 找过**本机真实存在**的文件，清单给你，可以自己去看 |
| **推理** | 调过工具，但没有一个目标落在本机能核的位置（没带路径、用了通配模式、路径不存在） |
| **猜想** | 一次工具都没调用 —— 全靠它已有的知识 |

**「确定」不等于「对」**。它说的是**查没查**，不是结论对不对：读到了真
文件，也可能读错、也可能从对的文件推出错的结论。所以它只回答一件事 ——
**要不要自己去核**。要看结论对不对，仍然得看代码。

另一个边界：它判不出「哪一句话属于哪一档」。整段答复只有一个档 —— 一段
答复里「文件在哪」是查过的、「这么改行不行」是推的，两者标同一个档。
把整段一起读、一起疑，比给它贴一个精确的假标签好。

**问的是哪个目录**：当前工作目录，输出里会**明写出来** —— 不留隐藏状态，
免得你以为它问的是别处。

**它会带上你记下的记忆**（V1.97；V1.99 起按相关度选）：发送前把全局记忆
拼进问题前面，执行器不再对你的约定一无所知。**选法是按你的问题** ——
问 requests 时就带「禁用 requests」那条，而不是一律带最新几条；相关度
没命中就带最近的几条并明说「相关度没命中」；相关度那条路本身坏了也明说
「按时间倒序取」，不装作按相关度选的。带上时会明说带了几条、怎么选的；
记忆块自带「可能过期，以当前为准」的定性 —— 它记的是「当时这么认为」。
**一条都没记时不注入，也不打印**（你问的是问题，不是记忆状态）。

**「不问任何审批」的前提是「改不了」**：只读模式靠配置强制
（`edit`/`bash` 一律 `deny`），不靠执行器自觉。万一执行器仍然挂起一个授权请求，
FreeAgent 会**中止会话并如实报错**，告诉你「只读配置没生效，别急着放宽它」——
它**不会**替你点「允许」。

**它会停下来的两种情况**，都会说清停在哪，而不是默默截断：

| 它说 | 意思 |
|---|---|
| 用尽预算（默认 20 次工具调用） | 已中止，**没有**接着跑；已拿到的半截答复会给你 |
| 超过时长上限（默认 180 秒） | 同上 |

两种情况都**保留已拿到的部分** —— 半截答案也比一句「失败了」有用。

⚠️ **一个已知局限**：预算数的是名为 `tool` 的**事件条数**（设计文档 11.8.1 的
实测分布），**不解析载荷**。所以哪天 opencode 改了这个事件名，预算会
**静默地不再计数** —— 于是上限失效而没有任何报错。这条写在这里而不是藏起来。

**执行器的输出流没答完就断了**（服务崩了/ 连接断了）会**如实报错**，
不会给你一段半截文字外加「成功」。

**选执行器**：默认 `/ask` 走 opencode。`hermes` 前缀**已停用**（V1.83）：

```text
> /ask hermes 这个项目是干什么的？
hermes 执行器已停用（V1.83）。它的审批闸是「按模式标记」而非「每动作确认」，
拦不住未标记的文件/终端操作，不能当受控执行器。知识问答请用 /ask
（默认 opencode，FreeAgent 全控）。
```

- ⚠️ **hermes 执行器已停用（V1.83）**：它的审批闸是「按模式标记」而非「每动作
  确认」，`del` / 简单 `write_file` 到普通路径不在危险清单里，API 面与飞书面
  **都会直接执行而不弹审批**（`approvals.mode: manual` + 重启也拦不住）——做
  不了执行期逐次授权，FreeAgent 不再把它当执行器（适配器保留作接缝）。知识问答
  统一走 `/ask`（opencode）；要「危险动作先飞书确认」请走 `/delegate`
  （opencode，FreeAgent 全控）。你真想用 hermes，就用它的独立飞书 bot 聊天，
  但那不是 FreeAgent 的执行器。
- `opencode` 不需要写（它是默认）。「hermes」前缀已停用；`/ask hermes` 会报已
  停用并给出路。

**用法三步：**

```text
> /delegate D:/PycharmProjects/freeagent | 工作 | 给执行器补上 --model 参数
> /start <刚建的那条>
```

然后**另开一个终端**跑执行器 —— 它不在对话里自动跑：

```bat
REM 先看一眼会派什么，但什么都不执行
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.delegate --dry-run

REM 确认无误后真跑
python -m freeagent.delegate
```

**如果这条委派是从飞书发起的，结果会自己飞回那个会话** —— 执行器跑完会
主动推一条结果回去（含事务 id 和一段摘要）。三个细节：

- 推送**在本地落库之后**才做。飞书挂了不影响委派结果，本地才是权威。
- 推送失败**只记日志**，不会让执行器失败。
- 文案里会写明「事务仍是进行中，需要你自己验收」——
  **通知送到不等于事情做完了**，机器不替你判断。

从终端发起的委派没有这一步（终端本来就能看到结果）。

> **不想开终端？** Web 界面的「后台服务」页可以**直接启停**桥接与执行器
> （`POST /api/services/<key>/start`），网页上就能管这两个进程。也可以把
> 启动脚本放进 Windows 启动文件夹，登录后自启（见 [README](../README.md)
> 的「开机自动运行」）。
>
> **授权卡与提问在网页上也能批**（V1.35）：「委派总览」页（旧名「编程」，V1.146）最上面那块面板会
> 实时显示进度、每次动手要你批的授权卡（带 diff）、以及它反问你的问题。
> 网页与飞书是两套并行的操作界面、共用同一份库 —— 在哪边批都行（飞书
> 发起的那个例外，见[委派的实时交互](#委派的实时交互网页上就能看能批v135)）。

> **执行器和桥接读的是同一份凭据，不用互相迁就环境变量。**
> 凭据在 `~/.freeagent/feishu.env`（界面上填一次即可），两个进程各自
> `load_config()` 都能读到 —— 所以**开一个全新终端跑执行器，照样能把结果
> 推回飞书**，不需要 `set` 任何东西。
>
> 早先这里写着「必须在跑执行器的那个终端里也设一遍 `FEISHU_*`」。那是
> **凭据只走环境变量时代**的约束（环境变量按进程继承、不跨终端），凭据落到
> 文件之后就不成立了 —— 那条建议会让白费力气，还让人以为闭环不可靠。
>
> 真正会导致推不回去的只有一种：**执行器用了另一个 `STEWARD_HOME`**（旧名
> `FREEAGENT_HOME` 也算），于是读的是另一个目录下的 `feishu.env`（或压根没有）。读不到时执行器会
> **明确警告**（不静默跳过，否则你会以为闭环是通的）：
>
> ```text
> 这条委派来自飞书会话 oc_xxx，但本进程没读到 FEISHU_APP_ID/
> FEISHU_APP_SECRET，**结果没有推回飞书**（已照常落库）。
> ```
>
> 看到它就查 `STEWARD_HOME` 是不是和桥接那边一致（旧名 `FREEAGENT_HOME` 也认，但两个都设时以前者为准）。
> `FEISHU_*` 环境变量仍然可用，作为临时覆盖或应急手段。

**三道闸门，缺一不可：**

1. **项目白名单** —— 项目路径必须已写进 `config.json` 的 `delegate.projects`，
   且**只接受绝对路径**（相对路径的基准随工作目录变，是绕过白名单的常见手法）
2. **必须先 `/start`** —— 只有进行中的委派才会被派发。创建时一定是「未开始」
3. **不传 `--auto`** —— opencode 自己把这个开关标为 `dangerous!`。
   宁可它中途停下来问，也不要一个没人盯着的 agent 改代码

  **执行器是独立进程**，只从库里取已确认的委派，**不接受任何外部消息作为指令** —— 命令 / 任务 / 授权都只能经由它自己签发的凭据进入（它会接受对「它自己提出的问题」的文本答复）。闸门都在服务层的函数里，所以合并进程也绕不过；拆分给的是**纵深防御**，真正的好处是**交互中桥接重启不丢**。

**跑完不会自动标完成。** 结果会作为新一版草稿存进产物链（旧的永不覆写），
日志里留下完整痕迹；「做没做成」由你验收 —— 机器不该替你判断一件事到底完成没有。

**选哪个模型。** 实测结论（2026-09-27，opencode 1.18.31）：

| 模型 | 是否需要账户余额 | 能否用工具 |
|---|---|---|
| `opencode/big-pickle` | **不需要** | 能（实测读了文件、建了文件） |
| `opencode/space-bunny-free` | **不需要** | 能 |
| `opencode/gpt-5.4-nano` | 需要 | 余额不足直接 `402` |
| `opencode/deepseek-v4-flash` | 需要 | 余额不足直接 `402` |

默认推荐 **`opencode/big-pickle`**：不需要余额，且工具调用正常。
名字带 `-free` 的那批同样不需要余额。

```bat
python -m freeagent.delegate --model opencode/big-pickle
```

也可以写进 `config.json` 的 `delegate.model` 作为长期默认。

> ⚠️ **实测出的两条硬限制**（2026-09-27）：
>
> **1. 简报里只要有一个换行符，委派就会失败。**
> 提示中含 `\n` 时，opencode 判定为「复杂任务」，升级到主 agent 的强模型
> 并**无视 `--model`**；余额不足即 `402`。所以委派简报被刻意压成**单行**
> （用「；」连接），不用 `#`/`##`/`-` 那套 markdown 排版。
> 你在 `/delegate` 里写的需求、完成标准若带换行，也会被自动压平。
>
> **2. 需要写权限的任务会路由到唯一的 primary agent。**
> 只读、问答类任务 `--model` 生效；**新建/修改文件**这类走 primary agent。
> 要让它用上免费模型，得把那个 agent 的模型也换成免费的。
>
> | 简报形态 | 实际模型 | 结果 |
> |---|---|---|
> | 单行 · 纯需求 | `--model` 指定的 | ✅ 建出文件 |
> | 单行 · 带上下文 | `--model` 指定的 | ✅ |
> | **任何含换行的简报** | primary agent 的模型 | ❌ 402 |
>
> 一句话：**简报必须单行。** 这是实测出来的，不是风格偏好。

### 角色与归属

| 命令 | 作用 |
|---|---|
| `/move <id> <角色>` | 只挂到目标角色 |
| `/unrole <id> <角色>` | 摘掉一个角色标签 |
| `/role-add <名字> [备注]` | 新建或更新备注 |
| `/role-rename <名字> <新名字>` | 改名 |

| `/merge <源> <目标>` | 合并角色，**原子重定向，历史可回看** |

### 其它

| 命令 | 作用 |
|---|---|
| `/tick` | 手动检查提醒 |
| `/reset-data <确认口令>` | **恢复出厂**：清空全部事务数据（角色脉络、配置、Key 保留），执行前强制自动备份（`.bak-factory-<时间戳>`）。口令为 `我确定清空所有事务数据`。执行器或桥接在跑时拒绝。见下方专节 |
| `/menu` `/菜单` | **发一张入口菜单卡**（飞书通道）。「你好」「你能做什么」等也会自动回这张卡 —— 菜单先于派发逻辑判定，所以它不会把你误当成在派发 |
| `/help` `/quit` | 帮助 / 退出 |

### 三条通用规则

1. **`<id>` 都可以只输前几位**：`/task 6a68355` 等价于完整 id
2. **角色可以按名字或 id 前缀匹配**：`/role 家庭`、`/role 4551`
3. **日期能听懂中文**：`今天` `明天` `后天` `昨天` `下周二` `周五` `3天后` `2026-10-01`；
   时刻：`下午三点` `15:30` `晚上8点半`

### 助手现在会拒绝的两类输入

白话入口**问句直接答、事照记**，只有做不到的才明确拒绝并告诉你该用什么，
而不是硬建一条垃圾记录：

| 你说的 | 它怎么回 |
|---|---|
| 「把周报改到下周三」「删掉那条旧提醒」 | 要改已有的一条 → 让你用 `/today-pin` `/drop` |
| 追问时回一句完整的话 | 不是角色名 → 让你用 `/role-add` 或 `/skip` |

> **问句是答的，不是拒绝的。** 「今天该做什么」「我在等什么」「全部未结束的事」
> 这些直接给结果 —— 和 `/today` 等价，只是你不用敲命令。**终端和飞书里一样**
> （早先只有网页对话框能问，终端和飞书会把问句打发成「查看用命令：/today」，
> 已在 2026-09-29 修掉）。

> 没听懂你问的是哪一类时，它会**先按「今天」答、并明说这是猜的** ——
> 而不是装作听懂了。觉得不对就直接问「在等什么」「有什么提醒」。

> 早先的版本会把「周报进展怎么样」直接建成一个**角色**。角色是整个工具的组织结构，
> 被随口一句话污染之后很难清理，所以现在**角色只能显式创建**，助手不再替你猜。

### 恢复出厂（`/reset-data`）

**清空全部事务数据，角色脉络与全部配置保留。** 适合测试留了一地垃圾、
或想从零开始的时候。执行前**强制自动备份**，随时可还原。

```bash
# 1. 先停掉两个服务（它们在写同一个库，不停会被拒绝）
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='python.exe'\" | Select-Object ProcessId,CommandLine"
#     照着输出里的 freeagent.delegate / freeagent.feishu.bridge，taskkill /f /pid <pid>

# 2. 不带口令先看说明（不会执行任何东西）
python -m freeagent.cli.app   # 然后：/reset-data

# 3. 确认执行（口令逐字对上才动）
/reset-data 我确定清空所有事务数据
#    → 删除 counts + 备份路径 + 还原命令

# 4. 还原（如果反悔）
copy /y "agent.db.bak-factory-<时间戳>" "agent.db"
del "agent.db-wal" "agent.db-shm" 2>nul
```

**边界**：清的 = 事务/记录/产物/审批卡；留的 = 角色脉络、`config.json`
（含委派白名单）、`llm.env`、`feishu.env` 与飞书状态文件。网页端入口在
**设置 → 恢复出厂**（同一口令）。这个功能**刻意不做飞书命令** —— 飞书是
「谁能指挥你本机」的边界，一条消息抹库太危险。

## 五、对话（首屏）

打开就是对话框。它**只读你的数据、只新建事务，不改已有事务**。

没配模型 Key 时，对话流顶部会挂一条**规则层提示条**：说清能记事、排期、提醒，
角色判断和草稿是模板，并给「去配置模型」按钮直达设置页；页面头部状态栏也显示
当前智能层（规则层 / 已配 Key）。

### 能问

| 你说 | 它答 |
|---|---|
| 今天该做什么 / 我现在该先做哪件 | 今天视图，按信号排序，每条带理由 |
| 为什么这条排第一 | 列出命中的信号和权重，并说「可以反驳它」 |
| 周报进展怎么样 | 那条的恢复契约：意图、完成标准、进度、下一步、当前稿 |
| 我上周完成了什么 | 那个时间范围内结束的（本周的不算上周的） |
| 我在等什么 | 每件卡住的事 + 在等谁 + 跟进日过没过 |
| 有什么提醒 | 接下来到点的提醒 |
| 家庭那边有什么 | 该角色下未结束的事务 |
| 全部未结束 | 所有未结束的 |
| 你能做什么 | 能力清单 + 边界说明 |
| 你好 / 在吗 | 招呼 + 两条出路（说一件事帮你记下；问「今天」给清单）。措辞由模型在给定的事实内组织，不会补充事实之外的内容；模型不可用或纯规则层时回退固定模板 |

### 能接着问（多轮）

问完一屏之后可以**直接指代**，不用重复名字：

```
你：今天要做什么
    → 列出 7 条
你：第二个
    → 第二条的恢复契约
你：它为什么排第一
    → 那条的信号与权重
你：第一条呢
    → 同样能接上
```

指代方式：`第N个` / `第N条`（中文数字和阿拉伯数字都认）、`它` / `这条` / `那个`。

**对话历史会留在浏览器里** —— 切页签、刷新都不丢，右下角有「清空」。
快捷建议按钮只随最新一轮答复保留：发下一句时旧建议就撤下，刷新也不会把
上几轮的旧建议行插回消息中间。
所以你可以先问一屏，再点进详情看某一条，回来接着聊。

> 指代只在**有上文**时成立。没问过任何东西就说「它」，它会当你在胡说 ——
> 这是刻意的：没有上下文还硬指一句，等于答非所问。

### 用起来更顺手的几处（V1.132 / V1.133）

- **快捷建议点一下填进输入框**：答复下面那排场景按钮是「起个头」，点一下把
  建议原文填进输入框（还可以改），你确认完再按发送 —— 不会一点就发出去。
- **对话内搜索**：按 `Ctrl+F`（Mac 上 `Cmd+F`）或输入框旁的「搜索」按钮，
  在这段对话里搜关键词；命中会高亮，显示「第几 / 共几条」，`Enter` 跳下一条、
  `Shift+Enter` 跳上一条，`Esc` 关闭。清掉搜索后正文原样恢复。
- **第一次来不知道怎么开口**（V1.145）：对话页在**还没有任何消息**时会居中摆一块
  欢迎区 —— 一句招呼、一句它能做什么与不做什么，下面是「试试这样问」和一格一格的
  例子。点一下**只把例子填进输入框**，改不改由你 —— 不用先配模型也能玩（规则层
  离线就能答）。发出第一句后欢迎区自然让位；它没有「不再显示」，因为空对话本来就
  该给出路，刷新回来还是它。

### 能记

直接说一件事，它会推断形状、角色、日期：

```
下周二要交的销售周报初稿
等客户法务回复合同条款
提醒我下午三点修窗户
```

**归属不明确时它会反问**，而不是替你建一个新脉络。

### 不能做（会明确告诉你，并给出该用的命令）

| 你说 | 它答 |
|---|---|
| 把周报改到下周三 | 做不到 —— 改排期 `/today-pin <id> <日期>` |
| 把它标完成 | 做不到 —— 完成 `/done <id>` |
| 删掉那条旧提醒 | 做不到 —— 放弃 `/drop <id>` |
| 你能改它的状态吗 | 做不到 —— 改形状 `/kind <id> <shape>` |

> **这是刻意的边界，不是没做完。** 详情页上的状态按钮和「排期」可以直接点，
> 那些是确定性的改动。自然语言入口只负责**读**和**新建**——
> 一个会改数据的白话入口，出错时你不会知道它改了什么。
>
> 这条边界在**多轮下也不松**：先问一屏，再说「把它标完成」，照样拒绝。
> 有上下文之后用户很容易顺势就下命令，这里正是最该守住的地方。

### 拍照识物

输入框左侧有个 **＋** 按钮（V1.149），点开选「图片 / 拍照识物」。拍下产品铭牌，它会读出
**品牌 / 型号 / 规格**，然后给你两样东西：

- **一键跳转**：按型号去京东 / 淘宝 / 什么值得买搜一下
- **记一条**：直接建任务，标题和意图都填好

```
📷 拍照 → 读出「小米 空气净化器滤芯」
         品牌 小米｜型号 KJ-800-G｜规格 除PM2.5
         铭牌文字：型号 KJ-800-G
         [京东搜这个型号] [淘宝搜这个型号] [什么值得买]
         [记一条「小米空气净化器滤芯」]
```

**为什么不给「内置搜索」**：读铭牌是难点，搜商品不是。型号 `KJ-800-G`
复制到京东搜索框 3 秒就有结果，而**京东自己的搜索页比任何接口都好用** ——
你有登录态、优惠券、评价筛选、价格曲线。接口只能给字段。所以这里只给
**深链**，点一下跳到电商自己的搜索结果页。

零 API、零密钥、零资质，顺带保住这个工具「本地、断网可用」的属性。

**图片不落盘。** 铭牌照片里可能有地址、门牌、工牌、手机号。图片只在内存里
待几十秒，识别完只剩文字 —— 不写进数据库、不写进临时文件、不进日志。

**没配 Key 时按钮会禁用**并说明原因，不会让你白等一次。拍照识别必须配
`DEEPSEEK_API_KEY`（视觉走 `deepseek-flash`，可在设置页单独改），
**其余功能不受影响**。

**识别不准时宁可说「没读出型号」也不编一个** —— 型号错了你会买到不适配的
滤芯，要等货到才发现。所以读不清会直接说看不清哪里（反光/模糊/角度），
能看出是物品但读不到型号会明确说「没读到型号」并且不给搜索按钮。
铭牌原文会一起显示，你可以自己核对。

| 项 | 值 |
|---|---|
| 支持格式 | JPEG / PNG / GIF / WebP（**按文件内容判断**，不看扩展名） |
| 单张上限 | 8 MB |

### 认不准就反问

说「周报进展」而你有三条都含「周报」时，它会列出今天排着的让你选，
**不会随便挑一条答**。答错对象比不答更糟。

### 界面上还有什么

首屏是**对话**。顶部一级入口是 **对话 / 工作台 / 今天 / 事务 / 更多**；
其余视图收进「更多」下拉，按三段分组：**我的事**（它记住了什么 / 已结束 / 角色 /
周回顾 / 画像 / 关系 / 承诺 / 待处理 / 催办）、**执行与通道**（编程 / 后台服务 /
飞书通道）、**系统**（设置）。

- 今天视图带顺延收口；角色视图能看静置和已合并；设置页改配置立即生效
  （Key 也一样，存进 `llm.env`，见第六章）。
- **它记住了什么（Harness，V1.143）**：一页看清「它为你累积了什么」，四块全是
  已有事实的回显，**这一页不改任何东西**：
  - **项目与规矩**：每个工作区一张卡（名字 / 目录 / 跑过几轮 / 备注），加一行
    规矩 —— 目录里的 `AGENTS.md` **在不在、多少行、多大、何时改过**。它**不解析
    内容**：规矩怎么解释是引擎的事，这里只告诉你「有没有、新不新」。文件超过
    8 KB 时行数写「没数完」并说明只读了前 8 KB，不会给你一个「前 8 KB 的行数」
    冒充总行数。
  - **记忆**：`共 N 条`。条数读满上限时写「至少 N 条」—— 编一个数比说「至少」更糟。
  - **事务与承诺**：未结束事务 / 未兑现承诺 / 待处理三个计数，**只是计数**，
    要动手去「今天」「承诺」「待处理」那三页。某一项读不出来时写「读不到」，
    **不会写成 0** —— 0 会被读成「你没有」。
  - **能力与设置**：能力库如实说「这个仓库还没有可反复调用的能力库（Skills）」，
    能力来自引擎、规矩来自项目里的 `AGENTS.md`；再往下是模型层、凭据三态
    （已配置 / 未配置（现在走规则层）/ 读不到）、授权档、数据目录。
  某个工作区的备注要改、授权档要换、记忆要删，都回它们原来那个入口 ——
  这一页是「看」，不是「管」。
- **关系 / 承诺 / 待处理 / 催办** 这四个页签，是下列命令在 Web 上的镜像
  （数据同源，在哪边操作另一边立刻同步）：
  - **关系**：联系人列表，点开看某个人名下一页账（「我欠他的」+「我在等他的」两笔并排）。对应 `/contact`。
  - **承诺**：我答应别人的未兑现承诺，每条可直接「兑现 / 破了 / 收回」结账。对应 `/promise`。
  - **待处理**：飞书收下的图片/文件排队等澄清，每条可一键「澄清成事务」。对应 `/pending`。
  - **催办**：该催的事务候选列表，点「起草」生成一份**只铺事实、正文留白**的草稿（可编辑、可复制，**系统不会替你发**）。对应 `/nudge`。

顶部是**新建事务**表单（必须选角色，不做推断）。点任意一条进**详情页**。

> 这些页签和终端命令是同一套能力的两张皮：在 Web 上结账一条承诺，终端
> `/promise` 列表里它立刻消失；反之亦然。不用记命令也能用。

### 详情页有什么

恢复契约全在一屏：意图、生效完成标准、当前稿（版本号 + 状态 + 全文）、
进度、最近记录、等候对象、**下一步建议**，以及**状态按钮**。

状态按钮只显示**服务端说合法的**那些 —— 不会出现点了没反应的按钮。

### 界面上的按钮，和命令怎么对上

一个动作有三套名字（界面标签 / 终端命令 / 接口动作）。对不上号很正常，这里给张表：

| 界面按钮 | 终端命令 | 接口动作 | 说明 |
|---|---|---|---|
| 开始做 | `/start <id>` | `start` | |
| 做完啦 | `/done <id>` | `done` | |
| 等会再做 | `/pause <id>` | `pause` | |
| 算了 | `/drop <id>` | `drop` | |
| **放一放** | `/wait <id> <等谁>` | `blocked` | **会追问在等什么** |
| 排进今天 | `/today-pin <id>` | `pin` | |
| 移出排期 | `/today-pin <id> off` | `unpin` | |

**「放一放」为什么要追问？** 因为「在等」必须说清等谁，否则「等候中」就是个黑洞状态：
你不知道该催谁，也不知道什么时候该放弃。界面上填了之后等同于 `/wait`，
而状态本身叫「等候中」（对应接口的 `blocked`）。

### 提醒

页面顶部会显示一条合并摘要（多个提醒合成一条，不逐条弹）。
超过 6 小时的会标成「已错过」。

**安静窗口**：在 `config.json` 顶层加 `"quiet_hours": ["22:00", "08:00"]`
（本地时间、起止、可跨天）后，这个区间内到点的提醒**不推送**，
窗口一结束由下一轮自动补推，并会说明「因安静窗口推迟」。
不配 = 不启用（默认全天都推）。它**只改推送时机**，不改变「已错过」的判定。

### 设置页能改什么，不能改什么

设置项**按用途分了三段**（V1.132）：智能层与模型 / 运行与降级 / 排序偏好。
分组只是把同一类东西摆在一起，字段和保存方式都没变。

| 能改（存进 `config.json`，立即生效） | 不能改 |
|---|---|
| 服务商（provider） | 是否启用智能层（由 `FREEAGENT_RULES_ONLY` 决定） |
| 模型名 | 委派的项目白名单（那是**安全边界**，只能在 `config.json` 里手改） |
| 接口地址 | |
| 超时秒数 | |
| 允许降级开关 | |
| 精力档位（三档区间，或整体关掉） | |
| **API Key**（存进 `llm.env`，不是 `config.json`） | |

### 支持哪些 LLM

只支持 **OpenAI 兼容**的那几家：DeepSeek、Kimi（月之暗面）、通义千问（DashScope
兼容模式）、OpenAI、**Ollama（本机，不联网、不需要 Key）**、以及「其它兼容服务」
（vLLM / LM Studio / one-api 这类，地址和模型自己填）。

**Claude 和 Gemini 还不行。** 它们不是 OpenAI 兼容形状：鉴权头、请求体、响应都
不同，有的还不支持 `response_format`。硬接的后果**不是报错，是悄悄变差** ——
分类、草稿、拆步骤这几件事都要靠模型稳定输出 JSON，兼容性差的实现会让助手
「老是反问你」，而日志里看不出异常。要接它们得先改协议，不是改一行地址。

用 **Ollama** 的额外好处是**事务内容不出本机**：不填 Key 也能用。

### 关于 API Key

**Key 可以在设置页填**，写进 `~/.freeagent/llm.env`（和 `config.json` 同目录，
但**不是同一个文件**）。`config.json` 里**永远不会有它** —— `Config` 压根没有
`api_key` 字段，它是个现读的 property，所以这条是**靠类型防住的**，不是靠约定。

界面上：

- 输入框**每次加载都是空的**（明文不可能回显），已配的会用**掩码**做占位提示；
- **留空 = 不改**，不是清空。想清空要勾「清空已存的 Key」——
  否则你只改个模型顺手点保存，Key 就被抹了，而且要等下次启动才发现；
- 所有服务商的 Key **共存于同一个 `llm.env`**，来回切不会丢；
- 界面上会显示**当前生效的是哪一份**。如果环境变量压住了文件里的那份，
  它会明确提示你「在这里重填不会生效」——那种情况下你重填多少次都没用。

**环境变量仍然优先于文件。** 临时想换一家做对比测试可以直接
`set MOONSHOT_API_KEY=sk-...`，跑完就消失，不用去改文件。

也可以完全用环境变量（适合脚本化）：

```bat
set DEEPSEEK_API_KEY=sk-...
python -m freeagent.web
```

设置页第一屏就会告诉你 Key 现在有没有配、来自哪；对话首屏顶部也能看到规则层
状态和直达设置的入口。没配的话，助手跑在**规则层**：
建事务、排期、提醒、恢复契约全都正常，只是角色推断退化成关键词匹配，
草稿和拆步骤基本是模板。

**「测试连通」会真发一次请求**（1 个 token，很便宜但不是零），
所以它能验证「Key + 地址 + 模型名」这一整套对不对，而不只是「地址通不通」。
「拉取模型列表」打的是 `GET /models`，一家家的模型目录都能列出来。

### 一个容易踩的坑

如果你启动时设了 `DEEPSEEK_MODEL` 之类的环境变量，**它会盖掉设置页里的值**。
这时设置页顶部会明确警告「改了不生效」。想去掉覆盖，就去掉那个环境变量。

### Web 做不到的

| 操作 | 只能去终端 |
|---|---|
| 改角色归属（`/move` `/unrole`） | ✔ |
| 改完成标准（`/dod` `/role-dod`） | ✔ |
| 改形状（`/kind` `/wait`） | ✔ |
| 草稿相关（`/draft` `/revise` `/accept`） | ✔ |
| 角色管理（改名/静置/合并/删除） | ✔ |
| 拆步骤（`/steps`） | ✔ |

> **原因**：状态迁移、草稿、角色合并这些操作需要额外输入和反馈（要说明在等什么、
> 要看到版本差异），终端的交互更合适。Web 层刻意只做**白名单**内的操作，
> 越权的一律 404 —— 免得点出静默的错误。

### 委派的实时交互：网页上就能看、能批（V1.35）

**「委派总览」页（旧名「编程」，V1.146）最上面那块面板**是委派的实时窗口：进度、每次动手要你批的
授权卡、agent 反问你的问题、跑完的结果，都在那里。它与飞书是**两套并行的
操作界面**，共用同一份库——你在哪边批，另一边立刻就看到那张卡消失了。

```
① 建事务      → ② 点「开始做」   → ③ 执行器接手（另一个进程）
                                        ↓
                      网页面板实时轮询 / 飞书流式卡片
                                        ↓
              授权卡：动作 + 影响哪些路径 + diff + 三个按钮
              提问卡：它问什么，你就在面板里答什么
```

| 界面 | 间隔 | 怎么做到 |
|---|---|---|
| 网页面板 | 每 2 秒 | 前端定时读一次 `GET /api/delegate/live`（只读） |
| 飞书 | 打字机效果 | CardKit 2.0 流式卡片，由执行器直推 |

**三个按钮的语义**（与飞书卡一致）：

| 按钮 | 它做的事 | 它**不**做的事 |
|---|---|---|
| 允许 | 批**这一个动作** | 不覆盖下一个动作 —— 下一个还会再问 |
| 拒绝 | 否掉这一步 | agent 会换个方向继续 |
| **停止这条委派** | 中止**整个会话** | 已完成的那几步改动**仍然有效** |

> **「拒绝」和「停止」混起来最危险**：你以为已经停掉了，agent 还在改代码。
> 所以它们是两个不同的按钮，且「停止」一定同时做两件事（回掉当前这次挂起
> ＋ 记一条停止请求）—— 少任何一件的表现都是「点了没反应」。

**七件要知道的事**：

- **不点就算拒绝**，沉默不等于同意（超时自动降级为拒绝）。
- **没配执行器就没有进度**。执行器是独立进程（`python -m freeagent.delegate`），
  它不在跑时面板是空的——这不是界面坏了。
- **「疑似卡住」只标不改判**。超过 60 秒没动静就打这个标记，因为它可能只是
  这一步慢；要真停就去点「停止这条委派」。**任务已删却还挂着「(事务已不存在)」
  的进度行**（V1.134 起不再显示）：那是执行器被强杀留下的孤儿投影，秒数会一直
  涨但没有委派在真跑；数据仍在库里，只是不再摆到面板上，它的待批项照常显示。
- **飞书发起的委派，网页上看得见但批不了**。那些卡只由发起人批（安全边界，
  见下）。面板会把原因写出来并告诉你去哪儿批。
- **面板读不到时不会静默停**（V1.107）：连不上会按 5→10→30 秒重试；还不行就
  停，并在面板最上面写一句「不再自动重试」，同时说明**下面那张是最后一次读到
  的样子、可能已经过期**，旁边给一个「重试」按钮。切回这个页签也会立刻重读一次。
  **要批的卡不会因为读不到而消失**——它还在库里，飞书那边照样能批。
- **想关掉轮询**：设 `FREEAGENT_LIVE_POLL_SECONDS=0`。脚本化与低配机器上用。
- **哪个按钮真机点过、哪个没有，是有账的**（V1.108）：审批链每一格（允许 /
  拒绝 / 停止 / 答提问 / 超时 / 谁有资格点）记在 `docs/真机验收矩阵.md`。
  **空框就是没点过** —— 不是「应该没问题」。那些格子里写着怎么验、以及为什么
  旁边那格验过不能替它作数。第一次真跑委派时先看一眼那个「停止」格子：
  它长期是空的，而它正是中止整个会话的那个开关。

> **为什么只有没配飞书的那些才能在网页上批？**
> 「只有发起人能批」是条硬规则。飞书发起的委派带着发起人身份（`ou_…`），
> 而网页这边**没有飞书身份可出示**——放行等于用空身份替那个人点头。
> 网页/终端发起的委派没有身份声明，本机控制台即权威，所以可以批。

### 工作台：网页上直接让 OpenCode 干活（V1.114）

**一句话**：打开 <http://127.0.0.1:8770/> → 点顶部「工作台」→ 选项目、选模型
→ 说一句话。**不需要**再敲 `/delegate`、也不需要去终端起服务。

**一句话起手（V1.141）**：不想一步步选，就在正文顶部「一句话起手」的输入框里
直接写一句，比如「让它改 Alpha 把登录页按钮改成蓝色」，点「识别」。它会用你
已配的模型认出项目与要做的事，把「项目 / 目录 / 那句话」预先填好 —— 你**看一眼
再点「交给它」**，不会自动开跑。拿不准时它会追问（「要改哪个项目？」「具体要
做什么？」），你在追问框里回一句即可，这一句不当成新请求、也不再花模型的钱。
认不出的项目名一律不预填。**V1.147 起**：这张卡挂出来就先只读检查前提 —— 没授权项目或没连模型时，输入框与「识别」按钮是禁用的，卡上直接写原因并给「去授权项目 / 去设置」入口；配好前提后刷新页面即可用。视觉层（拍照识物）在设置页存完 Key 后立即生效，不再需要重启（V1.147 修）。

#### 怎么用（四步）

1. **项目**：点顶部「项目：未选择」展开下拉。已有项目按最近使用平铺，可按名字
     或路径搜索。三个动作：
   - **不使用项目**：这一轮只接问答 / 记事，不交引擎写文件；
   - **新建项目**：填项目名（留空取目录末段）、备注，再点「浏览选目录」在二级
     面板里选定文件夹；
   - **选择本地文件夹**：直接打开浏览面板，选定即建档（名取末段、备注空）。
   浏览面板是一行行文件夹列表：点一行进入下一层，底部「选用此目录」选定当前层；
   顶部有最近用过的目录、面包屑（点任意层跳回）、家目录 / 桌面 / 下载 / 文档快捷
   入口与盘符入口；路径框可直接粘贴绝对路径、回车跳转；当前层可按名字过滤。
   符号链接与 Windows 遗留 junction 不列，点开头的隐藏目录排在普通目录后面。
   这些只是浏览起点，选中后仍过同一道目录校验。目录不是绝对路径、或不存在，会
   **当场拦下**并说明原因。项目档案存在数据库里，下次打开还在；删项目只删档案，
   磁盘目录与历史轮次都不动。目录选择**不会**被继承到别的目录 —— 换目录等于换
   一份授权。

   选完之后工作区会**留在左边**（V1.139）：左栏是常驻的工作区列表，每行写着
   「跑过几轮 · 目录」，点一行就切过去；上面的搜索框按名字 / 路径筛。列表下方
   的「这个工作区累积了什么」摆四行 —— 备注（点「改」就地改，下一轮会作为背景
   带上）、跑过几轮（「轮次读不到」与「还没跑过」是两句话）、这一轮会不会带上
   今天的记录、规则从哪来。四行都是已有事实的回显，这里没有第二个开关。

   右栏（V1.142）分上下两块：上块是**这一轮的产物**（碰过的文件 / 跑过的命令 /
   它给的答复，每轮重画）；下块是**这个工作区里有什么** —— 只列一层，只读名字与
   大小、不打开内容，目录行能「进去」、文件行能「定位」到系统文件管理器。根就是这个
   工作区的目录，没有手输路径的地方，`../` 与绝对路径一律被拒；超过 300 条会写
   「只显示前 300 条」并给出总数，跳过的符号链接也会如实说一句。

   **安静模式（V1.142）**：点顶部那枚「安静」，顶部配置表单、左栏工作区、右栏产物
   会一起收起来，只留正文和输入框；顶上出现窄条写着「安静模式 · 当前工作区」，点
   「退出（Esc）」或直接按 Esc 就出来。开关记在本机浏览器里，下次打开还是安静的。
   要换项目、改授权档，先退出安静模式。
2. **模型**：点「载入清单」从引擎里读可选模型（读不出来就手填，或留空
   用引擎默认）。
3. **授权档**：
   - **逐次授权（默认）**：改文件、跑命令都会弹一张卡，你点「允许这一次」
     或「拒绝」；也可以点「**本会话内允许此类**」—— 本轮里同一种动作（比如
     又一次改文件）就不再弹卡，换一种动作、换一轮、换目录仍会问，没有「永远允许」。
     实时事件万一漏掉，工作台会定时再捞一次还挂着的授权卡；
     认不出的请求不会替你放行。
   - **本目录内自动**：在你选的那个目录里，写文件与跑 shell **不再逐次问**。
     越界访问别的目录、起子代理、联网检索**仍然被拦**。
4. **说一句话**：点「交给它」，或在输入框按回车（Shift+回车才换行）。
   它会先判一句「这话要不要动手」——
   - 判要动手 → 直接开跑，正文流式出现在下面；
   - 判不用动手 → 只写理由（不花引擎的额度），旁边有「仍交给引擎执行」可按。
   引擎抛出提问时，提问框里回车即答复。

运行中那张状态行会写清 **「引擎在跑…」还是「在等你回答」** —— 两者长得
很像，但后者说明它停下来了、在等你点卡。要中止就点「停止」。

界面上还有一句恒显的说明：**它在后台自己跑** —— 关掉这一页不会停，回来还看得到
这一轮的进度；要它马上停按「停止」；连服务一起停，就关掉那个命令行窗口。

#### 三条你会想知道的事

- **引擎是常驻的，但不是随网页启动**：没在工作台里跑过，就不会起任何进程。
  起过之后它会留在后台，**关掉 FreeAgent 时会一起收掉**（它在你项目里写的
  那份 `opencode.jsonc` 也会一并还原）。
- **「停止」停的是这一轮，不是进程**：进程还在（关掉网页它也还在跑，状态行
  只写「就绪 / 在跑」，不再列内部 id），那是设计 —— 下次说话不用重起几秒。
- **自动档仍弹了卡 = 覆盖层没生效**：界面会留一条备注。这时**不要**当成
  「它多问一次没关系」——它说明你的「自动」其实没被引擎采纳，按提示换回
  逐次授权更安全。
- **模型调不通 / 引擎当场失败会立刻收口**：这一轮还没跑工具就失败（模型
  不可路由、接口报错等），状态行直接记「失败」并摆出引擎给的原因，不会一直
  「在跑」等到超时；运行中点「停止」也会当场收这一轮。

#### 它和「委派」的区别

| | 工作台 | 委派（`/delegate` + `/start`） |
|---|---|---|
| 授权卡 | 不落库，直接在事件流里摆出来、当场答复 | 落 `pending_approvals`，执行器轮询那个库 |
| 谁判断要不要做 | **FreeAgent 的规则**（可一票推翻） | 你自己（先建事务再派） |
| 产物 | 会话里的对话与改动 | 事务 + 验收（`/feedback`） |

两者并存，**不是替换**。要留验收记录的活，仍然走委派；随手一句「改一下这个
文件」，用工作台更快。

#### 最近的活：关掉网页也找得回来（V1.115）

说过的每一轮都会**记下来**（存在 `agent.db` 的 `workbench_turns` 表里）。
页签底部是「最近的活」列表：时间、哪句话、跑在哪一步。**点一条就回到那一轮
看当时的输出**，顶部有「回到最新」按钮。

- 列表**不显示正文** —— 它只是「找回来」的入口，不是聊天记录。
- 看历史时轮询会暂停（否则一两秒后画面自己跳回最新那轮，看着像点不动）。
- **没记上会说**：如果某一轮没写进库（磁盘满了之类），那一轮会明写
  「这一轮没能落库 —— 关掉网页之后就看不到它了」。

#### 步骤清单：它在读哪个文件、改到哪了（V1.115）

引擎调用工具时，轮次卡里会长出一张**步骤清单**：

```
步骤（3）
1. read  D:/work/app.py  · 已执行
2. grep  attempt_state   · 已执行
3. edit  D:/work/app.py  · 进行中
```

- 三种状态：**进行中 / 已执行 / 出错**。同一个文件反复读不会刷出十几行
  （那是同一步的状态在推进）。
- 清单认的是工具的**形状**，与委派进度卡共用同一份识别 —— 两边不会对
  同一件事有两种说法。
- 一次工具调用的「开始 / 派发 / 完成」会合成同一步；失败或被叫停的步骤标
  出错。正常结束却没看到收尾的步骤仍显示进行中，不替它判完成。
- 清单收在一张卡内紧凑排列：当前正在跑的一步高亮，已执行的步骤弱化；步骤
  超过 8 条时早期步骤收起，点「展开全部 N 步」可看全部，再点「收起」折回。

#### 带上「家里的事」：它知道你忙什么（V1.115）

发送框下面有个勾选框，默认**勾着**：

> 带上项目备注、今天的事、未结清的承诺与相关记忆（会显示它带了什么）

勾着的时候，每轮会把「当前项目的备注 + 今天的活（最多 3 条）+ 未结清的承诺
（最多 2 条）+ 与你这句话相关的记忆（最多 3 条）」折成**一行**，跟在你的话
后面发给引擎。轮次卡上会写「背景：附带：项目备注 1 段、今天的活 3 条、承诺 2 条」，
让人知道**它看见了什么**。

- **只读**：不会顺延你的事、也不会往 `task_records` 留一条记录。
- **读不出来会说**：写成「没读到：今天的活（原因）」，**不会**糊成「今天没事」。
- 不想让它看见就**取消勾选** —— 这一轮只带你那句话（会明写「你关掉了
  上下文注入」）。
- 记忆是按**这句话**去检索的（相关度），不是「最近记的三条」。

#### 它碰过哪些文件、跑了哪些命令（V1.116）

一轮结束（或正在跑）时，轮次卡里会多出两块：

```
碰过的文件（2）
D:/work/app.py
D:/work/tests/test_app.py

它跑过的命令（1）
$ pytest -q
```

- **命令这一列是给你看的安全账**。选「本目录内自动」时，跑命令**不会弹卡**、
  也不会进任何审批表 —— 所以每一条命令的原文都会列在这里。**如果不在这里
  看见它，就没有第二处能看见**。
- 「碰过的文件」只算**改内容**的工具（读文件不算），同一个文件被改三次只列
  一行；它**认不出目标时宁可不列**，也不列一行空的（空一行会被读成「它动了
  一个我不知道的文件」）。
- 失败或被「停止」之后，底部有一个「照这句话再来一次」：点它只把原话
  **填回输入框**，**不会**顺手重发 —— 重发是花钱的动作，而且有些失败正是
  「再跑一遍会重复做同一件事」。

**关于自动档的一句话**：授权档旁边写着「换档只对**下一轮**生效」—— 已经跑
起来的那一轮仍按开始时那一档走。刚切换完没看到它回来问你，不是没生效，
而是这一轮已经按老规则在跑。

#### 产物侧栏与简洁模式（V1.132）

工作台现在是**左右两栏**：左边还是步骤、状态与最新的活，右边多了一条固定的
**产物栏**，把这一轮「碰过的文件 / 跑过的命令 / 答复正文」并排摆出来 —— 不用
再滚上滚下地在步骤之间找它改了哪个文件、回了什么话。窄屏（手机或把窗口拉窄）
时两栏自动叠成一列。没有轮次时产物栏会写「这一轮还没有产物」，不会留一块空。

导航条右侧多了个「**简洁**」按钮：

- 默认**开**，只把工作台里**过程性**的东西收起来（步骤清单、命令 / 文件足迹
  卡），步骤头的「步骤（N）」仍留着 —— 是折叠，不是删掉信息；
- 点一下切到「详细」，过程全部展开；再点切回来。偏好记在本机浏览器里，下次
  打开还是你上次选的样子；
- 它**只管呈现**，不改引擎怎么跑、不改授权，也不影响别的页面。

#### 把产物交出去：复制与导出（V1.133）

- 工作台产物栏的「答复」下面有「**复制答复**」「**导出 .md**」两个按钮：
  复制走浏览器剪贴板，导出存成一个 Markdown 文件（文件名是 `freeagent-答复.md`）。
  没有剪贴板接口、或复制失败，会明说而不是静默什么都不做。
- 事务详情页里**任何一版草稿**（包括已采纳的）都多了「复制这一版 / 导出 .md」：
  导出文件名用事务标题（非法字符自动换成下划线）。这些都是**浏览器本地动作**，
  不经过服务端、不发任何请求 —— 你的产物不会被上传到哪里。
- 这一刀补的是「产物只在库里、看得见拿不走」：以前只能去终端复制，现在在网页上
  就能把它交出去。

#### 这一轮用了多少（V1.133）

工作台的状态行在「用时 / 工具次数」后面会补一段「**Token 输入 N / 输出 M**」：
它读的是引擎会话的用量，每 15 秒才重新取一次（避免一直刷新页面把接口打爆），
换一轮会立刻重取。**读不出来会写「Token 读不到：原因」，绝不会显示「用了 0」**
—— 读不到跟没用是两回事。引擎那边的 token 统计形状尚未在真机核实，所以这一行
只作参考，不当账本对。

#### 改了什么，与在文件管理器里定位（V1.135）

- 工作台产物栏多了「**变更（本会话）**」一段：它读的是引擎会话记下的
  **改动账**（每个文件被写了几次），不是从答复文字里猜的。读不出来会写
  「读不到改动账：原因」，并提醒你「别把『没记录』当成『没改』」；账里
  **没有记录**会写「这不等于没做事」。账里只有路径和次数、没有逐行差异时，
  会**如实说明**，不会编一段 diff 给你看。和 Token 一样每 15 秒才重取一次，
  换一轮立刻重取。
- 产物栏的**文件行**、以及「变更」里的**文件行**，末尾都有「**定位**」按钮：
  点一下会在**系统文件管理器**里选中 / 打开那个文件（Windows 资源管理器、
  macOS Finder，其他系统打开所在文件夹）。它只在本机**当前工作目录内**生效 ——
  路径不在目录里会被拒绝并说清原因，不会拿一个路径去起系统命令。定位失败也会
  明说，不会静默什么都不做。

### 飞书接入（可选）

飞书是**又一个入口**，不是又一个引擎：消息经 `ChannelService` 转进终端那一套
派发逻辑（把 `Repl` 的输出换成缓冲区）。所以**命令语义与终端完全一致**，
不会哪天两边分叉。

> **在飞书里可以直接问，不必打斜杠命令。** 「今天该做什么」「我在等什么」
> 「全部未结束的事」这类问句会**直接给结果**，说人话记事情也照常。
> 其中「今天」「全部」也各有等价命令（`/today`、`/all`）——
> 但「在等什么」只有白话说法，**没有**对应命令。
>
> 早先这里有个真 bug：问句在网页对话框能正常答，**但终端和飞书会把问句
> 打发成「查看用命令：/today」** —— 而 `/today` 就写在下一行。根因是那两路
> 自己写了一份「问句一律拒绝」的判流逻辑，与网页那份分叉。已修（2026-09-29），
> 并写进设计文档 12.1.1 作为硬约束：一份能力一份实现。

核心包**零依赖不受影响** —— 只有飞书通道需要 SDK：

```bat
pip install ".[feishu]"
```

#### 1. 飞书控制台要开的东西

| 位置 | 做什么 |
|---|---|
| 应用能力 | 开启**机器人** |
| 权限管理 | 至少开 `im:message`、`im:message:send_as_bot` |
| 事件订阅 | 订阅 `im.message.receive_v1`；订阅方式选**「使用长连接接收事件」**（**不是** Webhook） |
| 版本管理与发布 | 创建版本并**发布**（自建应用通常还需管理员审批） |

选长连接的好处：**不需要公网 IP、不需要内网穿透**。这条通道是从本机往外连的。

#### 2. 配环境变量

```bat
set FEISHU_APP_ID=cli_xxx
set FEISHU_APP_SECRET=xxx
REM 白名单：只有这些 open_id 能指挥本机。**留空 = 谁都不许**（启动直接报错退出）
set FEISHU_ALLOWED_USERS=ou_xxx
REM 国际版 Lark 填 lark；默认 feishu
set FEISHU_DOMAIN=feishu
REM 提醒轮询秒数；0 = 不推提醒
set FEISHU_REMINDER_POLL_SECONDS=60
```

> App Secret **只从环境变量读**，和 `DEEPSEEK_API_KEY` 一个规矩。
> 它是**能冒充你的机器人收发消息**的凭据，比 DeepSeek Key 更敏感。
> `FeishuConfig` 的 `repr()` 会把它显示成 `***` —— 这样打日志不会顺手泄掉。

**`open_id` 怎么拿**：这是启用通道的**必经一步**——白名单为空时启动就会报错退出。

**办法一（省事）：让 bot 把码给你，用 `/pair` 核销**

1. 白名单**先随便填一个占位值**把桥接跑起来（`FEISHU_ALLOWED_USERS=ou_placeholder`）
2. 在飞书里**私聊**你的机器人，发一句话
3. bot 会回一张**配对卡**，上面有一串配对码
4. 在**这台机器的终端**里敲 `/pair <那张卡上的码>`：

   ```text
   /pair 7KQF-2M9D-3XTP
   ```

5. 它会把你的 `open_id` 写进 `feishu.env`，**然后重启桥接**（白名单是启动时读的）

码 10 分钟内有效、**只能用一次**。复制时带了空格或换行没关系。

> 配对**不是**后门：白名单判定一个字都没动，配对只解决「怎么拿到 open_id」。
> 白名单为空仍然拒绝启动；配对码不执行任何命令，群里也不会发配对卡
> （群里发卡等于向全群确认「这里有个 bot」）。

**办法二（不想用配对就直接查日志）**

1. 用占位值把桥接跑起来
2. 在飞书里私聊机器人，发一句话
3. 看日志里这一行（`--verbose` 更详细）：

   ```text
   发送者 ou_9f8xxxxxxxxx 不在白名单（event_id=xxxx）
   ```

4. 把那个 `ou_...` 填进 `FEISHU_ALLOWED_USERS`，重启桥接

日志里只出现 `open_id`，**不会出现你发的消息正文**。

> 白名单填错时的表现是「bot 一句话都不回」，这行日志就是唯一的线索。
> 查不到的话把 `--verbose` 加上再试一次。

> ⚠️ 配对写的是 `feishu.env`，而**环境变量优先于文件**。若
> `FEISHU_ALLOWED_USERS` 也设了，配对会明确告诉你「这次写盘不生效」——
> 那种情况下要把新 id 也加到环境变量里，或者去掉那个环境变量。

#### 3. 跑起来

**推荐用交互式脚本** —— 它提示你粘贴 Secret，**不落文件、不进 shell 历史、
不经聊天工具**：

```bat
tools\run_feishu.bat
```

它会先跑一遍自检（含联网验凭据），确认没问题再起桥接。凭据错了会当场
说清原因并停下，而不是让你对着一堆静默重连发呆。

想手动设也行：

```bat
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.feishu.bridge
```

> **Secret 为什么要绕这一圈？** 32 位密钥里有 `I` / `l` / `1` / `!` 这类
> 肉眼几乎分不清的字符。靠人手转写经手一次就可能错一位，而**错一位的报错
> 是「app secret invalid」**——和真的失效完全一样，分不出是抄错还是过期。
> 让机器直接读 pasted 的原文，才彻底消除这一类错误。
>
> 顺带一提：`set "VAR=value & cmd"` 里 `&` 前的空格会被算进值里，
> 32 位会变成 33 位，接口报 `invalid param`。交互式脚本一并避开了。

它会一直阻塞在那儿（长连接有心跳和自动重连）。`Ctrl+C` 退出。

> **桥接和执行器是两个进程。** 桥接只负责「收消息 → 转命令 → 回话」；
> 真正去改代码的 `python -m freeagent.delegate` 要你**另开一个终端**跑。
> 这是刻意的：那条链路的终点是在你机器上执行代码，不该由一条聊天消息触发。
> 从飞书建了委派并 `/start` 之后，去终端跑一次执行器，结果会**自己飞回
> 那个飞书会话**（详见[委派](#委派交给-opencode-改代码)一节）。
>
> 想让提醒也能到飞书，两个进程都得开着 —— 提醒是轮询式的。

#### 4. 卡住了先跑 doctor

这套东西要配 App Secret、白名单、SDK，**每一处配错的表现都是
「bot 一句话都不回」**。所以配好之后、或者它不理你的时候，先跑自检：

```bat
python -m freeagent.feishu.doctor
```

输出逐项告诉你哪一环不对、**缺了会怎样**：

```text
飞书通道自检
==============================================
[OK  ] 飞书 SDK：已安装（1.7.3）
[OK  ] FEISHU_APP_ID：已设置（cli_xxx）
[OK  ] FEISHU_APP_SECRET：已设置（不显示内容）
[致命] FEISHU_ALLOWED_USERS：为空 —— 没有任何人能指挥本机，桥接会拒绝启动
[OK  ] FEISHU_DOMAIN：feishu → https://open.feishu.cn
[OK  ] 数据库：正常（schema v3，12 条事务）
[警告] bot 身份（open_id）：还没探到。**私聊不受影响，但群里 @ 它不会回**
       （门控失败关闭）。加 --live 联网探一次并缓存
[OK  ] 单实例锁：端口 8771 空闲（可以启动桥接）
==============================================
有 1 项致命问题，先修上面标「致命」的。
```

几点说明：

- **默认不联网**，只看本地配置 —— 「查一下配置填对没」不该有副作用。
- 想连凭据一起验（会发一次网络请求）加 `--live`。
- **不会打印 secret 内容**，只说「有没有」。这份输出可以放心贴给别人看。
- 退出码：有致命问题是 `1`，全过是 `0`。
- **`bot 身份` 是警告不是致命**：探不到身份只是群里不响应，私聊照常。
  标致命会让人以为整个通道都废了，反而不好定位。

最后两项是专门对付「**bot 突然不回应**」的，因为它们的表现和「权限坏了」
一模一样：

- **`bot 身份（open_id）`** —— 群里 @ 它到底认不认 bot 自己，靠的就是这个
  `open_id`，启动时自动探测（`GET /open-apis/bot/v3/info`）并缓存到
  `feishu_bot.json`。**探不到时群聊失败关闭**：群里带 @ 的消息一律不回。
  这是刻意的 —— 判不准的时候朝「关」偏。所以现象是「私聊能回、群里 @ 也不回」。
  `--live` 会联网探一次并缓存。⚠️ 群里如果**只 @ 了别人**，同样不响应，
  那是正常的：bot 不该抢答别人被 @ 的消息。日志里会写明是哪一种。
- **`单实例锁`** —— 同一个 `app_id` 上跑两个长连接，飞书只会把事件投给其中
  一个，另一个静默失效，现象就是「时好时坏」。默认锁 `8771`（**不是** Web 的
  8770，两个进程撞端口会互相误杀），`FEISHU_LOCK_PORT` 可改。端口被占时
  桥接会直接退出并说清「已有桥接在跑」。

#### 5. 三条安全边界

- **白名单失败关闭**：`FEISHU_ALLOWED_USERS` 为空时**启动就报错退出**，
  不存在「忘了配 = 所有人都能指挥本机」这种情况。这和
  `delegate.projects` 是同一个原则。
- **群里必须 @ bot 自己才响应**；@ 别人不抢答，判定靠 bot 自身 `open_id`
  （启动时自动探测并缓存）。探不到身份时群聊**失败关闭**（不响应），
  私聊不受影响 —— 判不准的时候朝「关」偏。
- **不传 `--auto`**：委派到 opencode 时永远不带这个开关，它自己标了 `dangerous!`。
- **同一台机器只跑一个桥接**：默认锁 `8771` 端口，第二个会直接退出。
  两个长连接里飞书只把事件投给一个，另一个静默失效，现象是「时好时坏」。

#### 6. 提醒是**私聊推**给你的

`reminders.check()` 是**消费型**的：取走就不再重复。所以通道不会靠「用户发消息
顺带触发」——那会被一条无关消息把提醒吞掉。通道按 `FEISHU_REMINDER_POLL_SECONDS`
自己轮询，**推给每个白名单用户的私聊**（不推群：提醒是私事，落到工作群等于广播）。

#### 7. 已知的限制

- **只把文字当指令，但非文字消息「收下而非丢弃」**。图片/文件（带可下载附件）
  会**下载到状态目录 `attachments/`、落入「待处理收集器」，并回一句「已收下」**；
  富文本仍只回一句「我只处理文字」（带上实际收到的类型）。**都不建事务**：
  收集器里的东西等你显式 `/pending N` 才澄清成事务（`/pending` 列出，先进先出，
  最早收下的排最前；下载失败也照样入队 —— `media_key` 是重新下载的凭据）。
  澄清成的事务归「默认脉络」，回话里说清落在哪，要归位用 `/move <id> <角色>`。
  `/today` 在有待处理时会多一行「待处理 N 条」，0 条不占位。
  这条告知**只发给白名单内、且群里确实 @ 了 bot 的人**：
  - **白名单外不回** —— 回一句就等于向陌生人确认「这里有个 bot 在跑」，
    那正是白名单要挡的泄露面；
  - **群里没 @ bot 也不回** —— 否则群里谁随手发张图，bot 就抢着说
    「我只处理文字」，那比沉默更糟，等于把「不抢答」又破一次。
  所以「发了图片没反应」只可能是这两种情况之一：不在白名单里，或群里没 @ 它。
- **只认 `/` 开头的命令和普通句子**，与终端一致；不支持卡片按钮交互。
- **群里 @ bot 自己才响应**；@ 别人不抢答。bot 身份启动时自动探测并缓存到
  `feishu_bot.json`（7 天）；探不到时群聊**失败关闭**（群里带 @ 的一律不回），
  私聊不受影响。`doctor` 有一项专查，跑 `--live` 可联网探一次。
- 飞书重投事件会去重（同一 `event_id` 只处理一次），去重表**落盘**在
  `feishu_seen_events.json`（24 小时 / 2048 条），所以**重启后仍然记得** ——
  长连接重连会重投近期事件，这正是重复建事务的来源。文件坏了会改名
  `.corrupt` 留现场、以空表启动，不会因为一个坏文件起不来。

## 六、配置文件与环境变量

### 配置文件

位置：**和数据库同一目录**下的 `config.json`（默认 `~/.freeagent/`）。

```json
{
  "llm": {
    "model": "deepseek-chat",
    "base_url": "https://api.deepseek.com/v1",
    "timeout": 20,
    "allow_fallback": true
  },
  "energy_windows": {
    "morning":   [5, 12],
    "afternoon": [12, 18],
    "evening":   [18, 24]
  },
  "quiet_hours": ["22:00", "08:00"],
  "delegate": {
    "projects": ["D:/PycharmProjects/freeagent"],
    "browse_roots": ["D:/PycharmProjects"],
    "model": "opencode/big-pickle",
    "plugins": "inherit"
  }
}
```

全部可选。优先级：**内置默认 → 配置文件 → 环境变量**（后者覆盖前者）。

> ⚠️ **`config.json` 里写 `api_key` 仍然不生效** —— 这个文件是**非秘密**配置，
> 放 Key 会跟着数据库一起被备份、被复制。Key 写进**另一个**文件 `llm.env`
> （同目录），在设置页里填。
> 界面上的「设置」页改的就是 `config.json`，改完立即生效。

### 委派配置

| 键 | 作用 |
|---|---|
| `delegate.projects` | 允许委派到的项目目录，**只接受绝对路径**。**留空 = 关闭委派** |
| `delegate.browse_roots` | 「可授权根」：允许在委派面板里**浏览**的目录，**只接受绝对路径**。**留空 = 浏览关闭**（浏览只是选目录的入口，不等于授权） |
| `delegate.model` | 用哪个 opencode 模型。留空 = 用 opencode 自己的默认 |
| `delegate.plugins` | 委派实例**要不要加载你的 opencode 插件**。`inherit`（默认）或 `off` |

`delegate.projects` 是整个委派链路最硬的安全约束：链路的终点是
「在你的机器上执行代码」，所以能去哪些目录必须是**你预先批准的清单**，
不能由消息内容决定。默认留空 —— **不配就一条都派不出去**。

`delegate.browse_roots` 决定「界面能从哪些目录里挑项目」。面板从这些根
逐级点进去，选中目录再加进白名单；客户端只说「第几个根 + 根内相对路径」，
**绝对路径由服务端拼**并校验仍在根内（符号链接也不列出来），所以浏览接口
读不到你圈定范围之外的目录。**默认空 = 浏览关闭** —— 浏览是扩大选择面的
功能，按「默认朝关」处理；留空时你仍可以手改 `delegate.projects`。

这一段在 **WEB 的委派面板**里点按钮改（允许 / 撤销 / 从可授权根点选），
也可以手改 `config.json`。设置页不管委派：白名单不该混进「随手保存」的
设置表单里，它需要**一次一个明确的动作**。

#### `delegate.plugins`：要不要带上你的插件

委派跑的是**系统 opencode**，看得见你的真实配置，于是你装的插件、
它们注入的 MCP 与技能**都会进来**（本机实测有 5 个 MCP 服务器：
codegraph / context7 / grep_app / lsp / websearch）。

| 值 | 行为 | 代价 |
|---|---|---|
| `inherit`（默认） | 全部加载 | 插件代码在闸门内运行（`tool.execute.before/after` 钩子**不受 permission 管**）；agent 人格可能被插件换掉；每轮多约 2 万 input tokens |
| `off` | 加 `OPENCODE_PURE=1`：插件注入的 **MCP 服务器与工具全部消失**，agent 人格回到默认 | 你正在用的那些工具在委派里**用不了** |

实测（2026-10-14，opencode 1.18.35，同一条「只回复OK」的指令，只差这一个变量）：

| | `inherit` | `off` |
|---|---|---|
| `GET /mcp` | 5 个服务器 connected | **`{}`** |
| agent 人格 | `Sisyphus - ultraworker` | **`build`** |
| input tokens | 20805 | **7092** |
| 启动耗时 | ~4s | **1.3s** |

> ⚠️ 别把它读成「插件一个都不加载」—— 事件流里**仍会出现 `plugin.added`**（实测 45 条）。
> 真正消失、也确实能被观测到的是：MCP 服务器与工具、插件注入的 agent 人格、
> steering 的提示注入与那份 token 开销。

**默认为什么是 `inherit`**：改默认会**静默削掉你正在用的工具**，那是功能回退。
安全性不靠这个开关 —— 执行期闸门已经失败关闭（未登记的工具一律要人点头）。

**填错会报错**（只认这两个值）。这不是死板：`true` / `none` / `""` 都能被读成
布尔或空值，一旦静默当成「继承」，你会以为关了插件、实际插件全在，
而**界面上看不出任何异常**。

> ⚠️ **关插件 ≠ 关闸门**。这个开关调节的是「agent 能用什么」，不是
> 「用之前问不问」。两种模式下执行期逐次授权都照常开着。

### 进度卡片要额外开一个飞书权限

委派执行过程中会往飞书推一张**动态更新的进度卡**（CardKit 2.0 流式卡片）。
这个功能需要你的飞书应用额外开通 **`cardkit:card:write`** 权限：

```
https://open.feishu.cn/app/cli_a93bf64450b89cc9/auth?q=cardkit:card:write&op_from=openapi&token_type=tenant
```

**加完权限要重新发布应用版本才生效。**

没开权限时**委派照常跑完**（进度卡会自动跳过，只记一条日志），
所以「看不到进度卡」不影响功能，只是少了个观察窗口。日志里的失败长这样：

| 日志里的错误 | 含义 |
|---|---|
| `code=99991672` | 没开 `cardkit:card:write` → 去上面那个链接开通 + 重发版本 |
| `code=200830` | 卡片 JSON 结构不合法 → 是代码问题，反馈即可 |
| `code=300309` | 流式已关闭却还在更新 → 收尾顺序错了，是代码问题 |

### 有 Key 和没 Key 的区别

| 能力 | 有 Key | 没 Key |
|---|---|---|
| 建事务、分类形状、排期、提醒、恢复契约 | ✅ 完全一样 | ✅ 完全一样 |
| 角色自动推断 | ✅ 理解力强 | 关键词匹配，弱 |
| `/draft` 出草稿 | ✅ 有内容 | ⚠️ 只有模板 |
| `/steps` 拆步骤 | ✅ 具体 | ⚠️ 三步脚手架 |
| 标题收敛 | ✅ | ✅ |

**没 Key 也能用全部功能**，只是助手「没那么聪明」。

## 七、常见用法（照着做）

### 场景 1：从零开始

```
> /role-add 工作项目A 销售 周报 客户
> /role-add 家庭 孩子 学校 材料
> /role-add 个人创作 写作 灵感
> /role-dod 工作项目A 先给我能用的就行
> /roles
```

第三条的备注是**关键词**，直接影响自动推断准不准。

### 场景 2：记一件事

```
> 下周二要交的销售周报初稿，重点讲增长
```

助手会：推断出「动作」、归到 `工作项目A`、解析出「下周二」、收敛标题。
然后回你一行 id，接着：

```
> /draft <id>          起骨架
> /start <id>          开始做
> /note <id> 框架有了   随手记一笔
```

被打断了就 `/task <id>`，看完接着做。

### 场景 3：卡在别人身上

```
> /wait <id> 客户法务回复
> /followup <id> 3天后
```

三天后 `/today` 里这条会带着理由顶到最前面：「该催 客户法务 了」。

### 场景 4：改主意，放弃

```
> /drop <id>
```

不会消失，移到「已结束」里。

### 场景 5：角色越建越多

```
> /merge 跑腿杂项 个人事务
```

事务会**原子地**重指向新角色，原数据保留。合并后旧名字不再出现在列表里。

### 场景 6：定期回看

```
> /today              今天要动的
> /all closed         上周做完的
> /roles              脉络全景
```

## 八、故障排查

| 现象 | 原因与解法 |
|---|---|
| 界面上中文乱码 | 忘了 `set PYTHONIOENCODING=utf-8`（`run_web.bat` 已替你设好） |
| `ModuleNotFoundError: freeagent` | 忘了 `set PYTHONPATH=src`（`run_web.bat` 已替你设好）；或改用 `pip install -e .` 注册命令入口 |
| 提示找不到 `python` / `py`，或解释器低于 3.11 | 机器上没装 Python 3.11+，或命中了微软商店占位符。从 python.org 装好、把真解释器加进 PATH 再跑 |
| 设置页改了模型名但没效果 | 启动时设了同名环境变量，它优先。设置页顶部会警告；去掉那个环境变量 |
| 建事务被追问「这是放到哪个脉络里？」 | 该角色名和备注的词跟你的输入没交集。补 `/role-add <名字> 关键词`，或直接回一个角色名，或 `/skip` |
| 界面上建的事务「今天」里看不到 | 新建表单的**日期框**留空了。补上，或 `/today-pin <id>` |
| 没收到提醒 | 提醒是**轮询**的：终端每轮对话查一次，Web 每次加载查一次。**两个进程都关着就收不到** |
| 提示「已退回规则推断」 | 模型调不通（没网/Key 错/超时）。`/llm` 看当前状态；不想要降级就设 `FREEAGENT_ALLOW_FALLBACK=0` |
| `/draft` 全是 `[TODO]` | 你给的信息太少。补意图、来源、口径，它就不敢瞎写了 —— 这是**故意的** |
| `/role-del` 提示不能删 | 该角色下还有事务。先 `/merge` 或逐条 `/move` |
| Web 打不开 | 端口被占：`python -m freeagent.web --port 9000` |
| 委派面板顶上出现「不再自动重试」 | 服务连不上了（多半是它没起来或被重启）。点那句旁边的「重试」，或切走页签再回来（会立刻重读一次）。**下面那张卡是最后一次读到的样子、可能已经过期**；要批的卡仍在库里，飞书那边照样能批 |
| 点了「允许 / 拒绝」，卡片也变了，但委派说「你批了，但结论没能送回引擎」 | 你点卡时把结论记下来了，可结论送回后台引擎那一步没成功（引擎当时连不上）。系统**自动重试 3 次**，仍失败就**停住本轮、不假装成功**，并在进度卡与摘要里写明原因。**重新发起这条委派即可** —— 卡面显示「已允许 / 已拒绝」不代表引擎收到了，这次没有继续 |
| 局域网访问不了 | **故意的**。只绑 `127.0.0.1`，无鉴权的个人数据不该暴露 |
| 「允许从『X』直接迁到『Y』」 | 状态迁移被拦。`/task <id>` 看「下一步建议」，按建议的来 |
| 想让助手更聪明 | 检查 `/llm` 确认 Key 已配置；再 `/draft <id> 多给点背景` |
| 项目里多出一个 `opencode.jsonc`，开头写着「FreeAgent 委派闸门覆盖层」 | **上次委派被强杀或机器重启**，收尾没跑到，闸门覆盖层留在项目里了。它是项目级配置、**真的会生效**（含当时的权限规则），所以**直接删掉这个文件**即可。下一次委派正常结束时会自动清掉带这个标记的残留 |
| 想确认自己项目里有没有残留 | 文件前几行有 `freeagent-delegation-gate` 那句注释的才是；没有就别删 —— 那是你自己的 `opencode.jsonc`，我们**不会**碰它 |

## 九、数据在哪、怎么备份

### 位置

| 什么 | 在哪 |
|---|---|
| 数据库 | `~/.steward/agent.db`（`STEWARD_HOME` 或 `--db` 可改）；机器上已有 `~/.freeagent` 的库会**继续用旧目录**，不自动搬 |
| 配置文件 | 同目录 `config.json` |
| 草稿内容 | 在数据库里（`artifacts` 表），不存文件 |
| 项目档案 | 在数据库里（`workbench_projects` 表，v35）：命名目录 + 备注 |
| 工作台上次选中的项目 / 目录 / 模型 / 授权档 | 同目录 `workbench.json`。**删掉它只丢一次点击**，不影响任何记录 |

### 备份

数据库就是一个文件，直接复制：

```bash
copy "%USERPROFILE%\.freeagent\agent.db" "D:\backup\agent-2026-09-26.db"
```

**建议定期复制。** 没有自动备份，没有云同步，文件丢了就真没了。

### 迁移

复制 `.db` 到新机器，或用 `--db` 指到新位置。**格式无版本兼容承诺**，
跨版本移动前建议先在旧环境导出一份。

## 十、它做不到什么

写在前面比事后发现好。

| 限制 | 说明 |
|---|---|
| **只能手打** | 不接邮件/日历/聊天。**这是最大的缺口** —— 原始四大痛点之一至今未验证 |
| **关了进程就收不到提醒** | 轮询式提醒的固有局限，Web 界面也一样 |
| **单库单用户** | 无同步、无多设备、无协作 |
| **`/draft` 不会替你编内容** | 信息不够就只给 `[TODO]`。这是刻意的（不伪造事实） |
| **`/steps` 可能拆得过细** | 属于「建议」不是「事实」，20 步那种。觉得烦就忽略它 |
| **任务草稿不能在线改** | 任务/产物草稿（`/draft` `/revise`）的**在线编辑** Web 还没有，改要回终端。注：催办草稿（`/nudge`）的草稿板在 Web 上是可编辑、可复制的，只是不落库、系统不发 |
| **没有角色级记忆的入口** | 服务层**有**可检索的角色脉络知识（`role_knowledge` 表 + 全文检索，测试守着），但**三个通道都没有入口**，用不到它。`/memory add-role` 记的是另一张表（`memory`，角色作用域，四类别：偏好/约定/修正/目标），**不是**角色脉络知识（三类别：偏好/口径/历史决策）。从使用者的座位看，「不能检索角色脉络」依然成立 |
| **review 队列判不出「冲突」** | 三组都是字面判定，**没有一组会说「这两条矛盾」** —— 改口 / 两件并列的真事 / 一条是特例，字面上完全同形。V1.102 的「只差一处」把「回复先给结论」vs「回复先给细节」这类（重合 43%）摆出来了，但它只说「差在哪」，判还是你判。两个词同时换且首尾短的对子仍会漏（如「周三前给张总报价」vs「周五前给李总报价」） |
| **排序不是打分模型** | 只是确定性弱信号。你完全可以反驳它，它不会坚持 |
| **不替你发、不替你决定** | 催办草稿只铺事实留白、**系统结构上无发送能力**；所有「主动」能力最多提醒你自己，绝不对外代发。这是刻意的边界，不是功能缺失 —— 详见设计文档 §11.22 与「〇、产品哲学与演进方向」 |

### 还有一件事没验证

这套设计有个承重假设：**角色视图能降低跨角色切换的成本**（文档第十四章 H1）。
目前**零证据**。用法就是验证它 —— 连续用几天，感受一下跨角色事务是不是真的
更容易捡回上下文。如果没改善，该砍的是多角色设计本身，不是继续加功能。

## 后台服务（页面）

「后台服务」页签统一管两个进程的**启停与状态**（配置不在这里）：

| 服务 | 是什么 | 备注 |
|---|---|---|
| 飞书桥接 | 飞书长连接：收消息、发卡片、回落授权结论 | 手动启停见该页；开机自启的那个也能被它停（按进程认，不按谁启的） |
| 委派执行器 | 每 5 秒扫库，把已 /start 的委派交给后台引擎 | 启动命令与 `tools\_svc_executor.cmd` 完全一致；日志落在 `data\executor-page-<时间戳>.log` |

Web 服务自己**只显示状态、不给停止按钮** —— 停掉自己这门手艺没有意义。

状态靠本机 PowerShell 扫进程命令行；起 Web 的环境若裁掉了 PATH，程序会先按
系统盘绝对路径找 `powershell.exe`，找不到再退回 `powershell` / `pwsh`。
仍提示「进程扫描失败」时，从正常终端重启 Web 服务即可。
