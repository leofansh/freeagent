## 一、30 秒上手

### 打开就能打字（推荐先试这个）

```bash
cd D:\PycharmProjects\freeagent
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.web
```

浏览器打开 <http://127.0.0.1:8770/>，**首屏就是一个对话框**。直接问：

```
今天该做什么
周报进展怎么样
我在等什么
我上周完成了什么
```

或者直接说一件事记下来：

```
下周二要交的销售周报初稿
```

**它能问什么、不能问什么，见第五章。**

### 启动终端版

```bash
cd D:\PycharmProjects\freeagent
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.cli.app
```

### 先试这三条

```
> 下周二要交的销售周报初稿，先理一版
> /draft <前面给的 id 前几位>
> /task <id>
```

第三条是核心：它把这条事务的**意图、完成标准、当前草稿、进度、最近记录、下一步建议**
一次全给你看 —— 中断几天回来，靠的就是这一屏。

## 二、它解决什么问题

一句话：**按「角色脉络」组织事务，而不是一个扁平的待办列表。**

具体解决三件事：

| 问题 | 做法 |
|---|---|
| 事情混在一起，看不出是工作还是家里的 | 每条事务挂一个或多个**角色**，角色视图分开看 |
| 中途被打断，回来得从头捡上下文 | 每条事务有**恢复契约**，`/task` 一屏还原 |
| 该先做哪件没依据 | 给**透明的弱信号**（附理由），但不替你决定 |

**它不做的事**：不替你判断哪件事更重要。

## 三、必须先懂的 5 个概念

不懂这几个，你会觉得它「问东问西」。懂了之后就很自然。

### 1. 角色 = 事务的来源语境

不是你的身份，是「这件事从哪来」。比如 `工作项目A`、`家庭`、`个人创作`、`跑腿杂项`。

- 一条事务**至少**属于一个角色，可以属于多个
- 角色可以随时**改名、合并、静置**
- **角色名和备注里的词会用于自动推断** —— 所以 `/role-add` 的备注要写关键词

```
> /role-add 工作项目A 销售 周报 客户
> /role-add 家庭 孩子 学校 材料
```

写完备注后，说「销售周报初稿」就能自动归到 `工作项目A`，不用每次指定。

### 2. 三种形状（kind）

| 形状 | 用于 | 例句 |
|---|---|---|
| `动作` action | 要产出某个东西 | 写周报 |
| `等候` wait | 等别人/系统/时间 | 等客户回复合同 |
| `提醒` reminder | 到点通知一下 | 下午三点提醒我修窗户 |

**这个区分很重要**：等一件事不需要你「做」，所以它不该混在待办里消耗注意力。

### 3. 三个状态（state）

`待办` → `进行中` → `已完成`，另有 `等候中`（卡住了）和 `已放弃`。

**不是死板的流水线** —— 任何方向都能走，只禁止明显矛盾的（已完成不能直接跳到等候中）。

### 4. 排期是独立的

「做不做」和「什么时候做」是**两件事**。

一条事务可以同时是「进行中」**且**排在今天。`/today` 只显示排进今天和顺延过来的。

### 5. 排期 + 顺延

- 排到某天 → 那天出现在「今天视图」
- 到了那天还没做完 → **自动顺延到今天**，并给你一条合并摘要
- 不排期（`scheduled_for` 为空）→ 不进今天视图，但「全部未结束」里能看到

> 顺延机制是为了防止「今天」越积越长直到你不再打开它。

## 四、终端：命令全表

`/help` 是权威版本（永远与实现同步）。以下按用途分组。

### 看

| 命令 | 作用 |
|---|---|
| `/today` | 今天视图。先顺延，再排序，每条附信号理由 |
| `/all [open\|closed\|all]` | 全部事务。默认只列未结束 |
| `/roles [all]` | 角色脉络。默认只列活跃，`all` 含静置 |
| `/role <名字\|id>` | 某角色下的事务 |
| `/task <id>` | **恢复契约**（核心，见第三章） |
| `/plan <id>` | 单条事务的排期参考 + 命中信号 |
| `/llm` | 当前智能层与配置（**不显示 Key**） |

### 建

| 命令 | 作用 |
|---|---|
| 直接说话 | 自动推断形状 + 角色；角色不明确时**问一句** |
| `/new <角色> \| <描述>` | 显式创建，跳过推断 |
| `/draft <id> [要求]` | 生成结构化草稿骨架，未知处标 `[TODO]` |
| `/revise <id> <新内容>` | 局部重做，**产生新版本，旧版永久保留** |
| `/artifact <id> [版本]` | 查看草稿版本链 / 某版全文 |
| `/accept <id> [版本]` | 采纳某一版 |
| `/steps <id>` | 拆成几步（**只拆，不排序**） |

### 状态与排期

| 命令 | 作用 |
|---|---|
| `/start <id>` | 开始做 |
| `/pause <id>` | 等会再做 |
| `/done <id>` | 做完啦 |
| `/drop <id>` | 算了 |
| `/kind <id> <action\|wait\|reminder> [等谁]` | 改形状 |
| `/wait <id> <等谁>` | 放一放，并记下在等什么 |
| `/followup <id> <日期\|off>` | 设/清跟进时间（驱动「该催了」提示） |
| `/today-pin <id> [日期\|off]` | 排进今天 / 指定日期 / 移出排期 |
| `/note <id> <内容>` | 记一笔进度 |
| `/dod <id> <标准\|off>` | 改这条事务的完成标准 |

### 委派（交给 opencode 改代码）

| 命令 | 作用 |
|---|---|
| `/delegate <项目绝对路径> \| <角色> \| <需求>` | 建一条委派事务 |

委派是**唯一**一条终点在「本地执行代码」的能力，所以它比其它命令多两道闸门。

**用法三步：**

```text
> /delegate D:/PycharmProjects/freeagent | 工作 | 给执行器补上 --model 参数
> /start <刚建的那条>
```

然后**另开一个终端**跑执行器 —— 它不在对话里自动跑：

```bat
REM 先看一眼会派什么，但什么都不执行
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.delegate --dry-run

REM 确认无误后真跑
python -m freeagent.delegate
```

**如果这条委派是从飞书发起的，结果会自己飞回那个会话** —— 执行器跑完会
主动推一条结果回去（含事务 id 和一段摘要）。三个细节：

- 推送**在本地落库之后**才做。飞书挂了不影响委派结果，本地才是权威。
- 推送失败**只记日志**，不会让执行器失败。
- 文案里会写明「事务仍是进行中，需要你自己验收」——
  **通知送到不等于事情做完了**，机器不替你判断。

从终端发起的委派没有这一步（终端本来就能看到结果）。

> **执行器和桥接读的是同一份凭据，不用互相迁就环境变量。**
> 凭据在 `~/.freeagent/feishu.env`（界面上填一次即可），两个进程各自
> `load_config()` 都能读到 —— 所以**开一个全新终端跑执行器，照样能把结果
> 推回飞书**，不需要 `set` 任何东西。
>
> 早先这里写着「必须在跑执行器的那个终端里也设一遍 `FEISHU_*`」。那是
> **凭据只走环境变量时代**的约束（环境变量按进程继承、不跨终端），凭据落到
> 文件之后就不成立了 —— 那条建议会让白费力气，还让人以为闭环不可靠。
>
> 真正会导致推不回去的只有一种：**执行器用了另一个 `FREEAGENT_HOME`**，
> 于是读的是另一个目录下的 `feishu.env`（或压根没有）。读不到时执行器会
> **明确警告**（不静默跳过，否则你会以为闭环是通的）：
>
> ```text
> 这条委派来自飞书会话 oc_xxx，但本进程没读到 FEISHU_APP_ID/
> FEISHU_APP_SECRET，**结果没有推回飞书**（已照常落库）。
> ```
>
> 看到它就查 `FREEAGENT_HOME` 是不是和桥接那边一致。
> `FEISHU_*` 环境变量仍然可用，作为临时覆盖或应急手段。

**三道闸门，缺一不可：**

1. **项目白名单** —— 项目路径必须已写进 `config.json` 的 `delegate.projects`，
   且**只接受绝对路径**（相对路径的基准随工作目录变，是绕过白名单的常见手法）
2. **必须先 `/start`** —— 只有进行中的委派才会被派发。创建时一定是「未开始」
3. **不传 `--auto`** —— opencode 自己把这个开关标为 `dangerous!`。
   宁可它中途停下来问，也不要一个没人盯着的 agent 改代码

  **执行器是独立进程**，只从库里取已确认的委派，**不接受任何外部消息作为指令** —— 命令 / 任务 / 授权都只能经由它自己签发的凭据进入（它会接受对「它自己提出的问题」的文本答复）。闸门都在服务层的函数里，所以合并进程也绕不过；拆分给的是**纵深防御**，真正的好处是**交互中桥接重启不丢**。

**跑完不会自动标完成。** 结果会作为新一版草稿存进产物链（旧的永不覆写），
日志里留下完整痕迹；「做没做成」由你验收 —— 机器不该替你判断一件事到底完成没有。

**选哪个模型。** 实测结论（2026-09-27，opencode 1.18.31）：

| 模型 | 是否需要账户余额 | 能否用工具 |
|---|---|---|
| `opencode/big-pickle` | **不需要** | 能（实测读了文件、建了文件） |
| `opencode/space-bunny-free` | **不需要** | 能 |
| `opencode/gpt-5.4-nano` | 需要 | 余额不足直接 `402` |
| `opencode/deepseek-v4-flash` | 需要 | 余额不足直接 `402` |

默认推荐 **`opencode/big-pickle`**：不需要余额，且工具调用正常。
名字带 `-free` 的那批同样不需要余额。

```bat
python -m freeagent.delegate --model opencode/big-pickle
```

也可以写进 `config.json` 的 `delegate.model` 作为长期默认。

> ⚠️ **实测出的两条硬限制**（2026-09-27）：
>
> **1. 简报里只要有一个换行符，委派就会失败。**
> 提示中含 `\n` 时，opencode 判定为「复杂任务」，升级到主 agent 的强模型
> 并**无视 `--model`**；余额不足即 `402`。所以委派简报被刻意压成**单行**
> （用「；」连接），不用 `#`/`##`/`-` 那套 markdown 排版。
> 你在 `/delegate` 里写的需求、完成标准若带换行，也会被自动压平。
>
> **2. 需要写权限的任务会路由到唯一的 primary agent。**
> 只读、问答类任务 `--model` 生效；**新建/修改文件**这类走 primary agent。
> 要让它用上免费模型，得把那个 agent 的模型也换成免费的。
>
> | 简报形态 | 实际模型 | 结果 |
> |---|---|---|
> | 单行 · 纯需求 | `--model` 指定的 | ✅ 建出文件 |
> | 单行 · 带上下文 | `--model` 指定的 | ✅ |
> | **任何含换行的简报** | primary agent 的模型 | ❌ 402 |
>
> 一句话：**简报必须单行。** 这是实测出来的，不是风格偏好。

### 角色与归属

| 命令 | 作用 |
|---|---|
| `/move <id> <角色>` | 只挂到目标角色 |
| `/unrole <id> <角色>` | 摘掉一个角色标签 |
| `/role-add <名字> [备注]` | 新建或更新备注 |
| `/role-rename <名字> <新名字>` | 改名 |
| `/role-silence <名字> [on\|off]` | **省略 = 静置**，`on` = 恢复活跃 |
| `/role-dod <名字> <标准\|off>` | 该脉络的默认完成标准 |
| `/role-del <名字>` | 删除（要求其下无事务） |
| `/merge <源> <目标>` | 合并角色，**原子重定向，历史可回看** |

### 其它

| 命令 | 作用 |
|---|---|
| `/tick` | 手动检查提醒 |
| `/help` `/quit` | 帮助 / 退出 |

### 三条通用规则

1. **`<id>` 都可以只输前几位**：`/task 6a68355` 等价于完整 id
2. **角色可以按名字或 id 前缀匹配**：`/role 家庭`、`/role 4551`
3. **日期能听懂中文**：`今天` `明天` `后天` `昨天` `下周二` `周五` `3天后` `2026-10-01`；
   时刻：`下午三点` `15:30` `晚上8点半`

### 助手现在会拒绝的两类输入

白话入口**问句直接答、事照记**，只有做不到的才明确拒绝并告诉你该用什么，
而不是硬建一条垃圾记录：

| 你说的 | 它怎么回 |
|---|---|
| 「把周报改到下周三」「删掉那条旧提醒」 | 要改已有的一条 → 让你用 `/today-pin` `/drop` |
| 追问时回一句完整的话 | 不是角色名 → 让你用 `/role-add` 或 `/skip` |

> **问句是答的，不是拒绝的。** 「今天该做什么」「我在等什么」「全部未结束的事」
> 这些直接给结果 —— 和 `/today` 等价，只是你不用敲命令。**终端和飞书里一样**
> （早先只有网页对话框能问，终端和飞书会把问句打发成「查看用命令：/today」，
> 已在 2026-09-29 修掉）。

> 没听懂你问的是哪一类时，它会**先按「今天」答、并明说这是猜的** ——
> 而不是装作听懂了。觉得不对就直接问「在等什么」「有什么提醒」。

> 早先的版本会把「周报进展怎么样」直接建成一个**角色**。角色是整个工具的组织结构，
> 被随口一句话污染之后很难清理，所以现在**角色只能显式创建**，助手不再替你猜。

## 五、对话（首屏）

打开就是对话框。它**只读你的数据、只新建事务，不改已有事务**。

### 能问

| 你说 | 它答 |
|---|---|
| 今天该做什么 / 我现在该先做哪件 | 今天视图，按信号排序，每条带理由 |
| 为什么这条排第一 | 列出命中的信号和权重，并说「可以反驳它」 |
| 周报进展怎么样 | 那条的恢复契约：意图、完成标准、进度、下一步、当前稿 |
| 我上周完成了什么 | 那个时间范围内结束的（本周的不算上周的） |
| 我在等什么 | 每件卡住的事 + 在等谁 + 跟进日过没过 |
| 有什么提醒 | 接下来到点的提醒 |
| 家庭那边有什么 | 该角色下未结束的事务 |
| 全部未结束 | 所有未结束的 |
| 你能做什么 | 能力清单 + 边界说明 |

### 能接着问（多轮）

问完一屏之后可以**直接指代**，不用重复名字：

```
你：今天要做什么
    → 列出 7 条
你：第二个
    → 第二条的恢复契约
你：它为什么排第一
    → 那条的信号与权重
你：第一条呢
    → 同样能接上
```

指代方式：`第N个` / `第N条`（中文数字和阿拉伯数字都认）、`它` / `这条` / `那个`。

**对话历史会留在浏览器里** —— 切页签、刷新都不丢，右下角有「清空」。
所以你可以先问一屏，再点进详情看某一条，回来接着聊。

> 指代只在**有上文**时成立。没问过任何东西就说「它」，它会当你在胡说 ——
> 这是刻意的：没有上下文还硬指一条，等于答非所问。

### 能记

直接说一件事，它会推断形状、角色、日期：

```
下周二要交的销售周报初稿
等客户法务回复合同条款
提醒我下午三点修窗户
```

**归属不明确时它会反问**，而不是替你建一个新脉络。

### 不能做（会明确告诉你，并给出该用的命令）

| 你说 | 它答 |
|---|---|
| 把周报改到下周三 | 做不到 —— 改排期 `/today-pin <id> <日期>` |
| 把它标完成 | 做不到 —— 完成 `/done <id>` |
| 删掉那条旧提醒 | 做不到 —— 放弃 `/drop <id>` |
| 你能改它的状态吗 | 做不到 —— 改形状 `/kind <id> <shape>` |

> **这是刻意的边界，不是没做完。** 详情页上的状态按钮和「排期」可以直接点，
> 那些是确定性的改动。自然语言入口只负责**读**和**新建**——
> 一个会改数据的白话入口，出错时你不会知道它改了什么。
>
> 这条边界在**多轮下也不松**：先问一屏，再说「把它标完成」，照样拒绝。
> 有上下文之后用户很容易顺势就下命令，这里正是最该守住的地方。

### 拍照识物

首屏对话框上有个 **📷 拍照识物** 按钮。拍下产品铭牌，它会读出
**品牌 / 型号 / 规格**，然后给你两样东西：

- **一键跳转**：按型号去京东 / 淘宝 / 什么值得买搜一下
- **记一条**：直接建任务，标题和意图都填好

```
📷 拍照 → 读出「小米 空气净化器滤芯」
         品牌 小米｜型号 KJ-800-G｜规格 除PM2.5
         铭牌文字：型号 KJ-800-G
         [京东搜这个型号] [淘宝搜这个型号] [什么值得买]
         [记一条「小米空气净化器滤芯」]
```

**为什么不给「内置搜索」**：读铭牌是难点，搜商品不是。型号 `KJ-800-G`
复制到京东搜索框 3 秒就有结果，而**京东自己的搜索页比任何接口都好用** ——
你有登录态、优惠券、评价筛选、价格曲线。接口只能给字段。所以这里只给
**深链**，点一下跳到电商自己的搜索结果页。

零 API、零密钥、零资质，顺带保住这个工具「本地、断网可用」的属性。

**图片不落盘。** 铭牌照片里可能有地址、门牌、工牌、手机号。图片只在内存里
待几十秒，识别完只剩文字 —— 不写进数据库、不写进临时文件、不进日志。

**没配 Key 时按钮会禁用**并说明原因，不会让你白等一次。拍照识别必须配
`DEEPSEEK_API_KEY`（视觉走 `deepseek-flash`，可在设置页单独改），
**其余功能不受影响**。

**识别不准时宁可说「没读出型号」也不编一个** —— 型号错了你会买到不适配的
滤芯，要等货到才发现。所以读不清会直接说看不清哪里（反光/模糊/角度），
能看出是物品但读不到型号会明确说「没读到型号」并且不给搜索按钮。
铭牌原文会一起显示，你可以自己核对。

| 项 | 值 |
|---|---|
| 支持格式 | JPEG / PNG / GIF / WebP（**按文件内容判断**，不看扩展名） |
| 单张上限 | 8 MB |

### 认不准就反问

说「周报进展」而你有三条都含「周报」时，它会列出今天排着的让你选，
**不会随便挑一条答**。答错对象比不答更糟。

### 界面上还有什么

除了对话，界面上还有 **今天 / 全部未结束 / 已结束 / 角色 / 设置** 五个页签
（首屏是对话）。今天视图带顺延收口，角色视图能看静置和已合并，
设置页改配置立即生效（Key 也一样，存进 `llm.env`，见第六章）。

顶部是**新建事务**表单（必须选角色，不做推断）。点任意一条进**详情页**。

### 详情页有什么

恢复契约全在一屏：意图、生效完成标准、当前稿（版本号 + 状态 + 全文）、
进度、最近记录、等候对象、**下一步建议**，以及**状态按钮**。

状态按钮只显示**服务端说合法的**那些 —— 不会出现点了没反应的按钮。

### 界面上的按钮，和命令怎么对上

一个动作有三套名字（界面标签 / 终端命令 / 接口动作）。对不上号很正常，这里给张表：

| 界面按钮 | 终端命令 | 接口动作 | 说明 |
|---|---|---|---|
| 开始做 | `/start <id>` | `start` | |
| 做完啦 | `/done <id>` | `done` | |
| 等会再做 | `/pause <id>` | `pause` | |
| 算了 | `/drop <id>` | `drop` | |
| **放一放** | `/wait <id> <等谁>` | `blocked` | **会追问在等什么** |
| 排进今天 | `/today-pin <id>` | `pin` | |
| 移出排期 | `/today-pin <id> off` | `unpin` | |

**「放一放」为什么要追问？** 因为「在等」必须说清等谁，否则「等候中」就是个黑洞状态：
你不知道该催谁，也不知道什么时候该放弃。界面上填了之后等同于 `/wait`，
而状态本身叫「等候中」（对应接口的 `blocked`）。

### 提醒

页面顶部会显示一条合并摘要（多个提醒合成一条，不逐条弹）。
超过 6 小时的会标成「已错过」。

### 设置页能改什么，不能改什么

| 能改（存进 `config.json`，立即生效） | 不能改 |
|---|---|
| 服务商（provider） | 是否启用智能层（由 `FREEAGENT_RULES_ONLY` 决定） |
| 模型名 | 委派的项目白名单（那是**安全边界**，只能在 `config.json` 里手改） |
| 接口地址 | |
| 超时秒数 | |
| 允许降级开关 | |
| 精力档位（三档区间，或整体关掉） | |
| **API Key**（存进 `llm.env`，不是 `config.json`） | |

### 支持哪些 LLM

只支持 **OpenAI 兼容**的那几家：DeepSeek、Kimi（月之暗面）、通义千问（DashScope
兼容模式）、OpenAI、**Ollama（本机，不联网、不需要 Key）**、以及「其它兼容服务」
（vLLM / LM Studio / one-api 这类，地址和模型自己填）。

**Claude 和 Gemini 还不行。** 它们不是 OpenAI 兼容形状：鉴权头、请求体、响应都
不同，有的还不支持 `response_format`。硬接的后果**不是报错，是悄悄变差** ——
分类、草稿、拆步骤这几件事都要靠模型稳定输出 JSON，兼容性差的实现会让助手
「老是反问你」，而日志里看不出异常。要接它们得先改协议，不是改一行地址。

用 **Ollama** 的额外好处是**事务内容不出本机**：不填 Key 也能用。

### 关于 API Key

**Key 可以在设置页填**，写进 `~/.freeagent/llm.env`（和 `config.json` 同目录，
但**不是同一个文件**）。`config.json` 里**永远不会有它** —— `Config` 压根没有
`api_key` 字段，它是个现读的 property，所以这条是**靠类型防住的**，不是靠约定。

界面上：

- 输入框**每次加载都是空的**（明文不可能回显），已配的会用**掩码**做占位提示；
- **留空 = 不改**，不是清空。想清空要勾「清空已存的 Key」——
  否则你只改个模型顺手点保存，Key 就被抹了，而且要等下次启动才发现；
- 所有服务商的 Key **共存于同一个 `llm.env`**，来回切不会丢；
- 界面上会显示**当前生效的是哪一份**。如果环境变量压住了文件里的那份，
  它会明确提示你「在这里重填不会生效」——那种情况下你重填多少次都没用。

**环境变量仍然优先于文件。** 临时想换一家做对比测试可以直接
`set MOONSHOT_API_KEY=sk-...`，跑完就消失，不用去改文件。

也可以完全用环境变量（适合脚本化）：

```bat
set DEEPSEEK_API_KEY=sk-...
python -m freeagent.web
```

设置页第一屏就会告诉你 Key 现在有没有配、来自哪。没配的话，助手跑在**规则层**：
建事务、排期、提醒、恢复契约全都正常，只是角色推断退化成关键词匹配，
草稿和拆步骤基本是模板。

**「测试连通」会真发一次请求**（1 个 token，很便宜但不是零），
所以它能验证「Key + 地址 + 模型名」这一整套对不对，而不只是「地址通不通」。
「拉取模型列表」打的是 `GET /models`，一家家的模型目录都能列出来。

### 一个容易踩的坑

如果你启动时设了 `DEEPSEEK_MODEL` 之类的环境变量，**它会盖掉设置页里的值**。
这时设置页顶部会明确警告「改了不生效」。想去掉覆盖，就去掉那个环境变量。

### Web 做不到的

| 操作 | 只能去终端 |
|---|---|
| 改角色归属（`/move` `/unrole`） | ✔ |
| 改完成标准（`/dod` `/role-dod`） | ✔ |
| 改形状（`/kind` `/wait`） | ✔ |
| 草稿相关（`/draft` `/revise` `/accept`） | ✔ |
| 角色管理（改名/静置/合并/删除） | ✔ |
| 拆步骤（`/steps`） | ✔ |

> **原因**：状态迁移、草稿、角色合并这些操作需要额外输入和反馈（要说明在等什么、
> 要看到版本差异），终端的交互更合适。Web 层刻意只做**白名单**内的操作，
> 越权的一律 404 —— 免得点出静默的错误。

### 飞书接入（可选）

飞书是**又一个入口**，不是又一个引擎：消息经 `ChannelService` 转进终端那一套
派发逻辑（把 `Repl` 的输出换成缓冲区）。所以**命令语义与终端完全一致**，
不会哪天两边分叉。

> **在飞书里可以直接问，不必打斜杠命令。** 「今天该做什么」「我在等什么」
> 「全部未结束的事」这类问句会**直接给结果**，说人话记事情也照常。
> 其中「今天」「全部」也各有等价命令（`/today`、`/all`）——
> 但「在等什么」只有白话说法，**没有**对应命令。
>
> 早先这里有个真 bug：问句在网页对话框能正常答，**但终端和飞书会把问句
> 打发成「查看用命令：/today」** —— 而 `/today` 就写在下一行。根因是那两路
> 自己写了一份「问句一律拒绝」的判流逻辑，与网页那份分叉。已修（2026-09-29），
> 并写进设计文档 12.1.1 作为硬约束：一份能力一份实现。

核心包**零依赖不受影响** —— 只有飞书通道需要 SDK：

```bat
pip install ".[feishu]"
```

#### 1. 飞书控制台要开的东西

| 位置 | 做什么 |
|---|---|
| 应用能力 | 开启**机器人** |
| 权限管理 | 至少开 `im:message`、`im:message:send_as_bot` |
| 事件订阅 | 订阅 `im.message.receive_v1`；订阅方式选**「使用长连接接收事件」**（**不是** Webhook） |
| 版本管理与发布 | 创建版本并**发布**（自建应用通常还需管理员审批） |

选长连接的好处：**不需要公网 IP、不需要内网穿透**。这条通道是从本机往外连的。

#### 2. 配环境变量

```bat
set FEISHU_APP_ID=cli_xxx
set FEISHU_APP_SECRET=xxx
REM 白名单：只有这些 open_id 能指挥本机。**留空 = 谁都不许**（启动直接报错退出）
set FEISHU_ALLOWED_USERS=ou_xxx
REM 国际版 Lark 填 lark；默认 feishu
set FEISHU_DOMAIN=feishu
REM 提醒轮询秒数；0 = 不推提醒
set FEISHU_REMINDER_POLL_SECONDS=60
```

> App Secret **只从环境变量读**，和 `DEEPSEEK_API_KEY` 一个规矩。
> 它是**能冒充你的机器人收发消息**的凭据，比 DeepSeek Key 更敏感。
> `FeishuConfig` 的 `repr()` 会把它显示成 `***` —— 这样打日志不会顺手泄掉。

**`open_id` 怎么拿**：这是启用通道的**必经一步**——白名单为空时启动就会报错退出。

1. 先随便填一个占位值把桥接跑起来（`FEISHU_ALLOWED_USERS=ou_placeholder`）
2. 在飞书里私聊你的机器人，发一句话
3. 看日志里这一行（`--verbose` 更详细）：

   ```text
   发送者 ou_9f8xxxxxxxxx 不在白名单（event_id=xxxx）
   ```

4. 把那个 `ou_...` 填进 `FEISHU_ALLOWED_USERS`，重启桥接

日志里只出现 `open_id`，**不会出现你发的消息正文**。

> 白名单填错时的表现是「bot 一句话都不回」，这行日志就是唯一的线索。
> 查不到的话把 `--verbose` 加上再试一次。

#### 3. 跑起来

**推荐用交互式脚本** —— 它提示你粘贴 Secret，**不落文件、不进 shell 历史、
不经聊天工具**：

```bat
tools\run_feishu.bat
```

它会先跑一遍自检（含联网验凭据），确认没问题再起桥接。凭据错了会当场
说清原因并停下，而不是让你对着一堆静默重连发呆。

想手动设也行：

```bat
set PYTHONIOENCODING=utf-8
set PYTHONPATH=src
python -m freeagent.feishu.bridge
```

> **Secret 为什么要绕这一圈？** 32 位密钥里有 `I` / `l` / `1` / `!` 这类
> 肉眼几乎分不清的字符。靠人手转写经手一次就可能错一位，而**错一位的报错
> 是「app secret invalid」**——和真的失效完全一样，分不出是抄错还是过期。
> 让机器直接读 pasted 的原文，才彻底消除这一类错误。
>
> 顺带一提：`set "VAR=value & cmd"` 里 `&` 前的空格会被算进值里，
> 32 位会变成 33 位，接口报 `invalid param`。交互式脚本一并避开了。

它会一直阻塞在那儿（长连接有心跳和自动重连）。`Ctrl+C` 退出。

> **桥接和执行器是两个进程。** 桥接只负责「收消息 → 转命令 → 回话」；
> 真正去改代码的 `python -m freeagent.delegate` 要你**另开一个终端**跑。
> 这是刻意的：那条链路的终点是在你机器上执行代码，不该由一条聊天消息触发。
> 从飞书建了委派并 `/start` 之后，去终端跑一次执行器，结果会**自己飞回
> 那个飞书会话**（详见[委派](#委派交给-opencode-改代码)一节）。
>
> 想让提醒也能到飞书，两个进程都得开着 —— 提醒是轮询式的。

#### 4. 卡住了先跑 doctor

这套东西要配 App Secret、白名单、SDK，**每一处配错的表现都是
「bot 一句话都不回」**。所以配好之后、或者它不理你的时候，先跑自检：

```bat
python -m freeagent.feishu.doctor
```

输出逐项告诉你哪一环不对、**缺了会怎样**：

```text
飞书通道自检
==============================================
[OK  ] 飞书 SDK：已安装（1.7.3）
[OK  ] FEISHU_APP_ID：已设置（cli_xxx）
[OK  ] FEISHU_APP_SECRET：已设置（不显示内容）
[致命] FEISHU_ALLOWED_USERS：为空 —— 没有任何人能指挥本机，桥接会拒绝启动
[OK  ] FEISHU_DOMAIN：feishu → https://open.feishu.cn
[OK  ] 数据库：正常（schema v3，12 条事务）
[警告] bot 身份（open_id）：还没探到。**私聊不受影响，但群里 @ 它不会回**
       （门控失败关闭）。加 --live 联网探一次并缓存
[OK  ] 单实例锁：端口 8771 空闲（可以启动桥接）
==============================================
有 1 项致命问题，先修上面标「致命」的。
```

几点说明：

- **默认不联网**，只看本地配置 —— 「查一下配置填对没」不该有副作用。
- 想连凭据一起验（会发一次网络请求）加 `--live`。
- **不会打印 secret 内容**，只说「有没有」。这份输出可以放心贴给别人看。
- 退出码：有致命问题是 `1`，全过是 `0`。
- **`bot 身份` 是警告不是致命**：探不到身份只是群里不响应，私聊照常。
  标致命会让人以为整个通道都废了，反而不好定位。

最后两项是专门对付「**bot 突然不回应**」的，因为它们的表现和「权限坏了」
一模一样：

- **`bot 身份（open_id）`** —— 群里 @ 它到底认不认 bot 自己，靠的就是这个
  `open_id`，启动时自动探测（`GET /open-apis/bot/v3/info`）并缓存到
  `feishu_bot.json`。**探不到时群聊失败关闭**：群里带 @ 的消息一律不回。
  这是刻意的 —— 判不准的时候朝「关」偏。所以现象是「私聊能回、群里 @ 也不回」。
  `--live` 会联网探一次并缓存。⚠️ 群里如果**只 @ 了别人**，同样不响应，
  那是正常的：bot 不该抢答别人被 @ 的消息。日志里会写明是哪一种。
- **`单实例锁`** —— 同一个 `app_id` 上跑两个长连接，飞书只会把事件投给其中
  一个，另一个静默失效，现象就是「时好时坏」。默认锁 `8771`（**不是** Web 的
  8770，两个进程撞端口会互相误杀），`FEISHU_LOCK_PORT` 可改。端口被占时
  桥接会直接退出并说清「已有桥接在跑」。

#### 5. 三条安全边界

- **白名单失败关闭**：`FEISHU_ALLOWED_USERS` 为空时**启动就报错退出**，
  不存在「忘了配 = 所有人都能指挥本机」这种情况。这和
  `delegate.projects` 是同一个原则。
- **群里必须 @ bot 自己才响应**；@ 别人不抢答，判定靠 bot 自身 `open_id`
  （启动时自动探测并缓存）。探不到身份时群聊**失败关闭**（不响应），
  私聊不受影响 —— 判不准的时候朝「关」偏。
- **不传 `--auto`**：委派到 opencode 时永远不带这个开关，它自己标了 `dangerous!`。
- **同一台机器只跑一个桥接**：默认锁 `8771` 端口，第二个会直接退出。
  两个长连接里飞书只把事件投给一个，另一个静默失效，现象是「时好时坏」。

#### 6. 提醒是**私聊推**给你的

`reminders.check()` 是**消费型**的：取走就不再重复。所以通道不会靠「用户发消息
顺带触发」——那会被一条无关消息把提醒吞掉。通道按 `FEISHU_REMINDER_POLL_SECONDS`
自己轮询，**推给每个白名单用户的私聊**（不推群：提醒是私事，落到工作群等于广播）。

#### 7. 已知的限制

- **只把文字当指令**。图片、文件、富文本会**回一句「我只处理文字」**（带上实际
  收到的类型），然后**不建事务**。
  这条提示**只发给白名单内、且群里确实 @ 了 bot 的人**：
  - **白名单外不回** —— 回一句就等于向陌生人确认「这里有个 bot 在跑」，
    那正是白名单要挡的泄露面；
  - **群里没 @ bot 也不回** —— 否则群里谁随手发张图，bot 就抢着说
    「我只处理文字」，那比沉默更糟，等于把「不抢答」又破一次。
  所以「发了图片没反应」只可能是这两种情况之一：不在白名单里，或群里没 @ 它。
- **只认 `/` 开头的命令和普通句子**，与终端一致；不支持卡片按钮交互。
- **群里 @ bot 自己才响应**；@ 别人不抢答。bot 身份启动时自动探测并缓存到
  `feishu_bot.json`（7 天）；探不到时群聊**失败关闭**（群里带 @ 的一律不回），
  私聊不受影响。`doctor` 有一项专查，跑 `--live` 可联网探一次。
- 飞书重投事件会去重（同一 `event_id` 只处理一次），去重表**落盘**在
  `feishu_seen_events.json`（24 小时 / 2048 条），所以**重启后仍然记得** ——
  长连接重连会重投近期事件，这正是重复建事务的来源。文件坏了会改名
  `.corrupt` 留现场、以空表启动，不会因为一个坏文件起不来。

## 六、配置文件与环境变量

### 配置文件

位置：**和数据库同一目录**下的 `config.json`（默认 `~/.freeagent/`）。

```json
{
  "llm": {
```

全部可选。优先级：**内置默认 → 配置文件 → 环境变量**（后者覆盖前者）。

> ⚠️ **`config.json` 里写 `api_key` 仍然不生效** —— 这个文件是**非秘密**配置，
> 放 Key 会跟着数据库一起被备份、被复制。Key 写进**另一个**文件 `llm.env`
> （同目录），在设置页里填。
> 界面上的「设置」页改的就是 `config.json`，改完立即生效。

### 委派配置

| 键 | 作用 |
|---|---|
| `delegate.projects` | 允许委派到的项目目录，**只接受绝对路径**。**留空 = 关闭委派** |
| `delegate.model` | 用哪个 opencode 模型。留空 = 用 opencode 自己的默认 |

`delegate.projects` 是整个委派链路最硬的安全约束：链路的终点是
「在你的机器上执行代码」，所以能去哪些目录必须是**你预先批准的清单**，
不能由消息内容决定。默认留空 —— **不配就一条都派不出去**。

这一段只能手改 `config.json`（设置页不管委派），因为它是白名单，不该由界面随手放宽。

### 有 Key 和没 Key 的区别

| 能力 | 有 Key | 没 Key |
|---|---|---|
| 建事务、分类形状、排期、提醒、恢复契约 | ✅ 完全一样 | ✅ 完全一样 |
| 角色自动推断 | ✅ 理解力强 | 关键词匹配，弱 |
| `/draft` 出草稿 | ✅ 有内容 | ⚠️ 只有模板 |
| `/steps` 拆步骤 | ✅ 具体 | ⚠️ 三步脚手架 |
| 标题收敛 | ✅ | ✅ |

**没 Key 也能用全部功能**，只是助手「没那么聪明」。

## 七、常见用法（照着做）

### 场景 1：从零开始

```
> /role-add 工作项目A 销售 周报 客户
> /role-add 家庭 孩子 学校 材料
> /role-add 个人创作 写作 灵感
> /role-dod 工作项目A 先给我能用的就行
> /roles
```

第三条的备注是**关键词**，直接影响自动推断准不准。

### 场景 2：记一件事

```
> 下周二要交的销售周报初稿，重点讲增长
```

助手会：推断出「动作」、归到 `工作项目A`、解析出「下周二」、收敛标题。
然后回你一行 id，接着：

```
> /draft <id>          起骨架
> /start <id>          开始做
> /note <id> 框架有了   随手记一笔
```

被打断了就 `/task <id>`，看完接着做。

### 场景 3：卡在别人身上

```
> /wait <id> 客户法务回复
> /followup <id> 3天后
```

三天后 `/today` 里这条会带着理由顶到最前面：「该催 客户法务 了」。

### 场景 4：改主意，放弃

```
> /drop <id>
```

不会消失，移到「已结束」里。

### 场景 5：角色越建越多

```
> /merge 跑腿杂项 个人事务
```

事务会**原子地**重指向新角色，原数据保留。合并后旧名字不再出现在列表里。

### 场景 6：定期回看

```
> /today              今天要动的
> /all closed         上周做完的
> /roles              脉络全景
```

## 八、故障排查

| 现象 | 原因与解法 |
|---|---|
| 界面上中文乱码 | 忘了 `set PYTHONIOENCODING=utf-8` |
| `ModuleNotFoundError: freeagent` | 忘了 `set PYTHONPATH=src` |
| 设置页改了模型名但没效果 | 启动时设了同名环境变量，它优先。设置页顶部会警告；去掉那个环境变量 |
| 建事务被追问「这是放到哪个脉络里？」 | 该角色名和备注的词跟你的输入没交集。补 `/role-add <名字> 关键词`，或直接回一个角色名，或 `/skip` |
| 界面上建的事务「今天」里看不到 | 新建表单的**日期框**留空了。补上，或 `/today-pin <id>` |
| 没收到提醒 | 提醒是**轮询**的：终端每轮对话查一次，Web 每次加载查一次。**两个进程都关着就收不到** |
| 提示「已退回规则推断」 | 模型调不通（没网/Key 错/超时）。`/llm` 看当前状态；不想要降级就设 `FREEAGENT_ALLOW_FALLBACK=0` |
| `/draft` 全是 `[TODO]` | 你给的信息太少。补意图、来源、口径，它就不敢瞎写了 —— 这是**故意的** |
| `/role-del` 提示不能删 | 该角色下还有事务。先 `/merge` 或逐条 `/move` |
| Web 打不开 | 端口被占：`python -m freeagent.web --port 9000` |
| 局域网访问不了 | **故意的**。只绑 `127.0.0.1`，无鉴权的个人数据不该暴露 |
| 「允许从『X』直接迁到『Y』」 | 状态迁移被拦。`/task <id>` 看「下一步建议」，按建议的来 |
| 想让助手更聪明 | 检查 `/llm` 确认 Key 已配置；再 `/draft <id> 多给点背景` |

## 九、数据在哪、怎么备份

### 位置

| 什么 | 在哪 |
|---|---|
| 数据库 | `~/.freeagent/agent.db`（`FREEAGENT_HOME` 或 `--db` 可改） |
| 配置文件 | 同目录 `config.json` |
| 草稿内容 | 在数据库里（`artifacts` 表），不存文件 |

### 备份

数据库就是一个文件，直接复制：

```bash
copy "%USERPROFILE%\.freeagent\agent.db" "D:\backup\agent-2026-09-26.db"
```

**建议定期复制。** 没有自动备份，没有云同步，文件丢了就真没了。

### 迁移

复制 `.db` 到新机器，或用 `--db` 指到新位置。**格式无版本兼容承诺**，
跨版本移动前建议先在旧环境导出一份。

## 十、它做不到什么

写在前面比事后发现好。

| 限制 | 说明 |
|---|---|
| **只能手打** | 不接邮件/日历/聊天。**这是最大的缺口** —— 原始四大痛点之一至今未验证 |
| **关了进程就收不到提醒** | 轮询式提醒的固有局限，Web 界面也一样 |
| **单库单用户** | 无同步、无多设备、无协作 |
| **`/draft` 不会替你编内容** | 信息不够就只给 `[TODO]`。这是刻意的（不伪造事实） |
| **`/steps` 可能拆得过细** | 属于「建议」不是「事实」，20 步那种。觉得烦就忽略它 |
| **没有草稿编辑界面** | Web 只能看草稿，改要回终端 `/revise` |
| **没有角色级记忆** | `Role.note` 只是自由文本，不能检索。V2 才做 |
| **排序不是打分模型** | 只是确定性弱信号。你完全可以反驳它，它不会坚持 |

### 还有一件事没验证

这套设计有个承重假设：**角色视图能降低跨角色切换的成本**（文档第十四章 H1）。
目前**零证据**。用法就是验证它 —— 连续用几天，感受一下跨角色事务是不是真的
更容易捡回上下文。如果没改善，该砍的是多角色设计本身，不是继续加功能。
